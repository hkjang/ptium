# Ptium 1.69.8

## 이름 뒤에 붙는 조사를 이름에 맞춰 고릅니다

한국어의 을/를, 이/가, 은/는, 와/과는 앞말의 받침으로 정해집니다. 그런데 그 앞말은
대개 사용자가 지은 이름입니다. 덱 제목, 올린 파일 이름, 템플릿 이름, 이 배포의
서비스 이름. 문장을 쓸 때는 알 수 없는 값이라, 한쪽으로 박아 두면 **절반은
틀립니다.**

화면 스무 곳이 그랬습니다.

- `보고서.pptx을 읽고 있습니다` (→ 를)
- `"분기 매출"를 잘라서 넣었습니다` (→ 을)
- `"차트"은 없는 지시어입니다` (→ 는)
- `제목 "…구축하고" 이(가) 문장 중간에서 끊깁니다` — 아무도 고르지 않았을 때
  나오는 그 모양 그대로였습니다 (→ 가)

편집기 쪽에는 이미 받침을 보고 고르는 함수가 있었고 일곱 군데에서 제대로 쓰이고
있었습니다. 나머지가 빠져 있었을 뿐입니다.

이제 규칙 하나를 `web/src/korean.ts` 한 곳에 두고 전부 그것을 씁니다. 이름이
한글이 아닐 때도 읽는 소리로 고릅니다.

- KPI → 케이피아이 → 를
- Excel → 엑셀 → 을
- 2026 → 이천이십육 → 을
- 보고서.pptx → 엑스 → 를

## 지키는 장치

`web/src/korean.test.ts`가 규칙을 확인하고, **소스 전체를 읽어** 이름이 끝나는
자리 바로 뒤에 조사를 박아 넣은 곳이 있으면 파일과 줄 번호를 대며 실패합니다.
돌아가는 화면은 이런 문장을 이상하다고 말해 주지 않습니다. `보고서.pptx을 읽고
있습니다`도 문장은 문장이기 때문입니다.

되돌려 돌리니 스무 곳이 그대로 잡혔습니다. 손으로 세어 본 목록에서 빠뜨린
`관리 · 디자인` 화면 세 줄도 이 검사가 대신 찾아냈습니다.

한 가지 더: 기존 테스트 한 줄이 틀린 쪽을 정답으로 붙들고 있었습니다.
`"flowchart"은` — flowchart 는 "플로차트"로 읽혀 받침이 없으니 는이 맞습니다.
테스트를 고쳤습니다.

## 확인만 하고 고치지 않은 것

미리보기와 내려받은 pptx 가 같은 말을 하는지, 구성 요소 열다섯 가지를 모두 넣어
낱말 단위로 맞춰 보았습니다. 열다섯 장 모두 정확히 일치했습니다. 링크와 슬라이드
점프, 발표자 노트도 파일 안에 제대로 들어 있었습니다.
