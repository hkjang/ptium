# Ptium v1.55.3

**v1.55.0이 내보낸 PDF의 사진을 조용히 깎아냈습니다. 제가 낸 흠입니다.**

## 지난 릴리스가 무엇을 건드렸는지 확인하다가

v1.55.0은 "그림을 그려질 크기로 박아 넣는다"를 고쳤습니다. 그런데 **PDF도 같은
렌더러를 지나갑니다.** PDF는 포인트 단위로 그려지고 그 폭이 960이므로, 화면용
계산이 그대로 적용됐습니다.

2400×1600 사진을 넣고 내보낸 PDF 안의 그림을 꺼내 재 봤습니다.

```
v1.55.0 이전 : 1400x933   PDF 2,832,786 bytes
v1.55.0 이후 : 1024x683   PDF 2,498,151 bytes    ← 가로세로 27% 손실
```

인쇄하고 돌려 보는 파일에서 **아무 말 없이** 사진의 4분의 1이 사라졌습니다.
PPTX는 원본을 그대로 담으므로 영향이 없었습니다(양쪽 다 8,789,563 bytes).

## 종이는 화면이 아닙니다

포인트는 1인치의 72분의 1입니다. 화면은 CSS 픽셀당 2개의 실제 픽셀을 칠하지만,
프린터는 포인트당 그보다 훨씬 많이 찍습니다. 그래서 `PreviewOptions`에 밀도를
하나 두고, PDF는 **포인트당 4픽셀**(약 288dpi)을 요구합니다.

```go
drawing := pptx.PreviewSVG(manifest, layout, slide, pptx.PreviewOptions{
    Width: int(width), ..., PictureDensity: pptx.PrintPictureDensity})
```

전면 사진은 다시 천장(1400px)에 닿고, 작은 상자에 든 그림은 그 상자에 맞는 만큼만
가져갑니다. 화면 쪽은 그대로 작습니다.

```
내보낸 PDF          1400x933   (v1.55.0 이전으로 복구)
편집기 레일 260px     59,109 bytes
개요 격자   320px     59,111 bytes
미리보기    960px    522,385 bytes
```

## 고치는 중에 하나 더 냈습니다

밀도를 상자에 넣으면서 **캐시 열쇠에는 넣지 않았습니다.** 그래서 PDF를 한 번
내보내면, 같은 상자의 다음 화면 미리보기가 인쇄용으로 인코딩된 것을 받아 갔습니다 —
960px 미리보기가 522KB에서 968KB로 돌아갔습니다. 재고 나서야 알았습니다. 열쇠에
밀도를 넣어 고쳤고, 양쪽 순서로 확인했습니다.

## 지나가다 발견한 것

```go
if format == "" { format = "pptx" }
if format == "" && strings.HasSuffix(request.URL.Path, ".pdf") { format = "pdf" }
```

기본값이 두 검사 **사이에** 적혀 있어서 `.pdf` 가지는 실행될 수 없었습니다. 경로도
등록되어 있지 않아 `/export.pdf`는 404였습니다. 순서를 바로잡고 경로를 열었습니다 —
이제 `.pptx`와 `.pdf`가 각자 이름대로 줍니다.
