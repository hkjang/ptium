# Ptium v1.6.5

지난 판에서 **잘린 답을 실패로** 돌렸습니다. 그러면 당연한 질문이 남습니다 — **한도가 8,000
토큰인 건 적절한가?** 정해 놓고 재 본 적이 없었습니다.

## 모델의 토크나이저로 직접 셌습니다

먼저 실제로 쓰인 덱들을 모델 자신의 토크나이저에 넣어 봤습니다.

| | |
|---|---|
| 이 세션에서 실제 모델이 쓴 덱 | 슬라이드당 **90~116 토큰** |
| 9장짜리 덱 원본 | 800~1,050 토큰 |

원본만 보면 8,000은 넉넉합니다. 그런데 **답을 쓰는 데 드는 토큰은 원본만이 아닙니다.**

## 9장 덱 하나가 이미 6,495 토큰을 씁니다

설계 단계 프롬프트를 그대로 실제 모델에 보내고 **usage** 를 읽었습니다.

```
plan @8000: finish=stop  completion_tokens=6495  content=2,634자  (302초)
```

**2,634자를 쓰려고 6,495 토큰을 썼습니다.** 네 배 가까이가 생각하는 데 들어갔고, 이건
**아무도 그보다 작게 요청하지 않는 9장짜리** 덱입니다. 기본 한도의 **81%** 가 한 번의 패스에서
사라집니다. 브리프가 조금만 길거나 모델이 조금만 더 생각하면 8,000에 닿고, 그러면 답이
문장 중간에서 끊깁니다.

50장은 아예 가망이 없습니다.

## 그래서 요청에 맞춰 늘립니다

```
한도 = 8,000 + 슬라이드 수 × 250   (최대 32,000)
```

- 9장 → 10,250 (측정된 6,495에 여유)
- 50장 → 20,500

바닥값 8,000은 **생각하는 데 드는 몫**, 슬라이드당 250은 **덱 자체가 쓰는 몫** (측정치 116의
두 배)입니다. **관리자가 직접 정한 값은 그대로 둡니다** — 3,000으로 낮춰 두었다면 3,000입니다.

## 실제 모델로 확인했습니다

같은 브리프로 다시 태웠습니다. 설계 단계 통과, 9장 완성, 점수 96. **조인 규칙과 늘린 한도가
함께 있어도 멀쩡한 생성이 막히지 않습니다.**

로그에서 수리 단계도 다시 보였습니다 — 두 장을 다시 써 보고 **둘 다 나아지지 않아 원본을
지켰습니다.** 그 두 장은 작성자의 측정 패널에 지적으로 남고, 그중 하나는 버튼 한 번으로
나뉩니다.

## 설치

```bash
gzip -dc ptium-1.6.5.tar.gz | docker load
```
