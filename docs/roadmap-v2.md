# Ptium v2 — 무엇을 먼저 만들 것인가

이 문서는 v0.44 시점의 코드를 기준으로, 다음 열 판에서 만들 것을 순서대로 적습니다. 아이디어
목록이 아니라 **착수 순서와 그 이유**입니다.

## 이미 있는 것 (다시 만들지 않을 것)

새 기능을 논의하기 전에, 이미 서 있는 것을 분명히 해 둡니다.

| 이미 있음 | 어디에 |
| --- | --- |
| 생성 잡 큐 (Postgres, `FOR UPDATE SKIP LOCKED`, 크래시 잡 10분 후 재확보) | `store.ClaimGeneration` · `generation/worker.go` |
| 브라우저 E2E (생성→편집→저장→내보내기 · 발표자 보기 · 키보드 · 좁은 화면) | `scripts/e2e/{ui,flows,deep}.py` |
| 내보낸 파일의 외부 검증 (python-pptx로 표·차트·워크북·번호·노트·대체 텍스트) | `scripts/e2e/package.py` |
| 슬라이드 라이브러리 (등록·검색·사용 횟수) | `store/snippets.go` · `SlideLibrary.tsx` |
| 측정 8종 (overflow · outside · collision · contrast · orphan · density · repeat · notes) + 안전 수정 | `pptx/inspect.go` · 편집기 측정 대화상자 |
| 기존 `.pptx` 가져오기 (글 · 표 · 그림 · **차트의 숫자**) | `pptx/importdeck.go` · `deck/importdeck.go` |
| 편집 가능한 표 · 차트 내보내기 (워크북 포함) | `pptx/tablepart.go` · `pptx/chartpart.go` |
| 모든 개체 대체 텍스트 (접근성 검사 통과) | `pptx/describe.go` |
| REST와 MCP가 같은 권한 계층 · API 키 회전 · OIDC | `httpapi` · `keys` · `auth` |

## 진짜 공백

| 공백 | 크기 |
| --- | --- |
| 품질을 **점수로** 말하지 않는다 (측정은 하는데 목록으로만 보여 준다) | 큼 |
| 숫자의 **출처**가 없다 | 큼 |
| 데이터에 **연결된** 슬라이드가 없다 | 큼 |

## 1차 — 프레젠테이션 품질 점수

**왜 먼저인가.** 측정 엔진이 이미 8종을 재고 있고, 편집기는 그것을 "다듬을 곳 2"로 보여 줍니다.
점수는 그 위에 얇게 얹히는 층이고, 사용자에게는 **"이 덱이 지금 몇 점인가"**라는 처음 보는
정보가 생깁니다. 새 모델도, 새 인프라도 필요 없습니다.

**정직하게.** 점수는 **그려진 것을 잰 결과**이지 논지의 설득력이 아닙니다. 화면에서도 그렇게
말합니다.

차원은 측정할 수 있는 것만 둡니다.

| 차원 | 무엇으로 계산하는가 |
| --- | --- |
| 가독성 | overflow · outside · density · orphan |
| 구성 | repeat · notes 없음 · 요점 수 |
| 시각 | collision · 빈 영역 · 컴포넌트 비율 |
| 접근성 | contrast · 대체 텍스트 · 제목 없는 슬라이드 |

API는 이미 있는 `GET /presentations/{id}/inspect` 를 넓힙니다.

```json
{
  "slides": 9, "defects": 0, "advisories": 2,
  "score": {
    "total": 92,
    "dimensions": [{"key":"readability","score":95,"counted":3}],
    "slides": [{"slide":3,"score":74,"worst":"density"}]
  },
  "findings": [...]
}
```

편집기 머리의 칩이 `품질 92` 가 되고, 눌러 연 대화상자가 차원 막대와 **가장 낮은 슬라이드**를
먼저 보여 줍니다.

## 2차 — 근거와 출처 *(v0.46에서 1단계 완료)*

기업 문서에서 AI가 쓴 숫자의 첫 질문은 언제나 "이거 어디서 나온 겁니까"입니다.

문장 단위로 답합니다.

**v0.46에서 한 것:** 소스 언어의 `!source`, 슬라이드에 함께 저장(문서와 같이 이동), 왕복 보존,
발표자 노트에 출처 목록, 측정 항목 `숫자의 출처 없음`, 점수의 **근거** 축.

**아직 남은 것:** 덱을 가로지르는 출처 검색과 재사용, 파일에서 가져온 근거의 자동 연결, 참고
슬라이드 생성. 그때 아래 표가 필요해집니다 — 지금은 슬라이드 문서 안에 사는 편이 낫습니다.

```sql
CREATE TABLE evidence (
  id uuid PRIMARY KEY,
  presentation_id uuid NOT NULL,
  slide_position int NOT NULL,
  claim text NOT NULL,          -- 슬라이드에 적힌 그 문장
  source_kind text NOT NULL,    -- upload | url | dataset | manual
  source_title text NOT NULL,
  source_locator text,          -- p.42, Sheet1!B7, #anchor
  retrieved_at timestamptz,
  confidence real
);
```

- 소스에서: `- 매출 1,240억 ^1` 처럼 각주를 답니다.
- 내보낼 때: 발표자 노트 끝에 출처 목록이 붙고, 원하면 **참고 슬라이드**가 마지막에 생깁니다.
- 측정에 한 줄 늘어납니다: **숫자가 있는데 출처가 없는 슬라이드**.

## 3차 — 문서에서 만들기 *(v0.47에서 1단계 완료: xlsx · csv · docx · md)*

`.pptx` 가져오기는 이미 있었고, v0.47에서 **xlsx · csv · tsv · docx · md · txt** 가 같은 자리에
붙었습니다 — 모두 표준 라이브러리만으로, 의존성 없이. 남은 것은 **PDF** 하나이고, 그것은 파서
의존성을 들일지 결정하는 문제입니다. 파일에서 뽑은 문단과 표가 **2차의 근거**로 그대로 이어집니다 — 이 순서가 중요합니다.
출처 없이 문서를 삼키면 AI가 지어낸 것과 구분되지 않습니다.

## 4차 — 편집기 코파일럿 *(v0.48에서 1단계 완료: 결정적 명령)*

말로 시키는 통로. 핵심은 채팅이 아니라 **편집 명령으로의 번역**입니다.

```
자연어 → 의도 → 편집 명령 → 덱 변경 → 측정 → 되돌릴 수 있는 한 판
```

**v0.48에서 한 것:** 합치기 · 나누기 · 옮기기 · 복제 · 삭제 · 줄이기(장수/발표 시간)를 문장에서
읽어 실행합니다. 모델 없이, 한국어와 영어 모두. 적용 전에 계획을 보여 주고, 버전 이력으로
되돌립니다.

**아직 남은 것:** 말을 고치는 명령("임원용으로 줄여줘", "기술 용어를 쉽게")은 모델의 일이고,
`slide.revise` 위에 붙입니다. 그리고 여러 명령을 한 문장에서 읽는 것.

## 5차 — 라이브러리를 먼저 찾기

라이브러리는 있는데 생성이 그것을 보지 않습니다. 생성 앞에 검색을 답니다.

```
브리프 → 라이브러리 검색 → 쓸 만한 것이 있으면 변형, 없으면 새로 씀
```

회사 소개 · 조직도 · 보안 아키텍처처럼 **매번 같아야 하는 슬라이드**가 매번 새로 지어지는 것을
막습니다.

## 6차 — 편집기 분해와 프론트 테스트

`EditorPage.tsx` 81KB를 화면 · 훅 · 모델로 나누고, Vitest와 React Testing Library를 넣습니다.
Playwright 스윕은 이미 있으니 **유닛이 비어 있는 자리**만 채웁니다. 리팩터를 여기 두는 이유는
하나입니다: 위의 다섯 판이 편집기를 계속 건드리므로, 그 다음에 나누는 편이 두 번 나누지 않습니다.

## 7차 — golden 파일 비교

`package.py`가 이미 외부 도구로 읽어 검증하지만, **바이트/XML 단위 회귀**는 없습니다.
`testdata/golden/*.pptx` 를 두고 정규화 후 비교합니다 — 관계 · 슬라이드 XML · 테마 · 레이아웃 ·
글꼴 · 좌표.

## 8차 이후

- 데이터 연결 슬라이드 (`{{sales.2026.revenue}}` · 새로고침)
- 스토리라인 그래프 · 보고 유형별 모드
- 덱 비교(버전 간 무엇이 바뀌었는가)
- 공유 · 댓글 · 승인
- 컴포넌트 레지스트리 (SWOT · 2x2 · 퍼널 · 로드맵 · 리스크 매트릭스)

## 바꾸지 않을 것

Go 단일 서버 · Postgres만 필요 · 얇은 프론트 의존성 · 폐쇄망 결정적 생성 · PPTX 자체 처리 ·
REST와 MCP의 같은 권한 계층. 새 기능은 이 선 안에서 만듭니다.
