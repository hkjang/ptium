# Ptium v0.49.0

회사에는 **매번 같아야 하는 슬라이드**가 있습니다. 회사 소개, 조직도, 보안 아키텍처, 표준
면책 문구. 누군가 이미 쓰고 합의해서 슬라이드 라이브러리에 넣어 뒀는데 — 생성은 매번 **자기
버전을 새로 썼습니다.** 회사의 덱들이 조금씩 어긋나는 것이 이렇게 시작됩니다.

## 새로 쓰기 전에 라이브러리를 봅니다

생성이 소스를 만든 다음, 각 슬라이드의 제목을 라이브러리에서 찾습니다. 분명히 같은 슬라이드면
**등록된 것으로 바꿉니다.**

```
# 회사 소개                     ← 생성이 쓴 제목
@content
> 2003년 설립                   ← 라이브러리에 등록된 슬라이드가 그대로
- 임직원 1,240명
- 매출 8,200억
```

- **엄격하게 맞을 때만.** `회사 소개` · `회사소개` · `회사 소개 (2026)` 는 같은 슬라이드,
  `계획` 은 아무것도 아닙니다. 이름의 절반 이상이 제목이어야 합니다 — 잘못 바꾸는 것은
  새로 쓰는 것보다 나쁘기 때문입니다.
- **표지는 바꾸지 않습니다.** 표지는 덱의 제목을 지고 있습니다.
- **말해 줍니다**: `"회사 소개" 슬라이드는 라이브러리에 등록된 "회사 소개"을 그대로 썼습니다`.
  그리고 그 슬라이드의 사용 횟수가 올라갑니다.
- **모델과 무관합니다.** 이름이 이름과 같은지는 판단이 아니라 사실이라, 폐쇄망의 결정적
  생성에서도 똑같이 동작합니다.

## 도중에 잡은 표지 결함

실측을 하다 표지가 이렇게 나오는 것을 봤습니다.

```
# 회사 소개와 2026년 사업 계획을 . 매출 목표 1조
```

브리프 `회사 소개와 2026년 사업 계획을 임원에게 보고. 매출 목표 1조.` 에서 지시문
(`임원에게 보고`)을 걷어내자 **그 앞에 있던 마침표만 남았고**, 제목이 두 문장을 이어 붙였습니다.
이제 제목은 **버려진 마침표 앞에서 끊습니다** — 그 뒤는 다른 문장이었고, 제목은 한 생각입니다.

## 확인

- 회귀 테스트 3건: 등록된 슬라이드가 제자리를 차지하고 등록 안 된 장은 그대로일 것, 표지는
  바뀌지 않을 것, **분명하지 않은 제목은 바꾸지 않을 것**(`계획`·`소개` 같은 조각).
- 생성 경로 테스트 1건: 라이브러리를 준 생성이 그것을 쓰고, 사용 횟수를 올리고, 썼다고 말할 것.
- 표지 회귀 테스트 1건.
- 전수 점검에 한 묶음 추가(api 87): 슬라이드를 등록하고 생성한 뒤, 덱이 그것을 썼는지와 사용
  횟수가 올라갔는지.
- 전수 점검: api 87 · edges 32 · package · deep 0 실패.
