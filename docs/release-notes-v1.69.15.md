# Ptium 1.69.15

## 글머리 기호가 • 인 문서를 넣으면 가져오기가 실패했습니다

워드나 아래아한글에서 복사해 온 목록은 `-` 가 아니라 `•` 로 시작합니다. 그런 파일을
넣으면 **서버 오류**만 뜨고 아무것도 들어오지 않았습니다.

글머리 기호를 떼어 낼 때 **한 바이트**만 잘라내고 있었습니다. `•` 는 UTF-8 로 세
바이트(E2 80 A2)입니다. 앞 한 바이트만 잘리니 남은 두 바이트가 글자 앞에 그대로
붙었고, 그것은 더 이상 글자가 아닙니다. 데이터베이스가 이를 거절하면서
`invalid byte sequence for encoding "UTF8": 0x80` 로 요청이 끝났습니다.

이제 기호를 **글자 단위로** 떼어 냅니다. `• · ▪ ▫ ◦ ‣ ⦁` 과 `- * +`, 그리고 대시를
알아봅니다.

붙임: 숫자를 잡아먹지 않습니다. `-5% 감소` 는 하이픈으로 시작하지만 목록이 아니라
숫자입니다. `-`, `*`, `+`, 대시는 **뒤에 공백이 있을 때만** 기호로 봅니다. 뒤에
아무것도 없는 `-` 한 글자도 빈 항목이 아니라 그냥 문장 부호로 둡니다.

## 유인물(PDF)을 다시 넣으면 글머리 기호가 두 번 그려졌습니다

PDF 에서 글머리 기호는 문단의 속성이 아니라 **페이지에 그려진 글자**입니다. 그래서
읽어 들이면 `• 매출이 늘었습니다` 라는 글자가 그대로 들어왔고, 덱은 그 앞에 자기
글머리 기호를 하나 더 그렸습니다.

```
- • 매출이 늘었습니다      ← 전
- 매출이 늘었습니다        ← 후
```

두 곳이 같은 규칙을 쓰도록 `internal/docs/listmarker.go` 하나로 모았습니다.

## 지키는 장치

- `internal/docs/listmarker_test.go` 가 기호별로 떼어 내는지, `-5% 감소` 같은
  숫자를 건드리지 않는지 봅니다. 그리고 `•` 로 쓴 문서를 읽어 결과가 **온전한
  글자인지** 확인합니다. 한 바이트만 자르던 때로 되돌리면 `- \x80\xa2 매출이…` 가
  나오며 실패합니다.
- `scripts/e2e/api.py` 가 덱을 PDF 로 내보내 다시 가져온 뒤, 본문에 `•` 가 남아
  있으면 실패합니다. 되돌려 돌려 실제로 잡히는 것을 확인했습니다.

## 확인만 하고 고치지 않은 것

마크다운·CSV·PDF 가져오기를 모두 왕복시켜 보았습니다. CSV 는 표를 `::table` 로,
마크다운은 제목과 요점을, PDF 는 쪽마다 제목과 요점을 제대로 만들고 `!source` 로
어디서 왔는지 적어 둡니다.
