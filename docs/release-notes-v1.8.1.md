# Ptium v1.8.1

v1.8.0 에서 글자 크기 328곳을 올렸습니다. 그런데 **확인한 화면은 6개** 였습니다. 나머지를
사람이 하나씩 열어 보는 대신, **기계가 재게** 했습니다.

## 두 가지를 잽니다

브라우저 검사(`ui.py`)가 이제 지나가는 **모든 화면에서** 두 가지를 확인합니다.

1. **11px 보다 작은 인터페이스 글자** — 슬라이드 그림 안의 글자는 뺍니다. 그건 덱 자신의
   타이포그래피이지 인터페이스가 아닙니다.
2. **서로 겹쳐 그려진 요소** — 줄바꿈된 인라인 요소는 뺍니다. 그 사각형은 줄 전체를 덮기
   때문에 옆의 모든 것과 겹친 것처럼 보입니다(제가 처음 만든 검사기가 여기에 속았습니다).

## 켜자마자 20곳 넘게 걸렸습니다

정규식이 `font-size:9px` 만 찾고 **`font-size: 9px`(공백 있는 표기)는 못 찾고 있었습니다.**
그래서 v1.8.0 이 통째로 놓친 곳들입니다.

| 걸린 것 | 어디 |
|---|---|
| 사이드바 구역 이름 (워크스페이스 · 내 설정 · 관리) | 9px |
| 계정 이름 아래 역할, `Ctrl K` 힌트, "셀프 호스팅" | 9px |
| 슬라이드 목록의 컴포넌트 이름 (핵심 지표 · 단계) | 10px |
| **API 문서와 사용 가이드의 코드 예제** | **9px · 10px** |

마지막 것이 특히 나빴습니다. 다른 서비스에서 연동할 때 **읽으라고 있는 코드** 가 주변 본문보다
두 단계 작게 그려지고 있었습니다. 코드 블록은 `font:` 축약형으로 쓰여 있어 크기만 찾는 검사에
아예 걸리지 않았습니다.

**76곳(공백 표기) + 코드 블록 4곳 + 작은 라벨 7곳** 을 올려 이제 인터페이스 글자는
**11px 아래가 없습니다.**

## 두 번 키우지 않았습니다

공백 표기를 고치는 과정에서 정규식을 느슨하게 바꿨더니 **이미 올린 곳까지 또 올라갔습니다**
(9 → 12 → 14.5). 배포된 상태로 되돌리고, **공백 표기만** 골라 다시 했습니다. 워크스페이스가
두 배로 커진 채 나갈 뻔한 것을 배포 전에 잡았습니다.

## 나머지 화면은 멀쩡했습니다

15개 화면 × 두 가지 창 너비(1440 · 1280)로 훑었고, v1.8.0 이 깨뜨린 곳은 **없었습니다.**
발표 화면, 공유 링크 화면, 만들기 흐름, 관리자 표 모두 그대로입니다.

## 설치

```bash
gzip -dc ptium-1.8.1.tar.gz | docker load
```
