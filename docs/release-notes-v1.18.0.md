# Ptium v1.18.0

## PDF를 읽습니다

지금까지 가져오기는 `.pptx` · `.xlsx` · `.csv` · `.docx` · `.md` 를 읽었고, **PDF는 거절했습니다.**
"글을 꺼내려면 폰트·인코딩·압축을 다루는 파서가 필요하고, 그 의존성은 폐쇄망 배포의 단순함과
바꿀 만한 것이 아니다" — 그렇게 적어 두었습니다.

그런데 회사가 자료를 주고받는 형식은 대개 PDF입니다. 규정도, 대행사 보고서도, 작년 발표자료도
PDF로 옵니다.

### 먼저 재 봤습니다

손에 있는 **실제 PDF 52개**로 후보 라이브러리를 재 봤습니다. 결과는 분명했습니다 —
**한글 0자.** 라틴 문자도 `Ö¨¬üÈÇ` 로 깨졌습니다. 쓸 수 없는 물건이었습니다.

같은 52개를 직접 훑어보니 **40개가 텍스트 레이어를 갖고 있었고 `/ToUnicode` 도 있었습니다.**
읽을 수 있는 파일을 못 읽고 있었던 것이지, 읽을 게 없는 게 아니었습니다. 그래서
**표준 라이브러리만으로 PDF 리더를 직접 썼습니다**(`internal/pdftext`). 의존성은 늘지 않았고,
폐쇄망 배포는 그대로입니다.

### 다시 잰 결과

| | 라이브러리 | Ptium |
| --- | --- | --- |
| 읽어낸 파일 | 0 | **42 / 52** |
| 나머지 10개 | — | **글자가 아예 없는 파일**(스캔본·그림으로 내보낸 PDF) |
| 한글 | 0자 | 전자금융감독규정 31,056자, 거래내역서 28,460자 … |

(폴더에는 `.pdf` 로 끝나는 파일이 56개 있었고, 그중 4개는 내용이 JSON이었습니다 — PDF가 아니라고
거절합니다. 나머지 52개가 위 숫자입니다.)

읽지 못한 10개는 전부 확인했습니다. 텍스트를 그리는 명령이 하나도 없고 그림만 있는 파일이었고,
**PDF 리더의 문제가 아니라 그 파일에 글자가 없는 것**입니다.

### 읽으면서 고친 것들

실제 파일이 아니면 몰랐을 것들입니다.

- **한 덩어리에 12,249개짜리 문자표.** 표준은 한 블록에 100개까지를 권하는데 실제 생성기는
  12,249개를 한 블록에 씁니다. 앞쪽을 버리는 구현이었다면 한 페이지의 10분의 1만 읽고
  나머지는 조용히 사라졌을 겁니다.
- **한글을 UTF-16으로 쓰면서 폰트는 라틴이라고 적은 파일.** 파일 말대로 읽으면 `Ö¨¬üÈÇ` 이고,
  쓰인 대로 읽으면 "프로젝트 현황"입니다. 라틴 바이트가 우연히 한글로 이어져 읽히는 일은 없으므로,
  이건 추측이 아니라 증거입니다.
- **자모로 쪼개 주는 폰트.** `ᄒ`+`ᅡ`+`ᆫ` 을 그대로 슬라이드에 넣으면 파워포인트에서 깨져 보입니다.
  유니코드가 정한 계산 그대로 **한 글자로 합칩니다.**
- **글자를 한 자씩 따로 찍는 생성기.** PDF에는 "줄"이 없고 좌표에 놓인 글자만 있습니다.
  그리기 명령 하나를 한 줄로 세면 `R` `E` `P` `O` `R` `T` 가 여섯 개의 요점이 됩니다.
  **같은 기준선에 있으면 한 줄**이고, 벌어진 간격은 띄어쓰기입니다. 실측 보고서 1쪽이
  **268줄 → 23줄**이 되었습니다.

### 모르는 것은 지어내지 않습니다

문자표가 없는 두 바이트 코드는 글자 번호일 뿐입니다. **그럴듯한 글자를 지어내는 것이 리더가
거짓말하는 방법**이라서, 증명할 수 없는 글자는 넣지 않습니다. 그래서 스캔본은 빈 덱이 되지 않고
이렇게 답합니다.

> 이 PDF에는 글자가 없습니다. 스캔했거나 그림으로 내보낸 파일로 보입니다. 원본 문서나 텍스트가
> 살아 있는 PDF로 올려주세요

## 덱이 되는 방식

- **한 쪽이 한 장**입니다. 쪽의 첫 줄이 제목처럼 보이면(짧고, 문장으로 끝나지 않으면) 제목이 되고,
  아니면 앞 장을 잇습니다.
- **모든 쪽에 반복되는 머리글·꼬리글과 쪽 번호는 빼고** 넣습니다. `법제처 12 국가법령정보센터` 처럼
  쪽 번호가 머리글 안에 들어 있어 줄마다 달라지는 경우까지 같은 것으로 봅니다.
- **한 장에 안 들어가는 줄은 발표자 노트로** 갑니다. 한 쪽을 여덟 장으로 쪼개지도, 버리지도 않습니다.
  34쪽짜리 감독규정이 31장(제한 30장 + 표지)이 되고, 넘친 4장은 몇 장이 남았는지 알려 줍니다.
- **각 장에 몇 쪽에서 왔는지** 출처가 붙습니다 — `!source 규정.pdf | 12쪽`.

## 함께 고친 것

가져오기 전반의 결함 두 개를 실제 파일에서 발견해 고쳤습니다. `.docx` 도 같은 길을 씁니다.

- 한 장에 다 못 담아 이어지는 장이 **자기 제목을 출처로 달고 있었습니다.** 이어지는 장은 원래
  자리에서 왔으므로, 그 자리를 그대로 답니다.
- 제목이 `(계속) (계속) (계속)` 으로 늘어났습니다. 이제 한 번만 붙습니다.

## 검사

- `internal/pdftext` 11개 · `internal/docs` PDF 6개 — 전부 **고친 코드를 되돌리면 실패하는지**
  확인했습니다.
- REST 훑기에 PDF 구간을 넣었습니다(467개 점검): 쪽이 장이 되는지, 출처가 쪽인지, 반복되는
  머리글이 슬라이드 글이 되지 않는지, 스캔본이 **이유를 말하며** 거절되는지.
