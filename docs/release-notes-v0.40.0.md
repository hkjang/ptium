# Ptium v0.40.0

자체 호스팅 모델(122B)에 실제 브리프를 넣어 10장짜리 보고서를 뽑고, 나온 것을 읽었습니다.

## 모델이 쓴 한국어는 숫자와 단위 사이가 벌어져 있습니다

```
배치 지연을 4 시간에서 15 분으로 단축
12 억 예산으로 투자 효율성을 극대화합니다
2026 년 하반기 · 3 단계 이행
각 단계는 명확한 deliverables 를 가지며 … 94% 의 개선
```

한국어를 쓰는 모델이 거의 예외 없이 하는 일입니다. 맞춤법이 틀린 것은 아니지만(단위 명사는
띄어 쓰는 것이 원칙입니다), **아라비아 숫자로 쓴 업무 문서에서는 붙여 쓰는 것이 관례**이고,
벌어진 쪽은 읽는 사람에게 **기계가 쓴 티**로 보입니다. 조사는 아예 붙여 써야 합니다.

Ptium은 이미 슬라이드의 글을 읽어 들이면서 이것을 정리하고 있었습니다. **딱 한 줄만 빼고 —
`!notes`.** 그래서 슬라이드는 `4시간`인데 발표자 노트는 `4 시간`이었고, 이 노트는 그대로
PowerPoint 노트 창으로 나갑니다.

- 발표자 노트도 같은 규칙을 지납니다.
- 규칙에 두 가지가 늘었습니다: **로마자·숫자 뒤의 조사**(`deliverables 를` → `deliverables를`,
  `94% 의` → `94%의`)와 단위 몇 개(`시`, `쪽`, `권`, `편`, `톤`, `줄`…).
- **모델이 쓴 소스 자체**도 문 앞에서 정리합니다. 지금까지는 슬라이드만 고쳐졌고 작업 공간의
  **코드** 화면에는 벌어진 원문이 남아 있었습니다. 이제 둘이 같은 문서입니다.

사람이 직접 친 글은 건드리지 않습니다. 편집기에 적어 둔 소스는 적은 그대로 남고, 슬라이드만
정리된 채로 그려집니다.

실측: 이번에 뽑은 10장 덱의 소스 **73줄 중 31줄**이 정리됐고, 정리되지 말아야 할 것은 그대로
남았습니다 — `94% 단축`, `20% 절감`, `1 대 1`, `은 메달`, `차 한 대`.

## 확인

- 회귀 테스트 3건: 붙여야 할 것 7가지, **건드리지 말아야 할 것 7가지**, 그리고 한국어 덱에만
  적용된다는 것(영어 덱은 그대로).
- 노트 회귀 테스트 1건: `!notes` 줄이 제목·리드·요점과 같은 규칙을 지납니다.
- 전수 점검: api 75 · edges 32 · deep · package 0 실패.
