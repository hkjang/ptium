# Ptium v1.29.3

어제 가져오기가 **그림에 무슨 일이 있었는지** 제대로 말하게 했습니다. 그런데 그 말이
**어디로 가는지**는 보지 않았습니다.

## 네 문장이 한 줄로 붙어서 사라졌습니다

가져오기 결과는 **토스트 한 줄**이었습니다.

```js
showToast([`${result.slides}장을 가져왔습니다.`, ...result.warnings].join(' '))
```

어제 문장을 하나 더 늘렸으니, 실제로는 이렇게 나갑니다 —

```
10장을 가져왔습니다. 그림 22개를 이미지 라이브러리에 저장했습니다 그 가운데 12개를
슬라이드에 넣었습니다. 나머지 10개는 이 디자인의 레이아웃에 그림 자리가 모자라
들어가지 못했습니다 — 이미지 탭에 있으니… 표 1개를 이 덱의 디자인으로 다시…
```

**읽기 전에 사라집니다.** 그리고 사용자는 곧바로 편집기로 이동합니다.

## 편집기에는 이미 그 자리가 있었습니다

모델이 쓴 덱은 **생성 안내 패널**에 무슨 일이 있었는지 남깁니다 — 한 줄에 하나씩,
닫기 전까지 그대로 있는 자리입니다. **가져온 덱만 그 칸이 비어 있었습니다.**

이제 가져오기가 한 말이 **덱과 함께 저장되고**, 편집기에서 그대로 보입니다.

```
그림 22개를 이미지 라이브러리에 저장했습니다
그 가운데 12개를 슬라이드에 넣었습니다. 나머지 10개는 …
표 1개를 이 덱의 디자인으로 다시 그렸습니다
여러 장에 반복되는 그림 2개는 로고로 보아 넣지 않았습니다(가장 많은 것은 8장)
```

토스트는 **"10장을 가져왔습니다."** 한 줄로 돌아갔습니다 — 토스트가 할 수 있는 말은
그것뿐입니다.

## 검사

- 덱이 가져오기의 말을 **그대로 갖고 있는지**, 그리고 **남의 덱에는 쓸 수 없는지**를
  데이터베이스로 확인합니다.
- REST 훑기가 가져온 덱을 다시 읽어 **첫 문장이 답과 같은지** 봅니다.
- 실제 회사 PPT로 편집기 화면에서 네 줄이 보이는 것을 확인했습니다.

전체 Go 테스트(DB 포함) · 웹 156개 · REST 579개 · 화면 훑기 · flows 0 failures.
