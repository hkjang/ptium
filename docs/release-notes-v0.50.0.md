# Ptium v0.50.0

계획서 6차 — **편집기 분해와 프론트 테스트**입니다. 다만 순서를 지켰습니다.

## 테스트를 먼저 넣었습니다

`EditorPage.tsx` 는 81KB짜리 한 파일이고, 나눠야 하는 것이 맞습니다. 그런데 **테스트 없이 큰
컴포넌트를 쪼개는 것은 회귀를 부릅니다.** 브라우저 스윕(`scripts/e2e`)이 있지만, 그것은 "화면이
뜨는가"를 봅니다 — 번역 규칙 하나가 틀렸을 때 어느 규칙인지 말해 주지는 않습니다.

그래서 이번 판은 **Vitest**를 넣고, 편집기에서 **React가 필요 없는 부분**을 모듈로 꺼내
테스트를 붙이는 데까지 했습니다.

```
web/src/pages/editor/model/
  ├─ findings.ts       측정 결과를 읽는 사람의 말로 (17개 규칙)
  ├─ findings.test.ts
  ├─ slides.ts         슬라이드가 템플릿 슬롯과 맺는 관계
  └─ slides.test.ts
```

`EditorPage.tsx` 81KB → **76KB**. 큰 감량은 아니지만, 나간 것이 **가장 규칙이 많고 가장 조용히
틀리던 부분**입니다. 남은 화면·훅 분리는 이 테스트 위에서 다음 판에 합니다.

## 첫 테스트가 바로 결함을 잡았습니다

측정 결과를 한국어로 옮기는 규칙에 **슬롯 이름이 빠져 있었습니다.**

```
전: 본문이 title 영역과 18% 겹칩니다
후: 본문이 제목 영역과 18% 겹칩니다
```

`title` · `body` · `body2` 같은 영역 이름이 한국어 문장 한가운데 영어로 남아 있었습니다.
반쪽만 번역된 문장은 아예 번역하지 않은 것보다 나쁩니다 — 읽는 사람이 그게 자기 말인지
기계 말인지 알 수 없기 때문입니다. 영역 이름을 모두 넣고, 겹침 규칙이 **양쪽** 이름을 번역하게
했습니다.

테스트에 규칙 하나를 더 뒀습니다: 번역된 문장에 **알파벳 세 글자 이상이 남아 있으면 실패**
(색상 코드는 제외). 다음에 규칙을 추가할 때 같은 실수를 하면 그 자리에서 잡힙니다.

## 그리고 그 다음 실수도 잡혔습니다

테스트를 넣자마자 **이미지 빌드가 깨졌습니다.** 컨테이너 빌드는 `tsc -b` 로 타입을 검사하는데,
그 검사가 **테스트 파일까지** 훑고 있었습니다. 픽스처의 필드 하나가 틀리면 제품의 빌드가
멈추는 구조입니다. 테스트는 그것을 실행하는 쪽(`npm test`)이 검사하고, 배포 빌드는 제품만
봅니다.

## 확인

- 유닛 테스트 8건 (`npm test` in `web/`): 번역 규칙 8가지, 규칙이 없는 문장은 그대로 둘 것,
  측정 종류 9가지와 점수 축 5가지·체크포인트 4가지에 모두 이름이 있을 것, 슬라이드가 슬롯과
  맺는 관계 4가지.
- 브라우저 스윕(flows)과 서버 전수 점검은 그대로 통과.
- 전수 점검: api 87 · edges 32 · package · deep · flows 0 실패.
