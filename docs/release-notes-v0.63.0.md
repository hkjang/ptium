# Ptium v0.63.0

마지막으로 남은 입구 — **PPTX 가져오기** — 를 감사했습니다. 덱을 하나 써서 내보내고 그대로
다시 가져와, 무엇이 살아 돌아오는지 봤습니다.

## 내보냈다 다시 가져오면 덱이 부서져 있었습니다

슬라이드 위의 컴포넌트는 **그림**입니다. 프로세스는 원과 선이고, 지표 카드는 상자와 숫자입니다.
그것을 다시 읽으면 이렇게 됩니다.

```
# 이행 계획          → - 1 / - 준비 / - 범위 확정 / - 2 / - 이행 / - 이관 …
# 핵심 지표          → - 한눈에 / - 연간 중단 / - 257분 / - 복구 시간 / - 14분 …
# 현장의 말 (인용)    → - 출처: 내부 인터뷰… / - 배포 하나에 이틀이…
# 다음 단계 (마무리)  → @section · 세 줄이 한 문장으로 뭉침
```

**말은 살아남고 뜻은 사라집니다.** 인용은 평범한 글머리표가 되고, `!source` 는 본문 한 줄이
되고, 마무리 슬라이드는 구역 페이지가 됩니다.

## 파일이 자기가 어떻게 쓰였는지 들고 다닙니다

이제 Ptium이 내보내는 파일에는 그 덱의 **원본 텍스트**가 함께 들어갑니다 —
`ppt/ptiumSource.xml`, PowerPoint는 무시하는 부품이고 크기는 몇 KB입니다. 가져올 때 그 부품이
있으면 **쓰인 그대로 복원**합니다. 그림을 보고 추측하지 않습니다.

왕복 결과: 8장 → 8장, 인용 · 지표 · 프로세스 · 표 · 차트 · 출처 · 발표자 노트 **전부 그대로**.

- 부품은 프레젠테이션에 관계로 연결됩니다. 아무것도 가리키지 않는 부품은 다음 저장에서
  버려지기 때문입니다.
- 다른 도구가 만든 파일은 **전과 똑같이** 도형을 읽어 가져옵니다.
- python-pptx로 열어 확인했고, 내보내기 검증 스윕도 그대로 통과합니다.

## 누군가 PowerPoint에서 고쳤다면 그쪽이 이깁니다

이 기능이 할 수 있는 최악의 일은, 파일을 받아 숫자 하나를 고쳐 보낸 사람의 수정을 **말없이
되돌리는** 것입니다.

그래서 부품에는 슬라이드의 모든 글자에 대한 **지문**이 함께 적힙니다. 가져올 때 파일의 지문이
다르면 — 다른 곳에서 고쳐졌다는 뜻이므로 — 원본 텍스트를 무시하고 도형을 읽습니다.
**고친 사람이 이깁니다.**
