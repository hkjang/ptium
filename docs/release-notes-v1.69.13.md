# Ptium 1.69.13

## 내려받은 파일이 열리는지를 지키는 검사

파워포인트가 파일을 열 때 가장 먼저 보는 것은 내용이 아니라 꾸러미입니다. 관계가
가리키는 부속이 실제로 있는지, 모든 부속이 `[Content_Types].xml` 에 선언되어
있는지, 부속이 XML 로 읽히는지, 슬라이드가 쓰는 `r:id` 가 그 슬라이드의 관계 안에
있는지. 하나라도 어긋나면 파워포인트는 **"복구할까요?"** 를 먼저 묻습니다. 한 글자도
읽기 전에 못 믿을 파일이 되는 셈입니다.

기존 검사들은 각자 관심 있는 관계 하나씩만 보고 있었습니다. 선언되지 않은 부속이나,
없는 그림을 가리키는 슬라이드는 아무도 보지 않았습니다.

이제 `internal/export/package_test.go` 가 덱을 **꾸러미로** 읽습니다. 구성 요소
열다섯 가지를 모두 넣고 링크·점프·발표 노트까지 있는 17장짜리 덱을 디자인 네 개로
내보내 확인합니다.

## 검사가 정말 무언가를 보고 있는지도 검사합니다

빈 파일은 위의 네 가지를 모두 통과합니다. 그래서 먼저 **무엇을 읽고 있는지** 셉니다.
슬라이드 15장 미만, 차트 없음, 관계 파일 5개 미만이면 그 자리에서 실패합니다.

그리고 멀쩡한 파일을 네 가지로 망가뜨려, 검사가 각각을 잡아내는지 봅니다.

- 관계가 가리키는 부속을 지움
- 아무도 선언하지 않은 부속을 넣음
- 슬라이드가 갖고 있지 않은 `r:id` 를 씀
- 부속을 XML 이 아니게 만듦

처음에 두 번째 경우를 "슬라이드의 Override 선언을 지우기"로 잡았는데 **검사가 잡지
못했습니다.** 확장자 기본 선언(`<Default Extension="xml">`)이 그 부속을 여전히
덮고 있었기 때문입니다 — OPC 규칙이 실제로 그렇습니다. 검사가 틀린 게 아니라
망가뜨리는 방법이 틀렸던 것이라, 아무도 선언하지 않은 확장자의 부속을 넣는 쪽으로
바꿨습니다.

## 확인만 하고 고치지 않은 것

python-pptx 로 내려받은 파일을 열어 다음을 확인했고, 모두 제대로였습니다.

- 슬라이드 크기 13.333 × 7.5인치, 제목은 템플릿의 자리 표시자를 그대로 씀
- 쪽 번호가 글자가 아니라 `slidenum` 필드 — 파워포인트에서 순서를 바꿔도 따라감
- 그림 설명: `::image 이름 | 설명` 의 설명이 대체 텍스트로 들어감. 설명이 없으면
  이미지 이름을 쓰되, `IMG_2831.png` 처럼 파일 이름으로 보이면 대체 텍스트를 아예
  쓰지 않고 제품이 "설명 없는 이미지"로 지적함
- 꾸러미 무결성: 디자인 여섯 개 × 구성 요소 열다섯 가지, 문제 0건
