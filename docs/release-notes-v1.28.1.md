# Ptium v1.28.1

1.28.0에서 **느린 생성을 그대로 두도록** 고쳤습니다. 그러자 **생성 큐 화면이 늑대를
외치게 됩니다** — 어제 만든 자리입니다.

## "15분 넘게 기다린 덱"

큐 화면은 15분이 지난 덱을 **문제 있는 덱**으로 셌습니다. 어제까지는 반쯤 맞는
말이었습니다(10분이면 회수되었으니까). 이제는 **30분 동안 잘 쓰이고 있는 덱**이
정상입니다 — 자체 호스팅 모델은 한 번 호출에 수 분이 걸리고, 자동 수정을 10회까지 걸 수
있습니다.

그러면 화면은 **멀쩡한 덱을 문제로 보고**하고, 운영자는 그걸 보고 **중단**할 수 있습니다.

## 오래 걸리는 것과 아무도 안 하고 있는 것

워커는 30초마다 살아 있다고 말합니다. 그래서 이제 큐가 **"얼마나 조용한가"** 를 함께
답합니다(`quietSeconds`).

```
대기 중인 덱      15분 넘게 아무도 안 가져감   → 문제
작성 중인 덱      3분 넘게 아무 말 없음        → 문제
작성 중인 덱      30분째 쓰는 중, 10초 전에 말함 → 정상
```

화면도 그대로 말합니다.

```
작성 중  32분  · 작성 중          ← 살아 있음
작성 중  12분  · 4분째 응답 없음   ← 맡은 워커가 조용합니다
```

지표 이름도 바꿨습니다 — **"맡은 워커가 조용하거나 15분 넘게 대기"**.

## 검사

- 큐 답변: 대기 중인 덱은 침묵 시간을 답하지 않고, 30분째 쓰면서 10초 전에 말한 덱은
  **조용하지 않다**고 답하며, 9분 동안 말이 없으면 그대로 답합니다. 침묵 대신 경과
  시간을 답하도록 되돌리면 그 자리에서 실패합니다.
- 화면 규칙: 여섯 가지 경우를 단위 테스트로 고정했습니다.
- 문서(`roadmap-v2.md`)의 "10분 후 재확보"도 사실에 맞게 고쳤습니다.

전체 Go 테스트(DB 포함) · 웹 149개 · REST 573개 · 화면 훑기 0 failures.
