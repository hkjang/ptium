# Ptium 1.69.6

## 창이 열리면 키보드도 창 안으로 들어갑니다

창(대화 상자)에는 `aria-modal="true"` 가 붙어 있었습니다. 보조 기술에게 "뒤쪽은
지금 없는 셈 치라"고 말하는 표시입니다. 그렇게 말만 해두고, 실제로 그렇게 만드는
코드는 없었습니다.

키보드로 창을 열면 초점은 창을 연 버튼에 그대로 남았습니다. 템플릿 화면에서 재어
보니, 창 안의 버튼에 닿으려면 탭을 **95번** 눌러야 했습니다. 창 뒤에 가려진
페이지의 조작 요소 119개를 하나씩 지나가는 길이었습니다. 겨우 들어가도 13번 만에
다시 뒤쪽으로 빠져나왔습니다.

이제 창이 열리면,

- 초점이 창 자체로 들어갑니다. 첫 버튼이 아니라 창으로 들어가므로, 낭독기가 제목을
  먼저 읽고 그 아래 조작 요소로 넘어갑니다.
- 탭과 시프트+탭이 창 안에서 돌고, 뒤쪽으로 나가지 않습니다.
- Escape 로 닫으면 초점이 창을 열었던 그 버튼으로 돌아갑니다.

관리 화면의 서랍(오류 상세, 감사 기록 상세)은 창과 같은 부품이 아니어서 Escape
로도 닫히지 않았습니다. 같은 규칙을 쓰는 훅으로 묶어 서랍도 똑같이 동작합니다.

## 지키는 장치

`scripts/e2e/ui.py`가 템플릿 창, 사용자 창, 감사 기록 서랍을 차례로 열어 초점이
안으로 들어오는지, 탭·시프트탭 50번 동안 밖으로 새지 않는지, Escape 로 닫히는지,
닫힌 뒤 초점이 열었던 자리로 돌아오는지 봅니다.

고침을 되돌려 돌리니 일곱 줄이 그대로 실패로 나왔습니다.
