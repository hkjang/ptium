# Ptium v1.40.0

**"보고해줘"의 "줘"가 표지에 올라가 있었습니다.**

## 브리프에 쓴 말투가 그대로 제목이 됐습니다

사용자가 실제로 쓰는 문장으로 덱을 만들어 봤습니다.

```
사내 PostgreSQL 전환 타당성 검토 결과를 경영진에게 12장으로 보고해줘
   → 표지: "사내 PostgreSQL 전환 타당성 검토 결과를 줘"
     그리고 아홉 장 전부의 머리글이 "…검토 결과를 줘 — 이행 순서" 였습니다.
```

한국어로 자료를 요청하는 가장 평범한 아홉 문장 중 **다섯 개**가 명령형을 제목에
남겼습니다.

| 브리프 끝 | 제목이 되던 말 |
| --- | --- |
| …보고해줘 | …검토 결과를 **줘** |
| …써줘 | …방안을 **써줘** |
| …보고해 주세요 | …방안을 **주세요** |
| …써 주세요 | …계획을 **써 주세요** |
| 경영진 대상 …작성해줘 | …로드맵을 **경영진 대상** |

원인은 셋이었습니다. 청중을 걷어내는 규칙이 `보고해`까지만 가져가고 `줘`를 남겼고,
`써 주세요`는 요청 동사 목록에 없었고, 청중을 `에게` 없이 `경영진 대상`으로 부르는
방식은 아예 다루지 않았습니다.

## 제품이 이미 알고 있었습니다

더 뼈아픈 부분입니다. 측정 계층은 이 제목들을 **이미 찾아내고 있었습니다** —
`the heading stops in the middle of what it was saying`. 찾아 놓고 그대로 내보냈습니다.

## 이제

요청을 끝내는 말(`줘·주세요·주시고·주십시오·다오`)은 요청의 일부로 취급합니다.
동사만 떼고 어미를 남기는 일이 없도록 요청 동사 세 갈래 모두에 붙였습니다.

같은 브리프 여섯 개를 사용자의 실제 템플릿 세 개에 다시 생성한 결과:

- `unfinished` 지적 **4건 → 0건**
- 두 덱이 **100점**(이전에는 전부 99점)
- 표지: `사내 PostgreSQL 전환 타당성 검토 결과` / `전사 데이터 거버넌스 체계 수립 방안`
  / `클라우드 비용 최적화 3개년 로드맵`

평범한 명사는 그대로 둡니다. `분석 대상 데이터셋 선정 기준`의 "대상"과
`월간 보고서 자동화 방안`의 "보고서"는 주제의 일부이며, 그 점도 함께 고정했습니다.
