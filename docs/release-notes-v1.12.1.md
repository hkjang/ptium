# Ptium v1.12.1

## 계정에 있는 이미지를 덱이 알아서 씁니다

젠스파크는 웹에서 이미지를 찾아 넣습니다. 폐쇄망에서는 그럴 수 없지만, **그 자리에 해당하는
것은 이미 있습니다** — 사용자가 올려 둔 이미지 라이브러리입니다. 이 워크스페이스만 해도
343개가 들어 있는데, 생성기는 그 존재를 **아예 몰랐습니다.**

이제 압니다.

```
# 현장 자동화 도입 계획        ← 슬라이드 2
::image 현장 자동화

# 조직도 개편                 ← 슬라이드 5
::image 조직도
```

- **이름으로 맞춥니다.** 슬라이드 라이브러리가 "회사 소개"를 찾는 것과 같은 방식입니다.
  "현장 자동화 도입 계획" 슬라이드와 "현장 자동화" 이미지는 같은 주제입니다
- **없으면 넣지 않습니다.** 글에서 사진 같은 낱말을 찾아 아무거나 얹는 일은 하지 않습니다 —
  아무도 고르지 않은 장식은 여백보다 나쁩니다
- 한 덱에 **최대 두 장**, 같은 사진을 두 번 쓰지 않고, 표지에는 넣지 않습니다
- 모델이 있는 배포에서는 **이미지 목록을 프롬프트에 함께 줍니다.** 목록에 없는 이름을
  지어내는 것은 없는 숫자를 지어내는 것과 같이 금지됩니다

## 만들면서 드러난 것

이름은 맞는데 그림이 안 붙었습니다. 원인이 둘이었습니다.

1. **이름을 실제 이미지로 바꿔 줄 해석기가 생성 경로에 없었습니다.** 편집기가 코드를 적용할
   때 쓰는 그 해석기를 생성기에도 연결했습니다. 없으면 소스에는 `::image 현장 자동화` 가
   적히고 슬라이드는 그림 없이 그려집니다
2. **이미지 목록이 즐겨찾기 우선 정렬이었습니다.** 사람이 훑을 때는 옳지만(핀을 꽂은 이유가
   그것이니까요), 생성기에는 **오늘 올린 사진** 이 필요합니다. 이 워크스페이스는 343개 중
   234개가 즐겨찾기라 최근 업로드가 목록에 들지도 못했습니다. 생성기 전용으로 **최신순
   이름 목록** 을 따로 읽습니다

## 확인

폐쇄망 생성: 두 이미지가 각각 2번·5번 슬라이드에 붙고 **미리보기에 실제로 그려짐**, 결함 0 ·
권고 0. 스윕 186 checks — 계정에 있는 이미지를 다루는 덱이 그것 없이 나오면 실패합니다.
