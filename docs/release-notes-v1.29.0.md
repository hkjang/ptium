# Ptium v1.29.0

**실제 회사 파일 세 개**를 템플릿으로 올려서 이 제품의 본래 약속을 재 봤습니다 —
"내 템플릿 그대로 나오는가". 결과는 좋았습니다. 그런데 **덱 자체에서** 하나가 나왔습니다.

## 같은 제목이 두 번

브리프에 "비용과 일정, 다음 단계"를 넣고 8장을 만들었더니 —

```
1  데이터 플랫폼 도입 성과와 다음 단계
2  목차
3  데이터 플랫폼 도입 성과
4  데이터 플랫폼 도입 성과 — 기대 효과
5  다음 단계        ←
6  비용
7  일정 포함
8  다음 단계        ← 같은 제목
```

**측정은 아무 말도 하지 않았습니다.** 그릴 것은 다 그려졌고, 자리에 다 들어갔고,
노트도 다 있었으니까요. 이 제품이 재는 것은 전부 **그림에 대한 것**이었습니다.

덱 20개를 확인해 보니 **2개**가 같은 상태였습니다.

발표를 듣는 사람은 같은 제목을 두 번 보면 **되돌아간 것인지, 반복인지, 다른 이야기인지**
알 수 없습니다. 만든 사람은 그 사실을 들은 적이 없습니다.

## 이제 말합니다

```
앞 장과 같은 제목
8번 슬라이드: 5번 슬라이드도 제목이 "다음 단계"입니다.
             같은 제목이 두 번 나오면 어느 쪽 이야기인지 알 수 없습니다
```

- **뒤에 나온 장**에 알립니다. 앞 장이 그 제목의 임자이고, 어느 쪽을 고칠지는 만든
  사람이 정할 일입니다.
- 띄어쓰기와 끝의 문장부호는 따지지 않고, **다른 낱말이면 다른 제목**입니다.
- 결함(defect)이 아니라 **권고(advisory)** 입니다 — 잘못 그려진 것은 없으니까요.

## 템플릿 충실도 (문제 없었습니다)

같이 잰 것들입니다. 실제 회사 파일 세 개(0.1MB · 1.3MB · 2.2MB) —

- **11개 레이아웃을 모두 읽었고**, 표지·본문·구역 역할을 찾았습니다.
- 내보낸 .pptx가 **글꼴과 색 구성(theme)을 그대로** 갖고 있습니다.
- **A4(9906000×6858000) 슬라이드 크기도 그대로** 입니다 — 16:9로 바꾸지 않습니다.
- 각 장이 **그 템플릿 자신의 레이아웃**을 씁니다(표지는 제목 슬라이드, 본문은 제목 및 내용).
- 실제 덱 측정: **결함 0**.

## 검사

- 측정 단위 테스트: 반복된 제목은 뒤 장에 한 번, 앞 장 번호와 함께. 첫 등장은 반복이
  아니고, 띄어쓰기만 다르면 같은 제목이며, 제목이 없거나 한 글자면 아무 말도 하지
  않습니다.
- REST 훑기가 제목이 반복되는 덱을 실제로 만들어 **3번 장에서 잡히는지** 봅니다. 측정을
  빼면 그 자리에서 실패합니다.
- 새 종류를 스키마(`twiceTitled`)와 화면 문구에 함께 넣었습니다.
