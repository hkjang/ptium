# Ptium v0.89.0

지난 판의 온보딩 덱은 브리프에 **없는 출처를 5건** 인용했고, 정작 브리프가 준 **사내 설문은
한 번도 인용하지 않았습니다.** 5건 중 4건은 지워졌습니다. 살아남은 하나가 이겁니다.

```
!source 내부 개발본부 보고서
```

브리프에 `개발본부` 가 있으니 통과했습니다 — **덱을 누구에게 보고하는지** 를 말한 자리에서요.
이게 가장 나쁜 종류의 날조입니다. **맞는 절반이 나머지를 믿게 만듭니다.**

## 절(clause)을 단위로 봅니다

이제 인용을 믿는 조건은 둘 중 하나입니다.

1. 브리프가 그 **이름을 그대로 적었다** — 저자 자신의 말이니 더 볼 것이 없습니다
2. 인용의 단어가, 브리프에서 **출처를 말하는 절 안에** 있다 — `기준`, `따르면`, `설문`,
   `조사`, `로그`, `보고서`, 파일 이름 같은 표지와 같은 절

거리(몇 글자 이내)로 재지 않습니다. **짧은 브리프에서는 모든 것이 모든 것 근처** 라서,
"개발본부 리더들에게 공유" 가 "사내 설문" 에서 열 몇 글자 거리에 있습니다.

저장된 덱 전부로 확인했습니다 — **23건 유지, 13건 삭제**, 삭제된 13건은 **전부 출처를 하나도
말하지 않은 브리프** 에서 나온 것들입니다.

## 지우는 것만으로는 절반입니다

브리프가 출처를 말했는데 **어느 슬라이드도 아무것도 인용하지 않으면** 이제 덱이 말합니다.

> 브리프가 말한 출처가 어느 슬라이드에도 인용되지 않았습니다. 숫자 옆에 `!source` 로 적어
> 두면 발표자 노트에도 함께 나갑니다.

저자가 회의실에서 가장 많이 요구받는 바로 그것을 줬는데 안 쓰인 것이니까요. 자기 자신을
"실무 논의 자료" 라고 부르는 브리프는 출처를 말한 게 아니라서, `자료` 와 `데이터` 는 세는
단어에서 뺐습니다.

## 결과

같은 브리프를 다시 태우니 덱이 이렇게 인용합니다.

```
!source 사내 온보딩 설문 | 2026년 3월, 응답 112명
```

**브리프가 준 것 하나, 그 위치까지. 나머지는 없습니다.**

## 설치

오프라인 설치 방법은 [docs/offline-deployment.md](offline-deployment.md) 를 보세요. 이미지에
Postgres 와 nginx 는 들어 있지 않습니다 — 배포할 때 `DATABASE_URL` 로 DSN 을 지정합니다.
