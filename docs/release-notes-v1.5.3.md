# Ptium v1.5.3

지난 두 판(v1.5.1, v1.5.2)의 원인은 같았습니다. **불변식이 예제 하나로만 검사되고 있었습니다.**

- 왕복(compile → 다시 쓰기 → compile): 예제 덱 **1개** 로 검사 → 1,000개 중 3개가 줄을 잃고 있었음
- 내보내기 → 들여오기: 덱 **1~2개** 로 검사 → 캔버스에서 편집한 덱은 한 장이 사라지고 있었음

이번 판은 **버그를 찾는 대신 그물을 짰습니다.**

## 모든 모양을 훑습니다

컴포넌트 **15종** × 역할 **9종** × (리드 / 발표 노트 / 출처 있음·없음) — 여기에 지난 판에서
실제로 깨졌던 모양(두 열이 각자 이름을 가진 비교 슬라이드 등)을 더해 **500가지 넘는 슬라이드**
를 만들어 두 가지를 확인합니다.

1. **써서 다시 읽으면 같은 덱인가** — 제목 · 컴포넌트 수 · 각 영역의 줄 수 · 발표 노트 · 출처
2. **한 장만 따로 쓴 것이, 덱이 그 장에 대해 말하는 것과 같은가** — 슬라이드를 저장해
   다른 덱에 넣는 기능이 이것에 기대고 있습니다

이 그물이 실제로 잡는지 확인했습니다. v1.5.1 에서 고친 한 줄을 **일부러 되돌리자 즉시
실패** 했습니다. 통과만 하고 아무것도 못 잡는 테스트가 아닙니다.

## 복원도 이제 확인합니다

버전 복원은 e2e 에서 **"200이 오는가"만** 보고 있었습니다. 다른 덱이 돌아와도 통과했습니다.

이제 덮어쓰기 전 원본을 기억해 두고, 덮어쓴 뒤 최신 체크포인트를 복원해 **덱이 그대로
돌아왔는지 글자 단위로 비교** 합니다. (api 검사 101 → **102개**)

## 재 봤지만 고칠 게 없던 것

- **슬라이드 저장**: 저장된 덱의 슬라이드 **8,271장** 을 한 장씩 따로 써서 덱의 표현과 비교 →
  **차이 0**
- **버전 복원**: 실제 덱 내용으로 만든 **120개** 덱에 대해 쓰기 → 덮어쓰기 → 복원 →
  **차이 0**

둘 다 멀쩡했습니다. 중간에 "41/120이 깨졌다"는 결과가 나왔는데, **비교 기준이 틀렸습니다** —
작성자가 손으로 쓴 원문과 시스템이 정규화한 표현을 견주고 있었습니다. 코드를 고치기 전에
기준을 다시 확인했습니다.

## 설치

gzip -dc ptium-1.5.3.tar.gz | docker load
