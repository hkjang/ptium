# Ptium v1.45.0

**모델이 사용자 템플릿의 세로쓰기 레이아웃을 매번 골랐습니다.**

## 1.44.0으로 모델 경로가 열리자 보인 것

키 없는 자체 호스팅 모델이 붙자, 이제야 **모델이 쓴 덱을 사용자의 실제 템플릿에**
넣고 잴 수 있게 됐습니다. 같은 브리프로 네 번 생성한 결과:

```
슬라이드 3: 현황: 오라클 라이선스 비용의 지속적 부담   layoutId=vertical-text
  outside   본문이 슬라이드 밖으로 3.11cm 넘어감
  collision 본문이 제목을 55% 덮음
```

전통 CJK 세로쓰기용 레이아웃입니다. **가장 많은 줄을 담을 수 있어서**, 용량으로
고르면 반드시 걸립니다. 자동 선택은 이미 이 레이아웃을 맨 뒤로 미루고 있었지만,
**레이아웃을 이름으로 고르는 모델에게는 아무도 말해 주지 않았습니다.**

## 한 줄로 고쳤습니다

레이아웃 목록에 그 레이아웃이 무엇인지 적었습니다:

```
- id=vertical-text role=content name="VERTICAL" slots: title(...) body(...) (vertical CJK typesetting — not for ordinary bullets)
```

사용자의 실제 템플릿으로 각각 네 번씩, 같은 브리프로 잰 결과:

| | 세로쓰기 레이아웃 사용 | 밖으로 넘침 | 겹침 | 점수 |
| --- | --- | --- | --- | --- |
| 1.44.0 | **4/4** | 6건 | **8건** | 81 · 74 · 88 · 72 |
| 1.45.0 | **0/4** | 1건 | **0건** | 95 · 97 · 94 · 83 |

레이아웃 이름이 무엇이든 **본문 자리표시자가 세로로 놓여 있으면** 세로쓰기로 봅니다.
그림 자리표시자에 붙은 표시는 글이 아니므로 세지 않습니다.

## 함께 넣었지만 효과를 재지 못한 것

모델이 2026년 목표를 받고도 `2024 Q4: 설계 및 PoC 완료` 같이 **이미 지난 날짜로
로드맵을 시작**하는 일이 있었습니다. 프롬프트에 "계획은 오늘부터 앞으로 간다"는
규칙을 넣었습니다.

다만 **효과를 입증하지 못했습니다.** 3회씩 재 봤을 때 지난 날짜가 나온 덱은 양쪽 모두
1/3이었고, 점수 분포도 같았습니다(87·78·83 대 87·83·78). 규칙 자체는 사실이고
비용도 없어 남겨 두지만, 이 릴리스가 개선했다고 말할 수 있는 것은 세로쓰기 쪽입니다.
