# Ptium v0.51.0

지난 판에 넣은 테스트 위에서 편집기를 계속 나눕니다.

## 대화상자 두 개가 자기 파일로

`EditorPage.tsx` 안에 있던 **측정 결과**와 **덱에 명령하기**를 컴포넌트로 꺼냈습니다.

```
web/src/pages/editor/
  ├─ QualityDialog.tsx      점수 · 가장 낮은 슬라이드 · 발견된 것과 그 수정
  ├─ QualityDialog.test.tsx
  ├─ CommandDialog.tsx      읽은 문장을 먼저 보여 주고, 그다음 적용
  └─ CommandDialog.test.tsx
```

76KB → **72KB**. 그리고 이제 두 화면이 **jsdom에서 실제로 렌더링되며** 테스트됩니다 — 브라우저를
띄우지 않고도, 계획 없이는 적용 버튼이 없다는 것과 점수 축 다섯 개가 모두 보인다는 것을 확인합니다.

## 브라우저 확인에서 또 하나 잡혔습니다

새 대화상자를 실제 편집기에서 열어 보니 이렇게 나왔습니다.

```
숫자의 출처 없음
figures with no source: nothing on this slide says where its numbers came from
```

v0.46에서 **측정 항목을 추가하면서 번역 규칙은 만들지 않았습니다.** 이름은 한국어인데 설명은
서버의 영어 그대로였습니다.

규칙을 넣고, **다음에 같은 일이 생기지 않도록 테스트를 하나 더 걸었습니다**: 서버가 내는 아홉
가지 측정 종류의 실제 문장을 모두 번역해 보고, **알파벳 세 글자 이상이 남으면 실패**합니다
(색상 코드와 `!source` 같은 문법은 제외). 다음에 측정 항목을 추가하면 규칙을 잊는 순간
`npm test` 가 잡습니다.

## 확인

- 유닛·컴포넌트 테스트 18건: 번역 규칙 9종 전수 + 규칙 없는 문장은 그대로, 측정 종류·점수
  축·체크포인트 이름, 슬라이드-슬롯 관계 4가지, 명령 대화상자 4가지(계획 없이는 적용 불가,
  Enter의 두 단계, 빈 문장 거절, 계획 표시), 측정 대화상자 5가지.
- 브라우저: 명령 → 계획 → 적용(5장 → 4장)과 측정 대화상자 표시, 콘솔 오류 0.
- 전수 점검: api 87 · edges 32 · package 0 실패.
