# 1.69.1 — 사용자 화면도 서버에 물어봅니다

앞 화면 다음은 사용자 관리 화면이었습니다. 같은 모양입니다: **계정을 전부
가져와서 브라우저에서 거르고 있었습니다.**

계정이 1,116개인 배포에서 잰 값입니다.

| | 고치기 전 | 고친 뒤 |
| --- | --- | --- |
| 화면이 뜨기까지 | 506ms | **371ms** |
| API 요청 (전체) | 15건 | **5건** |
| 그중 `/admin/users` | **12건** | 1건 |
| 표에 그려진 줄 | **1,116줄** | 50줄 |

아직 느리지는 않았습니다. 다만 계정이 늘면 요청도 줄도 같이 늘어납니다.
10,000개면 요청 100번에 줄 10,000개입니다.

이 제품은 덱 목록에 대해 이미 같은 판단을 내려 두었습니다 — *덱 600개짜리
서재에는 한 페이지와, 서버에 물어보는 검색창이 필요하다.* 사용자 화면에도 같은
것을 했습니다.

- 이름·이메일 검색, **역할**, **상태** 를 서버가 거릅니다 (역할·상태는 이번에
  서버에 새로 넣었습니다)
- 표는 50명씩, 이전·다음으로 넘깁니다
- 위의 카드 넷은 **전체 계정**을 셉니다. 보고 있는 페이지가 아니라 원래
  그 뜻이었습니다
- 검색어를 한 글자 칠 때마다 요청하지 않습니다

## 덤으로

지난 판에서 쓰던 `api.presentations()` — 계정의 덱을 전부 가져오던 함수 — 는
이제 부르는 곳이 없습니다.

그리고 새 경로를 문서에 적기 전에 **또 시험이 먼저 잡았습니다.**

## 확인

- 브라우저에서 검색·역할·상태·페이지 넘김을 모두 눌러 서버가 답한 수와 화면에
  그려진 줄이 맞는 것을 확인했습니다.
- 스윕에서 `role=admin` 과 `status=active` 의 총계가 카드의 숫자와 같은지
  확인합니다.
