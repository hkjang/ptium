# Ptium v1.45.1

**모델에게 말해 주는 것으로는 부족했습니다.**

## 1.45.0을 확인해 보니

레이아웃 목록에 "이건 세로쓰기용"이라고 적은 뒤 배포 이미지로 다시 재 봤습니다.
4/4에서 **1/3**로 줄었습니다 — 크게 나아졌지만 **없어지지는 않았습니다.** 모델이
가끔 그냥 무시합니다.

## 알고 있으면서 버리고 있었습니다

레이아웃을 **찾는** 쪽은 이미 알고 있었습니다:

```go
// A layout nobody would pick on purpose does not win on capacity.
score -= float64(layout.PreferenceRank()) * 5
```

그런데 **모델이 지정한 레이아웃을 바꿀지 판단하는** 비교는 양쪽 모두 이 감점 없이
날 것의 적합도로 쟀습니다. 세로쓰기 레이아웃은 어느 레이아웃보다 많은 줄을 담으므로
적합도만 보면 **항상 이깁니다.** 그래서 모델이 지정하면 그대로 남았습니다.

이제 양쪽을 **찾을 때와 같은 방식으로** 잽니다. 판단이 모델의 협조에 기대지 않습니다.

## 작성자의 선택은 그대로입니다

원문에 직접 `@layout` 을 적은 것은 제안이 아니라 결정입니다. 그건 예전처럼 그대로
쓰이고, 바뀌는 것은 모델이 고른 것뿐입니다. 바뀌면 덱이 그 사실을 기록합니다 —
`layout "VERTICAL" cannot hold this slide; used "OBJECT" instead`.
