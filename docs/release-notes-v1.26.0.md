# Ptium v1.26.0

지난 판에서 **개인화 화면이 아무도 고르지 않은 색을 저장하던 것**을 고쳤습니다.
같은 화면의 바로 위 칸 — **기본 테마** — 을 이어서 봤습니다.

## 화면은 이 제품이 예전에 갖고 있던 네 개를 보여 주고 있었습니다

이 배포가 갖고 있는 디자인은 **50개(10계열 × 5)** 입니다. 그런데 개인화 화면과 관리자
설정 화면이 고를 수 있게 내놓은 것은 `aurora · paper · mint · graphite` **네 개**였고,
이 넷 중 **디자인 키인 것은 하나도 없습니다.** 지금 배포의 기본값인 `slate-classic`은
목록에 없어서, 화면에서는 이렇게 보였습니다 —

```
개인화 · 기본 테마    네 개 중 아무것도 선택되어 있지 않음
관리자 · 기본 테마    "Aurora"          ← 실제 저장된 값은 slate-classic
```

관리자는 **자기 배포의 기본 디자인을 화면에서 볼 수 없었고**, 나머지 46개는 두 화면
어디에서도 고를 수 없었습니다.

## 저장된 값이 실제로 어떤 디자인인지도 화면마다 달랐습니다

서버는 예전 이름을 지금 디자인으로 바꿔 읽습니다 — `aurora`는 Plum Rail,
`graphite`는 계열 이름이라 Graphite Minimal입니다. 생성 화면은 그 규칙을 몰라서
**목록에서 맨 앞에 있던 디자인**을 골랐습니다.

```
저장된 값 'aurora'    서버: Plum Rail        생성 화면: Plum Wash   ← 다른 디자인
저장된 값 'graphite'  서버: Graphite Minimal 생성 화면: Plum Wash
```

## 세 화면이 서버와 같은 답을 합니다

개인화 · 관리자 설정 · 생성 화면이 모두 **이 배포가 갖고 있는 50개**를 계열별로 묶어
보여 주고, 저장된 값을 **서버와 같은 규칙**으로 읽습니다.

```
저장된 값 'crimson-panel' → 세 화면 모두 Ptium Crimson Panel
저장된 값 'aurora'        → 세 화면 모두 Ptium Plum Rail
저장된 값 'graphite'      → 세 화면 모두 Ptium Graphite Minimal
저장된 값 없음            → 세 화면 모두 Ptium Slate Classic
```

개인화 화면은 고른 디자인의 **표지를 실제로 그려서** 함께 보여 줍니다. 화면이 색을
따로 갖고 있지 않습니다 — 그리는 것은 그 디자인 자신입니다.

## 순서를 답에 담았습니다

계열 이름 하나(`graphite`)가 어느 디자인이 되는지, 이 제품에 없는 값이 어디로
떨어지는지는 **라이브러리 자신의 순서**가 정합니다. 이름순으로 정렬된 목록으로는
같은 답이 나오지 않습니다. 그래서 템플릿 목록이 내장 디자인마다
**`designRank`** 를 함께 답합니다.

## 검사

- 화면 훑기: 디자인 선택이 이 배포의 50개를 모두 내놓는지, 개인화 화면과 생성 화면이
  **같은 디자인 이름**을 말하는지. 되돌려서 둘 다 실제로 잡는지 확인했습니다
  (`2 failures`).
- 저장된 값이 어떤 디자인을 고르는지 서버에서 고정했고, 웹이 갖고 있는 예전 이름 표가
  서버와 어긋나면 테스트가 실패합니다.

전체 Go 테스트 · 웹 127개 · REST 557개 · deep · edges 전부 0 failures.
