# Ptium v1.55.1

**시간을 완벽하게 지키는 발표자에게 화면이 계속 "늦음"이라고 말했습니다.**

## 발표자 보기의 페이스 표시

발표자 창은 목표 시간을 받아 지금 늦었는지 일렀는지를 말해 줍니다. 그 계산은
이랬습니다.

```js
spent - (index / total) * target * 60
```

`index`는 **지금 서 있는 슬라이드의 시작**입니다. 그런데 슬라이드는 한 순간이
아니라 발표자가 그 안에 머무는 **구간**입니다.

## 완벽한 발표를 시뮬레이션했습니다

10장, 20분, 장마다 정확히 2분. 4번 장에 머무는 2분 동안 화면이 한 말입니다.

```
경과       슬라이드   지금 규칙      고친 뒤
 6분00초    4        예정대로       1분 이름
 6분45초    4        1분 늦음       예정대로
 7분30초    4        2분 늦음       예정대로
 7분45초    4        2분 늦음       1분 늦음
 8분00초    5        예정대로       1분 이름
```

한 장에 머무는 동안 **점점 더 늦어지다가**, 화살표를 누르는 순간 **예정대로로
되돌아갑니다.** 발표자의 속도에 대해 새로 알게 된 것은 아무것도 없는데도 말입니다.

20분짜리 완벽한 발표 전체로 보면:

```
지금 규칙   '예정대로'라고 말하는 시간 38%   범위 0초 ~ +119초   한 번도 '이름'이라 하지 않음
고친 뒤     '예정대로'라고 말하는 시간 74%   범위 -60초 ~ +59초  좌우 대칭
```

**한 번도 "이름"이라고 말하지 않는다**는 것이 이 계산이 한쪽으로 기울어 있다는
증거입니다. 발표자는 있지도 않은 지각을 보고 필요 없이 서두르게 됩니다.

## 고친 것

일정을 슬라이드의 **시작**이 아니라 **가운데**에서 읽습니다.

```js
spent - ((index + 0.5) / total) * target * 60
```

10장 20분짜리 발표는 **9분에 5번 장의 절반**에 있어야 합니다. 그 자리에서 이 값은
정확히 0이 되고, 장의 시작에서는 1분 이름, 끝에서는 1분 늦음으로 좌우가 맞습니다.

계산은 `pacingSeconds()`로 꺼내 두었습니다. 발표 중에만 보이는 숫자는 그때 눈으로
확인할 수 없기 때문입니다.

  걸린 전체 화면(1.73배)보다 오히려 촘촘합니다
