# Ptium v0.92.0

지난 판에서 이렇게 썼습니다.

> 라벨은 저자의 글이라 줄이지 않고 **지적합니다** — 수리 패스가 더 짧은 문장을 요청합니다.

**그 주장을 확인해 봤습니다.** 지적은 수리 패스까지 도달했고, 패스는 다시 쓰기를 요청했고,
실제 모델은 라벨을 짧게 고쳐 보냈고, 지적은 사라졌습니다.

그런데 **두 가지가 같이 딸려 왔습니다.**

## 다시 쓴 슬라이드가 단 하나를 지웠습니다

원래 슬라이드는 두 단이었습니다 — `준비된 것` 과 `남은 것`. 돌아온 답에는 **한 단만** 있었고
다른 단의 머리말은 그냥 없었습니다.

그런데 **채택됐습니다.** 채택 기준이 "재 봐서 나아졌는가" 뿐이었고, **뭔가를 지우면 언제나
나아지기** 때문입니다.

**단어가 줄어드는 건 다시 쓰기의 목적입니다. 머리말이 사라지고 영역이 비는 건 아닙니다.**
머리말 수나 내용이 든 영역 수가 줄어든 제안은 **거절** 하고 슬라이드를 원래대로 둡니다. 줄을
짧게 고치거나 두 줄을 하나로 합치는 것은 그대로 통과합니다 — 그게 원래 원하던 것입니다.

## 다시 쓴 슬라이드가 출처를 지어냈습니다

```
!source 내부 시스템 대장 | 2026-03
```

브리프에 그런 것은 없습니다. v0.75 부터 **생성** 을 지키던 필터가 **다시 쓰기에는 한 번도
적용된 적이 없었습니다** — 생성이 지키지 않는 문이었습니다. 이제 같은 필터를 지납니다. 같은
실행을 다시 돌리니 깨끗하게 나옵니다.

## 편집기의 "다시 쓰기" 버튼은 다릅니다

거기서는 **저자가 결과를 보고** 채택할지 정합니다. 그래서 모델이 준 것을 그대로 보여 줍니다.
거절은 **혼자 판단하는 패스** 의 몫입니다.

## 설치

오프라인 설치 방법은 [docs/offline-deployment.md](offline-deployment.md) 를 보세요. 이미지에
Postgres 와 nginx 는 들어 있지 않습니다 — 배포할 때 `DATABASE_URL` 로 DSN 을 지정합니다.
