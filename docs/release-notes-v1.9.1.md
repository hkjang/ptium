# Ptium v1.9.1

편집기의 두 가지를 고쳤습니다. **원인은 하나였습니다.**

## 50장짜리 덱에서 슬라이드 목록이 스크롤되지 않았습니다

슬라이드 목록도, 가운데 캔버스도, 오른쪽 속성 패널도 **스크롤되지 않았습니다.** 첫 화면 밖의
내용은 잘려서 **닿을 수 없었습니다.**

측정한 값입니다. 900px 창에서:

| | 실제 높이 | 스크롤 |
|---|---|---|
| 슬라이드 목록 | **7,111px** | 안 됨 |
| 캔버스 (200% 확대) | **7,063px** | 안 됨 |
| 속성 패널 | **7,211px** | 안 됨 |

세 영역 모두 그리드 칸 안에 있는데, **그리드 항목의 기본값이 `min-height:auto`** 입니다. 안의
내용만큼 늘어난다는 뜻이고, 그러면 안쪽의 `overflow:auto` 는 **넘칠 것이 없으니 영원히 스크롤
막대를 만들지 않습니다.** 바깥은 `overflow:hidden` 이라 늘어난 부분은 그냥 잘립니다.

세 칸에 `min-height:0` 을 넣었습니다. 같은 창에서:

| | 보이는 높이 | 담고 있는 높이 | 스크롤 |
|---|---|---|---|
| 슬라이드 목록 | 742px | 7,111px | **됨** |
| 캔버스 (200%) | 594px | 904px | **됨 (좌우도)** |

**200% 확대한 슬라이드의 오른쪽 아래까지 닿습니다.** 확대는 되는데 확대한 곳을 볼 수 없던
상태였습니다.

덤으로, 슬라이드를 바꾸면 **그 썸네일이 보이도록 목록이 따라갑니다.** 이미 보이는 것은
움직이지 않습니다.

## "저장됨"이 오른쪽 버튼과 붙어 있었습니다

헤더가 `1fr auto 1fr` 그리드였습니다. 가운데 칸은 내용만큼만 넓어지고, 오른쪽 버튼 묶음이 자기
몫보다 넓어지면 **왼쪽으로 넘쳐 나와 저장 상태 위에 그려졌습니다.** 1440px에서는 정확히
**0px** — 딱 맞닿아 있었습니다.

가로 한 줄(flex)로 바꿨습니다. 줄어들 수 있는 항목은 **덱 제목** 하나로 정해 두었으므로, 좁아지면
제목이 먼저 줄고 나머지는 서로 밀어냅니다. 겹칠 수가 없습니다. 이제 어느 너비에서나
**14px 간격**이 유지됩니다.

또, 넘쳐서 잘리는 위치에서 가운데 정렬을 하면 위쪽 절반은 스크롤로도 닿을 수 없습니다.
캔버스 무대는 `safe center` 로 바꿔, 내용이 더 클 때는 위에서부터 보이게 했습니다.

## 다시는 이렇게 안 되도록

브라우저 검사에 넣었습니다 — **창보다 키가 큰 영역이 있으면 실패** 합니다. 고친 것을 되돌리고
돌려 보니 슬라이드 목록·캔버스·속성 패널 **세 곳을 정확히 짚어** 실패했습니다.
