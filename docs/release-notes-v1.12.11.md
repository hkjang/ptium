# Ptium v1.12.11

브라우저에 실제로 그려진 글자를 세어 봤습니다. 열여섯 낱말짜리 제목을 쓰면 **여덟 낱말만
그려지고, 품질 패널은 "결함 0" 이라고 말했습니다.**

## 재 본 방법

미리보기 SVG 를 크로미움에 그려 넣고 글자 상자를 하나씩 읽었습니다. 슬라이드 밖으로 나간
글자도, 서로 겹친 글자도 44 장에서 **하나도 없었습니다** — 그리기는 건전합니다. 그래서
반대쪽을 물었습니다: **넘치지 않는 이유가 잘려서는 아닌가.**

낱말마다 고유한 글(`항목01가나 항목02가나 …`)로 다시 재니 답이 나왔습니다:

```
낱말 16개 제목 → 8개 사라짐,  findings=[]
낱말 30개 제목 → 22개 사라짐, findings=[]
```

## 왜 조용했나

맞추기(fitter)는 자를 때 **자른 자리를 표시**하고(`…`), 무엇을 잘랐는지 보고서로 돌려줍니다.
본문 요점 경로는 그 보고서를 받아 경고를 냅니다. 그런데 **제목과 리드 경로는 보고하지 않는
쪽 함수를 쓰고 있었습니다.** 잘랐다는 것을 컴파일러는 알고 있었고, 아무에게도 말하지
않았을 뿐입니다.

## 이제

- 제목과 리드가 잘리면 적용 응답의 경고에 나옵니다 —
  `"line 1 (slide 1): 1 line(s) were shortened to fit title"`
- **검사기도 말합니다.** 소스를 거치지 않고 워크스페이스에서 편집하는 사람은 적용 응답을
  볼 일이 없으므로, 잘림 표시(`…`)를 검사기가 읽어 `trimmed` 권고로 올립니다
- 들어맞는 제목은 양쪽 모두 조용합니다

## 확인

- 손실이 있는 네 경우 모두 `trimmed` 가 뜨고, 손실 없는 네 경우는 조용합니다
- 두 수정을 각각 되돌려 테스트가 무는지 확인했습니다. 처음 쓴 검사기 테스트는 **연결을
  건너뛰고** 함수를 직접 불러서 되돌려도 통과했습니다 — `InspectDeck` 을 지나가게 고쳤습니다
- 기존 덱 35 개 재측정: 결함 0, 권고 104 — 새 권고가 붙은 덱은 없습니다
- 스윕이 양쪽을 지킵니다 (216 checks)

## 설치

```bash
gzip -dc ptium-1.12.11.tar.gz | docker load
```
