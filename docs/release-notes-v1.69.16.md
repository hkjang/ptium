# Ptium 1.69.16

## 엑셀이 저장하는 그대로의 파일을 읽지 못했습니다

한국어 엑셀은 인코딩 메뉴를 따로 열지 않는 한 CSV 를 **CP949** 로 저장합니다.
그렇게 저장한 파일을 올리면 아무 설명 없는 **서버 오류**로 끝났습니다.

글자 파일은 자기가 무엇으로 쓰였는지 말해 주지 않습니다. 그런데 읽는 쪽은 언제나
UTF-8 이라고 여기고 바이트를 그대로 흘려보냈고, 데이터베이스가 거절하면서
`invalid byte sequence for encoding "UTF8": 0xc7` 로 요청이 끝났습니다. 같은 대화
상자가 제안하는 UTF-16 도 마찬가지였습니다(`0xff`).

이제 `.csv` · `.tsv` · `.md` · `.txt` 는 문서로 읽기 전에 **글자로** 먼저 읽습니다.

- 바이트 순서 표시(BOM)가 있으면 그 말을 따릅니다 — UTF-8, UTF-16 LE, UTF-16 BE
- 없으면 UTF-8 로 읽어 보고
- 그것도 아니면 CP949 로 읽습니다 (EUC-KR 을 포함합니다)
- 어느 쪽으로도 글자가 아니면, 무엇을 하라는 말과 함께 거절합니다

`golang.org/x/text` 는 이미 쓰고 있던 의존성이라 오프라인 빌드에 새로 받아 올 것이
없습니다. `go.sum` 은 그대로입니다.

## 지키는 장치

- `internal/docs/textbytes_test.go` 가 다섯 가지 인코딩으로 같은 표를 읽어 결과가
  같은지 봅니다. CP949 로 쓴 바이트가 **UTF-8 로는 읽히지 않는다는 것**을 먼저
  확인하므로, 같은 표를 오갔을 뿐인 검사가 되지 않습니다.
- `scripts/e2e/api.py` 가 CP949 로 쓴 표를 실제로 올려 낱말이 살아 오는지 봅니다.

되돌려 돌리면 두 검사 모두 실패합니다.

## 확인만 하고 고치지 않은 것

가져오기가 이미 제대로 답하던 것들입니다.

- 빈 파일 → `올린 파일이 비어 있습니다` (400)
- 공백만 있는 파일 → `이 문서에서 슬라이드로 만들 내용을 찾지 못했습니다` (422)
- UTF-8 BOM, CRLF 줄바꿈 → 그대로 잘 읽습니다
