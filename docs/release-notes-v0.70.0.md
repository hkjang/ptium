# Ptium v0.70.0

지난 판에 이어, 모델이 쓴 덱에서 본 마지막 하나를 고쳤습니다.

## "성장 채널 | 위축 채널" 이 글자 그대로 찍혀 있었습니다

비교 슬라이드는 두 쪽의 이름을 이렇게 씁니다.

```
# 채널별 실적 분화
@comparison
> 성장 채널 | 위축 채널
- 직영 채널은 468억 원으로 11.4% 성장하며…
- 온라인 채널은 212억 원으로 28.5% 급성장하며…
- 대리점 채널은 287억 원으로 7.4% 감소하며…
- 대리점 마진율 하락과 가격 경쟁력 약화로…
```

세로줄은 이 언어에서 **행을 나누는 기호**입니다 — 표에서도, KPI에서도, 비교 컴포넌트에서도.
그런데 리드에 쓰면 그대로 한 줄로 찍혔습니다. 왼쪽 칸 위에 `성장 채널 | 위축 채널` 이 놓이고,
오른쪽 칸은 이름 없이 남습니다.

이제 **두 칸짜리 슬라이드에서 세로줄이 든 리드는 두 쪽의 이름**입니다. 각 이름이 자기 쪽 위에
서고, 요점은 반씩 나뉩니다. 그려서 확인했습니다.

**문장은 자르지 않습니다.** 칸 제목은 이름이지 문장이 아니므로 **세 단어까지**로 봅니다.
`매출과 비용을 같은 기준으로 | 분기별로 나누어 자세히 살펴봅니다` 는 누군가 쓴 문장이고,
반으로 자르면 그 사람의 문장을 자르는 것입니다. 그대로 둡니다.

## 지도를 순서대로 걷습니다

고치는 도중에 **왕복이 흔들리는 것**을 발견했습니다. 두 칸이 각자 제목을 가진 슬라이드를 다시
쓸 때, 코드가 **맵을 순회해** 둘 중 아무 제목이나 슬라이드의 리드로 뽑았습니다. 그래서 한 번
쓸 때와 다음에 쓸 때 두 제목의 자리가 바뀌었습니다.

Go에서 맵 순회 순서는 매번 다릅니다. 같은 덱이 같은 글로 나오지 않는 것은 왕복이 아닙니다.
이제 정해진 순서로 걷습니다.

## 확인

- Go 전 패키지 통과. 두 쪽 이름 · 문장은 자르지 않음 · 왕복 안정성을 각각 확인합니다.
- 모델이 쓴 그 슬라이드를 다시 그려 **눈으로** 확인했습니다.
- api 87 · edges 32 · package · flows · ui 0 실패.
