# Ptium v1.20.0

## 품질 점수가 100점인데 제목이 말이 안 됐습니다

지난 판에서 고친 것들 — `…개선하려고`, `회사 소개 어줘`, `AI 챗봇 도입 검토 서` — 은 전부
**품질 점수 98~100점짜리 덱**에 있었습니다.

측정하던 것을 다시 보면 이유가 분명합니다. 넘침, 겹침, 대비, 여백, 잘림, 출처, 반복 —
**전부 "어떻게 그려졌는가"** 입니다. **"뭐라고 쓰여 있는가"를 보는 것은 하나도 없었습니다.**

그래서 제품이 자기가 만든 문장을 읽지 못했습니다. **읽는 사람이 가장 먼저 보는 한 줄**인데도요.

## 제목이 문장인지 봅니다

이제 검사가 이런 제목을 잡습니다.

| 제목 | 왜 |
| --- | --- |
| 협력사 정산 프로세스를 **개선하려고** | 하려던 일만 있고 문장이 끝나지 않음 |
| 새로 **만들려고 하는데** | 〃 |
| 회사 소개 자료 **만들어줘** | 부탁하는 말이 제목에 들어옴 |
| 고객 이탈률 개선**을 위한** | 꾸밀 명사를 기다리는 채로 끝남 |
| 2026년 계획**을** | 조사가 뒤를 기다림 |
| Plan **for the** | 〃 (영어) |

이런 것은 잡지 않습니다 — `매출이 12% 늘었습니다`(한 문장짜리 헤드라인은 흔한 표현),
`AI 챗봇 도입 검토 보고서`, `결정이 필요한 사항`, `매출을`(한 단어짜리 제목은 이름이 서툴 뿐
끊긴 것은 아닙니다).

편집기 품질 패널에는 **"제목이 문장 중간에서 끊김"** 으로 나오고, 무엇이 문제인지와
**브리프의 부탁하는 말이 섞였을 수 있다**는 것까지 한국어로 말합니다.

## 되돌려 확인했습니다

지난 판의 고침 하나를 되돌리자, **이번 검사가 그 덱을 세 곳에서 잡았습니다.** 어제는 사람이
읽어야만 알 수 있던 것을, 이제 제품이 스스로 말합니다.

## 덤: API 문서가 검사 종류를 절반만 적고 있었습니다

스키마의 목록은 **7가지**, 서버가 내보내는 것은 **13가지**였습니다. 스키마대로 검증하는
클라이언트라면 멀쩡한 응답을 거절합니다 — 빠져 있던 것들이 하필 **글에 대한 검사들**
(반복 · 앞 장과 같음 · 출처 없음 · 일부 안 그려짐 · 링크)이었습니다.

전부 채우고, **검사 종류를 추가하고 문서를 고치지 않으면 실패하는 검사**를 넣었습니다.
