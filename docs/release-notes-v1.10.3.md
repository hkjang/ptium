# Ptium v1.10.3

v1.10.0 에서 적어 둔 "아직 없는 것들" 중 세 번째, **링크** 입니다.

## 슬라이드 안의 링크

어느 줄에나 `[보이는 말](주소)` 로 씁니다. 리드 문장, 요점, 제목, 캔버스 텍스트 상자 —
글이 들어가는 곳이면 어디든 됩니다.

| 이렇게 쓰면 | 이렇게 갑니다 |
| --- | --- |
| `[안내 문서](https://docs.example.com/plan)` | 웹 |
| `[담당자](mailto:plan@example.com)` | 그 주소로 메일 쓰기 |
| `[부록](#7)` | 같은 덱의 7번 슬라이드 |

**내려받은 pptx 가 진짜 링크를 답니다.** PowerPoint 가 자기 하이퍼링크에 쓰는 것과 같은
표시라, 파워포인트·키노트에서 열어 눌러도, 구글 슬라이드로 가져가도 그대로 동작합니다.
같은 덱 안의 슬라이드로 가는 링크도 마찬가지입니다. 실제로 파워포인트 형식을 읽는
도구로 내보낸 파일을 열어 세 종류 모두 확인했습니다.

미리보기·썸네일·발표 화면에서는 **밑줄이 그어진 템플릿 자체의 링크 색** 으로 보입니다.
(브라우저 발표 화면은 슬라이드 그림이라 **누를 수는 없습니다.** 누르는 것은 내려받은
파일에서 됩니다.)

## 링크가 아닌 것은 손대지 않습니다

주소로 인정하는 것은 위의 세 가지뿐입니다. 나머지는 **쓴 그대로 둡니다** — 각주로 쓴
`[1](주석 3)` 은 계속 각주입니다.

대신 그 침묵이 반대로 위험한 경우가 있습니다. `[문서](www.example.com)` 처럼 **링크로
쓰려다 인정받지 못한 자리** 는 대괄호와 주소가 그대로 슬라이드에 그려지고, 화면에
띄우기 전에는 아무도 모릅니다. 그래서 측정에 새 항목을 넣었습니다 — **"링크로 인식되지
않음"**, 어떤 주소가 거절됐는지와 함께. 대괄호를 글자 그대로 쓰려면 `\[` 입니다.

## 표시를 어디에 둘지, 이번에도 같은 답이었습니다

링크를 슬라이드의 새 필드로 만들면 원본 코드·저장·복제·되돌리기·내보내기가 전부 그것을
알아야 합니다. 그래서 **글자 안에** 넣었습니다. 사이에 있는 어떤 손도 링크를 알 필요가
없습니다.

알아야 했던 곳은 두 군데뿐입니다.

- **측정.** `[분기 보고서](https://…?utm_source=…)` 는 화면에서는 다섯 글자, 덱에서는
  예순 글자입니다. 원본 글자로 재면 잘 그려지는 슬라이드를 "넘친다"고 판단해서 글씨를
  줄이거나 두 장으로 쪼갭니다. 그래서 재는 것은 **그려지는 말** 입니다 — 이 규칙은
  일부러 되돌려 테스트가 깨지는 것까지 확인했습니다(36줄 → 4줄).
- **그리기.** 문단을 런으로 쪼개서, 대괄호와 주소는 **어디에도 그려지지 않습니다.**

기존 덱 20,929장을 세어 `](` 가 들어간 슬라이드가 **0장** 인 것을 확인하고 이 문법을
골랐습니다. 이미 쓰고 있던 글이 갑자기 링크로 바뀌는 일은 없습니다.
