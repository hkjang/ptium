# Ptium v0.47.0

덱의 재료는 대개 덱보다 먼저 있습니다. 지난 분기 보고서는 `.docx`이고, 숫자는 `.xlsx`이고,
정리해 둔 메모는 마크다운입니다. 지금까지 Ptium은 그중 `.pptx` 하나만 읽었습니다. 나머지는
사람이 **다시 타이핑**해야 했고, 다시 타이핑하는 순간 가장 중요한 것이 사라졌습니다 —
그 숫자가 어디서 왔는지.

## 가지고 있는 문서로 만듭니다

**프레젠테이션 → 기존 자료 가져오기**가 이제 이것들을 읽습니다.

| 올리는 것 | 되는 것 |
| --- | --- |
| `.xlsx` · `.csv` · `.tsv` | 시트마다 한 장. 라벨 한 열 + 숫자 한 열이면 **차트**, 넓으면 **표** |
| `.docx` | 제목이 슬라이드, 그 아래 문장이 요점, 표는 표 |
| `.md` · `.txt` | `#` 이 슬라이드, `-` 이 요점, 파이프 표는 표 |
| `.pptx` · `.potx` | 지금까지처럼 덱으로 |

그리고 **각 장이 출처를 답니다.**

```
# 분기 실적
::columns 매출
- 1분기 | 1180
- 2분기 | 1240
::
!source 매출.xlsx | 분기 실적!A1:B3
```

v0.46에서 만든 근거 체계에 그대로 이어집니다 — 노트에 출처가 찍히고, 측정의 **근거** 축이
이 슬라이드를 문제 삼지 않습니다. 옮겨 적는 대신 **읽어 오면** 출처가 따라옵니다.

## 의존성은 늘리지 않았습니다

`.xlsx` 와 `.docx` 는 XML을 담은 zip입니다. Ptium은 이미 그런 파일을 **씁니다**(내보낸 차트마다
워크북이 들어갑니다). 읽는 것도 같은 표준 라이브러리로 됩니다 — 새 모듈 하나 없이.

`.pdf` 는 읽지 않습니다. PDF에서 글을 꺼내려면 폰트·인코딩·압축을 다루는 파서가 필요하고, 그
의존성은 **폐쇄망 배포의 단순함과 바꿀 만한 것이 아직 아닙니다.** 올리면 그렇게 말합니다:
`Ptium reads .pptx presentations and .xlsx, .csv, .docx and .md documents`.

## 크기와 정직함

문서는 덱의 재료이지 덱이 아닙니다. 백 줄짜리 시트를 한 장에 넣으면 그건 스프레드시트의
스크린샷입니다. 그래서 시트는 앞 8행 · 5열까지, 문서는 30장까지 가져오고 — **자른 것은 말합니다**:
`행이 많아 앞 8줄만 가져왔습니다`, `문서가 길어 N장은 가져오지 않았습니다. 나눠서 올리면 전부 가져옵니다`.

## 확인

- 회귀 테스트 6건: CSV가 차트가 되는 것, 넓은 표가 표가 되는 것, 마크다운·워드의 제목이
  슬라이드가 되는 것, 라이브러리 없이 통합 문서를 읽는 것, 그리고 **읽을 수 없는 파일이 그렇게
  말하는 것**.
- 전수 점검에 두 줄 추가: 스프레드시트를 올려 `::columns` 와 `!source` 가 들어갔는지, PDF가
  422로 거절되는지.
- 실측: `매출.csv` → 2장(표지 + 차트), `상반기 보고서.docx` → 3장, 각 장에 출처.
- 전수 점검: api 79 · edges 32 · package · deep 0 실패.
