# Ptium v0.44.0

이번에는 **자유 배치 캔버스**를 API로 직접 두드려 봤습니다 — 글상자, 도형, 선, 표, 회전, 투명도를
얹고 내보낸 파일과 미리보기를 나란히 놓고 비교했습니다.

대부분은 정확했습니다. 회전(`rot="900000"` = 15°), 투명도(`alpha 60000` / `opacity 0.6`), 겹침
순서, 표의 머리행, 화살표 — 미리보기와 파일이 같은 그림이었습니다. **정렬 하나만 빼고.**

## 가운데 맞춤이 조용히 왼쪽이 됐습니다

개체에 `align: "ctr"` 을 주면 — DrawingML이 쓰는 말이고, 작업 공간이 **템플릿 영역을 캔버스로
들어 올릴 때 실제로 다루는 말입니다** — 렌더러는 그것을 모르는 값으로 보고 **말없이 왼쪽 정렬**
했습니다. `verticalAlign: "ctr"` 도 마찬가지로 위쪽이 됐습니다.

두 가지를 고쳤습니다.

- **두 어휘를 모두 읽습니다.** 브라우저의 말(`center`·`right`·`middle`·`bottom`)과 DrawingML의
  말(`ctr`·`r`·`b`·`just`) 모두 같은 결과로 그려집니다. 미리보기와 파일 양쪽에서.
- **모르는 값은 거절합니다.** `align: "사선"` 은 이제 422와 함께 어느 개체인지 말합니다 —
  `freeform element 1 has an unsupported alignment`. 영역 스타일은 이미 그렇게 하고 있었고,
  캔버스 개체만 조용히 넘어가고 있었습니다.

조용히 다르게 그려지는 것이 이 제품에서 가장 나쁜 종류의 오류입니다. 화면에서 가운데로 맞춰
놓은 것이 파일에서 왼쪽에 있으면, 그건 미리보기가 아니라 짐작입니다.

## 확인

- 회귀 테스트 1건: 두 어휘가 같은 `anchor="ctr"`·`algn="ctr"` 로 나가고, 렌더러가 그릴 수 없는
  값은 알려진 정렬이 아니라는 것.
- API로 확인: `ctr/ctr` 200 · `center/middle` 200 · `사선` 422.
- 캔버스 왕복: 글상자·도형·선·타원(회전 15°, 투명도 60%)·표 5개 개체가 좌표·회전·투명도 그대로
  내보내집니다.
- 전수 점검: api 75 · edges 32 · package · deep 0 실패.
