# Ptium v1.59.2

**어제 고친 자리가 틀렸습니다. 그리고 같은 문제가 스무 곳 더 있었습니다.**

## 어제 제가 잘못 고쳤습니다

v1.59.1에서 공유 링크의 영어 문장 다섯 개를 **서버에서** 한국어로 바꿨습니다.
그런데 이 제품에는 이미 정해진 방식이 있었습니다. `web/src/api/errors.ts`의 첫
문단이 그렇게 적어 두었습니다.

> API는 영어로 답한다 — 그 문장은 요청 로그를 들여다보는 사람과 API를 쓰는 사람도
> 읽기 때문이다. 워크스페이스에 있는 사람은 그 언어를 고른 적이 없고, 그 문장은
> 토스트로 눈앞에 뜬다. 그래서 여기에 다시 적는다.

즉 **서버는 영어로 답하고 화면이 옮겨 적는 것**이 이 제품의 방식이었습니다. 어제
저는 서버를 한국어로 바꿔서, 문서화된 API 표면과 로그까지 함께 바꿔 버렸습니다.

진짜 결함은 다른 데 있었습니다. **공유 페이지만 그 번역층을 거치지 않고 있었습니다** —
19개 페이지가 쓰는데 이 한 장만 자기가 직접 `fetch` 하고 서버 문장을 그대로
띄웠습니다.

서버를 영어로 되돌리고, 공유 페이지가 다른 페이지들처럼 번역층에 묻도록 고쳤습니다.
이제 API는 영어로 답하고 읽는 사람은 한국어를 봅니다. **다섯 문장이 아니라 그
페이지가 만날 모든 문장이 고쳐집니다.**

## 그리고 나머지를 셌습니다

서버가 코드와 함께 내는 문장 96개 중 **옮겨지지 않은 것이 24개**였습니다. 그중 8개는
서버가 이미 한국어로 말하고 있었고, 나머지 16개가 영어로 화면에 떴습니다.

가장 흔한 것부터:

```
[ai_unavailable]  This deployment has no AI provider configured
```

**모델이 없는 오프라인 사이트에서는 덱을 만들려는 모든 시도가 여기서 끝납니다.**
그 사람이 보던 화면은 처음부터 끝까지 한국어입니다.

14개를 옮겨 적었습니다 — 모델 없음, 고쳐쓰기 실패, 읽을 수 없는 파일, 너무 긴 파일,
너무 큰 코드, 지원하지 않는 문서 형식, 사라진 이미지 원본, 로그인 시도 초과,
비밀번호 로그인 없음, 외부 인증 계정, API 키로 세션 열기, 이메일 중복, 큐 관련 둘.

남은 2개는 **OIDC 토큰 교환** 응답입니다. 화면이 아니라 인증 연동을 만드는 사람이
읽으므로 영어로 둡니다.

## 다시 어긋나지 않도록

`writeError`가 내는 문장을 전부 훑어 `errors.ts`에 규칙이 있는지 확인하는 검사를
넣었습니다. 두 파일이 따로 자라도 다음부터는 검사가 먼저 말합니다 — 24개를 전부
잡아냈을 검사입니다.
