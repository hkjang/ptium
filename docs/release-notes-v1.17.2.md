# Ptium v1.17.2

## 다시 쓰기가 끝나면 보던 자리에 그대로 있습니다

`AI로 다듬기` 를 누르면 끝난 뒤 **무조건 1번 슬라이드로 튀었습니다.**

이유는 이렇습니다. 다시 쓰기는 덱 전체를 새로 쓰고, **슬라이드 id 가 전부 새로 생깁니다.**
화면은 "보고 있던 id 가 아직 있으면 거기 머문다"는 규칙이었는데, 그 id 는 이제 없습니다.
그래서 맨 앞으로 갔습니다.

이제 **자리로 지킵니다**: id 가 살아 있으면 그 슬라이드에, 없으면 **그 자리를 물려받은
슬라이드**에 섭니다. 7번을 보고 있었으면 새 덱의 7번입니다. 덱이 짧아졌으면 마지막 장에
섭니다. 실제 모델로 6장짜리를 다시 써서 4번에서 4번으로 돌아오는 것을 확인했습니다.

같은 규칙이 저장·템플릿 교체 뒤에도 적용됩니다 — 슬라이드가 다시 컴파일되며 id 가 바뀌는
경우가 그쪽에도 있습니다.

## 카드보다 긴 숫자를 옆 칸 위에 그리지 않습니다

영어 브리프로 실제 모델을 돌려 나온 덱을 읽다가 찾았습니다. 모델이 `인력` 항목의 값으로
숫자가 아니라 문장을 적었습니다 — `12 staff redeployed`. 지표 카드의 숫자는 카드에 맞춰
작아지되 **라벨 크기 아래로는 줄이지 않는데**(그 아래로 가면 숫자가 주인공이 아니게 됩니다),
그래서 **옆 칸을 가로질러 0.6cm 삐져나가** 그려졌습니다.

이제 그 자리에서 자르고, **무엇을 잘랐는지 품질 패널이 말합니다**:
`지표 컴포넌트가 "12 staff…"를 잘라서 넣었습니다`. 보통 지표(`42개`, `18억`)는 그대로입니다.

## 검사

- 자리 지키기: id 가 전부 바뀌어도 같은 자리, 덱이 짧아지면 마지막 장, 근거가 없으면
  첫 장 (단위 검사 4개, 되돌리면 실패)
- 긴 숫자: 좁은 카드에서 결함 0 이고 잘렸다는 안내가 있어야 하며, 보통 지표는 아무 말도
  없어야 합니다 (458 checks)
