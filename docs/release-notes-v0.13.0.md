# Ptium v0.13.0

생성이 끝난 덱을 여는 화면을 바로잡았습니다. 그 과정에서 편집기가 조용히 디자인을 지우고
있었다는 사실을 발견해 함께 고쳤습니다.

## 편집기가 컴포넌트를 지우던 문제

편집기는 텍스트만 알고 있었습니다. 슬라이드를 저장할 때 방금 편집한 필드로 내용 전체를
교체했으므로, 생성된 덱에서 **제목 한 글자만 고쳐도 모든 슬라이드의 핵심 지표·타임라인·비교
표·이미지가 사라졌습니다.** 자동 저장이 걸려 있어 사용자가 알아채기도 어려웠습니다.

- `blocks`·`images`를 언급하지 않은 수정은 저장된 그림을 그대로 유지합니다. 텍스트만 아는
  클라이언트(편집기든, 컴포넌트가 생기기 전에 작성된 API 호출이든)가 덱을 망가뜨릴 수 없습니다.
- 지우는 것은 여전히 가능합니다. `"blocks": {}`를 명시적으로 보내면 비웁니다.
- 편집기도 그림을 그대로 되돌려 보냅니다. 편집 전후 내용을 바이트 단위로 비교해 확인했습니다.

## 보이는 것이 실제 슬라이드입니다

지금까지 편집 화면은 슬라이드를 **흉내낸 HTML**이었습니다. 제목, 텍스트 영역, 색 막대. 본문이
컴포넌트인 슬라이드에서는 텍스트 영역이 그냥 비어 있어서 "이 슬라이드엔 아무것도 없다"처럼
보였고, 거기에 글을 쓰면 실제로 그렇게 되었습니다.

- 왼쪽 슬라이드 목록, 편집 화면 옆의 큰 그림, 발표 모드 모두 **서버가 실제 템플릿으로 그린
  슬라이드**입니다. 내보내는 파일과 같은 렌더러를 씁니다.
- 각 슬라이드가 담고 있는 것을 이름으로 보여줍니다 — 핵심 지표, 타임라인, 비교, 표, 격자,
  이미지. 컴포넌트는 텍스트로 고칠 수 없으므로 **코드** 탭으로 안내하고, 제목·리드·본문을
  고쳐도 지워지지 않는다고 화면에서 밝힙니다.
- 본문은 그림이 차지하지 않은 영역에 씁니다. 컴포넌트가 있는 슬롯에 글을 밀어 넣어 둘 중
  하나를 잃는 일이 없습니다.

## 덱의 상태를 주장하지 않고 측정해서 보여줍니다

헤더의 표시는 저장된 덱을 실제로 측정한 결과입니다. 결함 0이면 "결함 없음", 아니면 개수가
보이고, 눌러서 어느 슬라이드의 무엇이 문제인지 확인한 뒤 바로 그 슬라이드로 이동합니다.
저장하거나 코드를 적용할 때마다 다시 측정합니다.

## 발표 모드

- ← → PageUp/PageDown, 스페이스로 넘기고 Home/End로 처음과 끝, ESC로 닫습니다.
- 발표 노트가 슬라이드 아래에 함께 나옵니다.
- 모든 대화상자가 ESC로 닫힙니다. 지금까지는 닫히지 않아 멈춘 것처럼 보였습니다.

## 버전 정보

계정 메뉴 아래에 실행 중인 빌드 버전이 표시됩니다(`GET /api/v1/settings`의
`service.version`). 오류를 알릴 때 이 값을 함께 전달하면 어느 릴리스인지 바로 확인됩니다.
릴리스가 아닌 빌드는 "개발 빌드"라고 표시합니다.
