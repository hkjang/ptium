# Ptium v0.9.0

조직이 자기 표를 정의해서 쓸 수 있습니다. 선택지 세 가지 중 **선언적 격자**로 진행한
결과입니다.

## 격자 컴포넌트

RACI 차트, 위험 매트릭스, 준비 상태 점검표는 모두 격자입니다 — 이름 붙은 열, 이름 붙은
행, 그리고 짧은 값이나 표식이 들어가는 칸. 그래서 조직마다 컴포넌트를 추가하는 대신
격자를 **데이터로 정의**하고 하나의 렌더러가 그립니다.

```
::grid raci 전환 프로젝트
- 활동 | 데이터본부 | 개발팀 | 운영팀
- 요건 정의 | A | R | C
- 이관 실행 | I | R | A
::
```

첫 행이 머리글, 나머지가 데이터이고, 정의가 아는 값은 색 칩으로 그려집니다.

## 정의는 색을 쓰지 않고 역할을 씁니다

```json
{
  "title": "KCB 담당 체계", "zebra": true, "legend": true,
  "order": ["R", "A", "C", "I"],
  "columns": [{"label": "업무", "weight": 2.4, "align": "l"}],
  "values": {
    "R": {"label": "실행", "role": "accent1", "chip": true, "meaning": "직접 수행"},
    "A": {"label": "승인", "role": "negative", "chip": true, "meaning": "최종 책임"}
  }
}
```

`accent1`~`accent6`, `positive`, `negative`, `muted`, `ink` — 색 대신 역할만 지정합니다.
템플릿이 각자의 테마로 해석하므로 **하나의 정의가 회사마다 그 회사 색으로** 나오고, 그
색은 팔레트 검사(v0.5.1)를 통과한 것들입니다. 색을 직접 적으면 422로 거절합니다.

- `raci`, `matrix`, `checklist`가 기본 제공됩니다. 정의 없이도 바로 쓸 수 있고, 자기 정의를
  만들 때 베낄 예시이기도 합니다.
- 같은 이름으로 자기 정의를 저장하면 기본 정의를 **덮어씁니다.** `::grid raci` 라고 쓴
  기존 소스가 그대로 동작하면서 슬라이드는 그 회사 규칙을 따릅니다. 덮어쓴 정의를 지우면
  기본 정의가 돌아옵니다.
- `weight`는 열의 폭 비율, `order`는 범례 순서(R·A·C·I는 알파벳순이 아닙니다), `zebra`는
  줄 음영입니다.
- `GET/POST /api/v1/grids`, `PUT/DELETE /api/v1/grids/{name}`.
- 격자도 다른 컴포넌트와 같은 검사를 받습니다. 기본 제공 30종 디자인 회귀 테스트의
  검사 덱에 RACI 격자가 포함됐습니다.
