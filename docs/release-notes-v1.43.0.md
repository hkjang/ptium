# Ptium v1.43.0

**한 덱 안에 서체가 두 개였습니다. 둘 다 사용자가 고른 것이 아니었습니다.**

## 렌더된 슬라이드를 직접 열어 봤습니다

이번에는 JSON이 아니라 실제 결과물을 봤습니다 — 사용자의 진짜 템플릿으로 덱을 만들고,
내보낸 .pptx의 XML과 화면 미리보기를 나란히 놓고.

먼저 잘 맞는 것들:

- 슬라이드 크기 `12192000 × 6858000` — 사용자 파일과 **완전히 동일**
- 제목은 레이아웃의 상자를 그대로 물려받고(`457200`부터 `8229600` 폭), 미리보기도
  같은 위치(가로 37.5%)에 그립니다 — **화면과 파일이 일치**
- 테마 색·폰트 스킴·강조색(`4F81BD`·`C0504D`)이 원본 그대로

그런데 서체가 갈라져 있었습니다.

```
표지·제목  → Calibri   (레이아웃에서 물려받음)
KPI 카드·본문 → Arial   (제품이 직접 그림)
```

## 왜 그랬는가

이 템플릿은 **폰트 스킴에는 Arial**, **마스터의 자리표시자 스타일에는 Calibri**를
적어 두고 있습니다. PowerPoint는 자리표시자를 그릴 때 **자리표시자 쪽 스타일을
우선**하므로 실제 화면에는 Calibri가 나옵니다.

제품은 자리표시자에서 물려받는 글자는 (제대로) Calibri로 나오게 두고, 자기가 직접
그리는 상자에는 **테마의 답인 Arial**을 썼습니다. 두 답이 다른 템플릿에서만 드러나는
어긋남입니다.

## 이제

직접 그리는 블록도 **템플릿의 자리표시자가 실제로 쓰는 서체**를 씁니다. 여러 레이아웃의
자리표시자 중 가장 많이 쓰인 것을 제목용·본문용으로 각각 고르고, 자리표시자가 서체를
적지 않은 템플릿은 예전처럼 테마를 따릅니다. `+mn-lt` 같은 테마 참조는 이름이 아니므로
그대로 테마로 넘깁니다.

확인: 같은 템플릿으로 다시 생성한 .pptx의 **모든 슬라이드에 등장하는 서체가 Calibri
하나**, 미리보기도 Calibri. 이전에는 `['Arial', 'Calibri']` 였습니다.

## 함께 고친 것

생성 리스 테스트가 **같은 데이터베이스에 붙은 서버의 작업자와 경합**해서 간헐적으로
실패하고 있었습니다. 덱을 다시 큐에 넣고 몇 번 더 시도하며, 끝내 못 잡으면 이유를
밝히고 건너뜁니다. 테스트가 배포와 경합해 실패하면 진짜 회귀를 가려 버립니다.
