# Ptium v0.4.1

v0.4.0에서 새로 만든 부분을 전문가 관점으로 감사하고, 발견한 결함을 고치고, 코드 편집
경험을 완성했습니다.

## 입력하는 동안 슬라이드가 그려집니다

편집기의 **코드** 탭이 좌우로 나뉘어, 텍스트 오른쪽에 해당 슬라이드가 실제 템플릿으로
그려집니다. 입력을 멈추면 갱신되고, 슬라이드 사이를 넘겨볼 수 있습니다.

- `POST /api/v1/presentations/{id}/source/preview.svg?slide=N` — 저장하지 않은 소스를
  컴파일해 그립니다. 저장하는 것이 없으므로 적용 전까지 덱은 그대로입니다. 컴파일된
  장수는 `X-Ptium-Slide-Count` 헤더로 알려 줍니다.

## 고친 결함

- **중첩 그룹 도형의 좌표가 틀렸습니다.** 그룹은 자신의 프레임과 자식 좌표계를 따로
  가지며 중첩됩니다. 서브트리를 다시 써서 매핑을 적용하던 방식은 두 단계 이상 들어간
  도형에서 바깥쪽 변환을 잃었습니다. 이제 내려가면서 배율과 오프셋을 누적해 적용하므로
  깊이에 상관없이 정확합니다. 그룹 안의 글자 크기도 함께 배율이 적용됩니다.
- **덱을 텍스트로 쓸 때 출력이 매번 달라졌습니다.** 역할 이름을 별칭 표에서 찾느라 맵
  순회 순서에 의존했고, 같은 덱을 다시 열 때마다 diff가 생겼습니다. 역할별 대표 이름을
  고정했습니다.
- **본문 텍스트가 왕복에서 사라졌습니다.** 슬롯이 없어 따로 보관된 텍스트를 다시
  내보내지 않아, 덱을 텍스트로 열었다 적용하면 그 문장이 없어졌습니다.
- **이스케이프가 눈에 보이지 않는 문자를 텍스트에 심었습니다.** 지시자처럼 보이는
  문장을 보호하려고 zero-width space를 넣었고, 그 문자가 내보낸 PPTX 본문까지
  들어갔습니다. 이제 역슬래시 하나를 쓰고 읽을 때 제거합니다. 대상도 실제로 필요한
  곳(제목 앞의 `#`, 컴포넌트 필드 안의 `|`)으로 좁혔습니다.
- **자른 사진의 클립 ID가 충돌했습니다.** 좌표로 ID를 만들었기 때문에 같은 위치의 두
  사진이 서로를 덮었고, 음수 좌표는 SVG가 거부하는 ID를 만들었습니다.
- **같은 이미지를 레이아웃마다 다시 디코딩했습니다.** 마스터 배경은 모든 레이아웃이
  상속하므로, 11개 레이아웃 템플릿은 같은 사진을 11번 디코딩했습니다. 평균 색을 내용
  기준으로 캐시합니다.
- 컴포넌트 캡션이 프레임 아래쪽이 아니라 내용 위에 붙습니다(v0.4.0에서 함께 수정).

## 다음에 할 만한 것

- AI 공급자에게 JSON 대신 이 슬라이드 언어로 응답받기: 스키마 오류가 줄고, 모델 출력을
  사람이 그대로 읽고 고칠 수 있습니다.
- 소스에 이미지 지시자(`::image`)와 표(`::table` 다중 열) 확장.
- 컴파일 경고를 줄 번호와 함께 편집기에 표시.
