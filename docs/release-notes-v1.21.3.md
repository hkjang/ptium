# Ptium v1.21.3

지난 판에서 "PowerPoint에서 열어 저장한 덱"을 다시 가져와 봤습니다. 출처가 두 번 들어오는
문제를 고쳤는데, **같은 실험에서 두 가지가 더 보였습니다.**

```
슬라이드의 성격  before: 표지 · 마무리 · 구역 · 인용 · 그림
                after : 표지 · 구역 · 구역 · 본문 · 그림
                              ↑ 마무리가 구역으로   ↑ 인용이 본문으로
```

**마무리 장이 간지가 되고, 인용 장이 평범한 본문**이 됩니다. 인용문은 요점 하나로 내려앉습니다.

## PowerPoint에는 "마무리"도 "인용"도 없습니다

PowerPoint의 레이아웃 종류에는 표지 · 간지 · 제목과 내용 · 2단 · 비교 · 그림 … 은 있어도
**마무리와 인용은 없습니다.** 그래서 이 제품은 마무리 장을 **간지 레이아웃 위에**, 인용 장을
**본문 레이아웃 위에** 만듭니다.

읽을 때는 **종류를 먼저** 보고 있었습니다. 종류만 보면 마무리는 간지이고 인용은 본문입니다 —
맞는 말이지만, **그 레이아웃의 이름이 "마무리"이고 "핵심 인용"** 인데도요.

이제 **종류가 말할 수 없는 두 가지는 이름으로 먼저** 읽습니다(`마무리` · `맺음` · `closing` ·
`thank you` · `인용` · `quote`). 나머지는 예전처럼 종류가 먼저입니다 — 남의 템플릿에서
레이아웃 이름은 만든 사람 마음이니까요.

```
after : 표지 · 마무리 · 구역 · 인용 · 그림     ← 그대로 돌아옵니다
```

## 확인

가진 `.pptx` 12개를 다시 가져와 성격 분포를 봤습니다 — 본문 103 · 그림 38 · 표지 4 ·
2단 3 · 비교 3 · **마무리 1**. 남의 덱을 잘못 읽지 않습니다.

## 검사

레이아웃 종류와 이름의 조합 11가지를 고정했습니다 — 이름으로 읽는 두 가지, 종류로 읽는
여덟 가지, 그리고 **아무것도 말하지 않는 "제목만"**. 되돌리면 네 곳에서 실패합니다.
