# Ptium v1.32.0

**가져온 덱의 글이 절반 사라졌습니다.** 편집기에서 "코드"를 열고 적용 한 번이면 됩니다.

## 무엇이 있었나

실제 회사 PPT(10장)를 가져온 뒤, 그 덱이 보여 주는 **자기 원문을 그대로 다시 적용**해
봤습니다.

```
슬라이드                    글자수 (전) → (후)
도입 배경 및 전략적 목표          484 →  212   ✗
PostgreSQL의 HTAP 기능      561 →  225   ✗
안정적인 운영을 위한 지원 체계       499 →  215   ✗
핵심 도입 기대 효과             415 →  215   ✗
리스크 대응 및 전략             482 →  210   ✗
```

**10장 중 5장이 글의 절반 이상을 잃었습니다.**

## 왜

- 데이터베이스에 저장된 원문은 **2,822자**였고, 그 안에 글이 다 있었습니다.
- 그런데 `GET /source`가 돌려준 원문은 **1,337자**였고, 그 글이 **없었습니다.**
- 화면은 돌려받은 그 원문을 보여 주고, 적용하면 그대로 덱이 됩니다.

원문을 슬라이드에서 다시 써 낼 때, **그림이 있는 자리를 "글은 이미 썼다"로 세고 있었습니다.**
가져온 슬라이드는 사진이 본문 자리에 들어가고 글은 갈 곳이 없어 `Body`에 남는데, 그
`Body`가 통째로 버려졌습니다.

## 고친 것

- **그림은 슬라이드의 말이 아닙니다.** 표도 아닙니다. 글이 자기 자리(필드)에 있을 때만
  "썼다"로 셉니다.
- **한 자리에 그림과 글이 같이 있으면 둘 다 씁니다.** 예전에는 그림을 쓰고 그 자리의
  글은 건너뛰었습니다.

```
GET /source: 2,362자 · 그 글을 담고 있음 ✓
적용 후 10장 모두 글자수 그대로 (484 → 484 …)
```

## 검사

- 사진 옆의 글이 원문으로 나오는지, 자기 자리를 가진 글이 두 번 나오지는 않는지
  고정했습니다. 예전 규칙으로 되돌리면 그 자리에서 실패합니다.
- REST 훑기가 **가져온 덱의 원문을 다시 적용해 글자수를 견줍니다** — 어느 장이든 글의
  절반 이상을 잃으면 실패합니다. (지금 훑기가 가져오는 파일에는 그림이 없어 이 특정
  경로까지는 닿지 않습니다. 그 경로는 위 단위 테스트가 지킵니다.)
