# Ptium v1.31.0

내장 생성기(폐쇄망에서 쓰는 그 생성기)가 만든 덱을 **사람처럼 읽어** 봤습니다.

```
[3] 현재 인력 현황   →  "투입과 회수를 같은 기준으로 놓고 봅니다"   ← 비용 이야기
[4] 필요 인원       →  "가장 큰 위험부터 다룹니다"                ← 위험 이야기
[5] 채용 일정       →  "무엇이 어떻게 달라지는지 지표로 말합니다"      ← 지표 이야기
[?] 예산을 담아 주세요 ←  제목에 부탁하는 말이 붙었습니다
```

측정은 **아무 defect도 잡지 않습니다.** 다 그려졌고, 자리에 맞고, 노트도 있습니다.
잘못된 것은 **제목과 본문이 서로 다른 이야기**라는 점입니다.

## 세 가지를 고쳤습니다

**하나 — 제목의 마지막 낱말이 그 장의 성격을 정합니다.**
우리말은 머리명사가 뒤에 옵니다. `도입 효과`는 *효과*에 대한 장인데, 표를 앞에서부터
읽다가 `도입`(순서 낱말)에 먼저 걸려 **로드맵 본문**을 받고 있었습니다. 이제 **끝에서
끝나는 낱말**이 이깁니다. 같은 자리에서 끝나면 더 구체적인 쪽(`기대효과` > `효과`)입니다.

**둘 — 제목에서 고른 성격은 다른 것으로 바뀌지 않습니다.**
예전에는 "이 덱에 아직 안 쓴 모양"을 우선해서, 제목이 고른 성격을 밀어냈습니다.
이제는 **덱이 아직 그 성격을 쓰지 않았다면 제목이 고른 대로** 갑니다.

**셋 — 부탁하는 말은 제목이 아닙니다.**
`…, 예산을 담아 주세요`에서 `담아 주세요`가 마지막 항목에 붙어 있었습니다(`넣어 주세요`,
`포함해 주세요`는 이미 떼고 있었습니다). 이제 `예산`입니다.

## 결과

```
[4] 현재 문제   → 지금 어디까지 와 있는지 정리합니다      ← 현황
[5] 도입 효과   → 투입과 회수를 같은 기준으로 놓고 봅니다   ← 효과·타당성
[6] 비용       → (선택지 비교)                        ← 비용
```

## 남은 것 (일부러 두었습니다)

**한 덱에서 두 장이 같은 문장으로 시작하지 않는다**는 규칙이 이 제품에 있습니다
(테스트로 지켜집니다). 그래서 같은 성격의 장이 두 번 나오면 **두 번째는 다른 각도**를
받습니다 — 위 예의 `일정`이 지표 본문을 받은 이유입니다.

제대로 고치려면 **성격마다 두 번째 본문**(다른 리드와 요점)을 써야 합니다. 그건 제품의
목소리를 새로 쓰는 일이라 임의로 정하지 않고 남겨 둡니다.

## 검사

- 제목의 끝 낱말이 성격을 정하는지(9가지), 말이 아무것도 정하지 않을 때 그렇다고
  말하는지 고정했습니다.
- 브리프의 부탁하는 말이 제목에 남지 않는지 고정했습니다.
- 기존 규칙(두 장이 같은 제목·같은 리드로 시작하지 않음)은 그대로 통과합니다.
