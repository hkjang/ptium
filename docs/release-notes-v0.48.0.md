# Ptium v0.48.0

계획서 4차 — **편집기 코파일럿**입니다. 다만 채팅창을 붙이지 않았습니다.

## 말로 시킵니다

편집기 위 **명령**에 하고 싶은 일을 적습니다.

```
3번과 4번 합쳐줘
5번 삭제 · 2번과 5번 지워줘
2번을 두 장으로 나눠줘
6번을 2번으로 옮겨줘
8장으로 줄여줘 · 10분 발표로 맞춰줘
```

**무엇을 할지 먼저 보여 줍니다.** 읽은 문장을 되돌려 주고("2번과 3번을 한 장으로 합칩니다"),
몇 장이 몇 장이 되는지 말한 다음에야 적용합니다. 확인할 수 없는 명령은 실행하지 않습니다.
되돌리기는 **버전 이력**입니다.

## 모델을 쓰지 않습니다

이것이 이 판의 핵심 판단입니다. 합치고 · 나누고 · 옮기고 · 지우고 · 줄이는 일에는 **정답이
하나뿐**입니다. 문장을 읽는 편이 모델에게 물어보는 것보다 빠르고, 정확하고, **모델이 없는
폐쇄망에서도 똑같이 됩니다.** 모델의 일은 따로 있습니다 — 슬라이드의 **말**을 다시 쓰는 것,
`AI로 다듬기`입니다.

한국어와 영어를 함께 읽습니다. 두 언어는 동사가 어디 오는지만 다르고 나머지는 같아서, 문장을
**동사 하나와 숫자 몇 개**로 읽으면 두 언어가 한 파서를 씁니다(`merge 3 and 4` 도 됩니다).

## 잃지 않고 합칩니다

두 장을 합치면 **요점 · 발표자 노트 · 출처**가 모두 따라갑니다. 출처를 절반 잃은 한 장은 두
장보다 나쁩니다 (v0.46에서 만든 근거가 여기서 값을 합니다).

줄일 때는 **측정 점수가 가장 낮은 장부터** 빠집니다 (v0.45의 점수가 여기서 값을 합니다).
표지와 마무리는 남고, 무엇을 뺐는지 말해 줍니다: `측정 점수가 가장 낮은 3번을 뺐습니다`.
발표 시간으로 맞추면 **한 장에 2분**으로 셉니다.

## 확인

- 회귀 테스트 4건: 문장 10가지가 각각 어떤 편집이 되는지(그리고 **없는 슬라이드·뜻 없는 문장은
  거절**), 합치기가 요점·노트·**출처**를 모두 지키는 것, 줄이기가 가장 낮은 장을 빼고 표지·마무리를
  남기는 것, 나누기가 요점을 반씩 갈라 "(계속)"을 붙이는 것.
- 전수 점검에 두 줄: 미리보기가 덱을 바꾸지 않는 것, 뜻 없는 문장이 422로 거절되는 것.
- 브라우저: 명령 → 계획 확인 → 적용 → 5장이 4장이 되는 것까지, 콘솔 오류 0.
- 전수 점검: api 81 · edges 32 · package · deep 0 실패.
