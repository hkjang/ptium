# Ptium v0.65.0

지난 판의 결함 — "저장한 슬라이드가 100개를 넘으면 안 보인다" — 은 **데이터가 쌓여야 드러나는**
종류였습니다. 그래서 이번에는 그 종류를 찾아 나섰습니다. 지금 이 개발 DB에는 프레젠테이션
655개, 슬라이드 4,170장, 스니펫 126개, 이미지 115개가 쌓여 있습니다.

## 목록 한 페이지가 190KB였습니다

프레젠테이션 목록은 제목 · 상태 · 날짜를 그립니다. 그런데 응답에는 **덱마다 원본 텍스트 전체와
개요(outline)** 가 들어 있었습니다. 화면이 읽지도 않는 글입니다.

그리고 웹은 목록을 그리려고 **모든 페이지를 다 받아 왔습니다** — 655개면 요청 7번, 1.2MB.
검색은 그렇게 다 받아 온 다음 브라우저에서 걸렀습니다. 덱이 열 개일 때는 아무 문제가 없고,
육백 개가 되면 앞 화면이 그렇게 열립니다.

| | 이전 | 이후 |
|---|---|---|
| 한 페이지 | 190KB | **51KB** |
| 첫 화면 요청 | 7번 (전량) | **1번** |
| 검색 | 전량 받은 뒤 브라우저에서 | **서버에서** (`?q=`) |

- 목록 응답에서 `source` 와 `outline` 을 뺐습니다. 덱을 열면 그때 전부 가져옵니다.
- `/presentations?q=` 를 추가했습니다 — 제목과 브리프에서 찾고, 세는 것도 서버가 셉니다.
- 앞 화면은 한 번에 60장을 받고 **`더 보기 (60 / 655)`** 로 이어 받습니다. 검색은 타이핑이
  멈추면 서버에 물어봅니다.

브라우저로 확인했습니다: 첫 화면 요청 1번 · 카드 60장 · `더 보기` 누르면 120장 ·
`왕복` 검색에 10건.
