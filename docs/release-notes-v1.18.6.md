# Ptium v1.18.6

## 쪽이 스스로 옮겨 그린 글은 한 줄로 붙어 있었습니다

PDF에는 "줄"이 없습니다. 좌표에 놓인 글자만 있고, **그 좌표계를 쪽이 마음대로 바꿀 수
있습니다**(`cm`). 그래서 많은 생성기는 글을 옮기는 대신 **좌표계를 옮깁니다** — 문단마다
`q … cm … Q` 로 감싸고, 그 안에서는 전부 같은 자리에 씁니다.

리더는 글자의 행렬만 보고 있었습니다. 그러면 그렇게 만든 쪽은 **모든 문단이 같은 기준선**에
있는 것처럼 보입니다.

```
q 1 0 0 1 72 700 cm  BT … (First) Tj  ET Q     ← 쪽에서 40포인트 떨어져 있는데
q 1 0 0 1 72 660 cm  BT … (Second) Tj ET Q     ← 글자 행렬로는 같은 줄
```

읽어 보면 `"FirstSecond"` 한 줄이었습니다. 400포인트 떨어진 두 덩어리도 `"InsideOutside"`
였습니다.

이제 **쪽의 변환을 따라갑니다** — `q` · `Q` 로 쌓이고 풀리는 것까지 포함해서, 글자가 실제로
**종이 위 어디에 찍히는지**로 줄을 나눕니다. 뒤집힌 쪽(`1 0 0 -1 0 792 cm`)도, 배율이 걸린
쪽도 같은 기준으로 봅니다.

실측 52개는 **글자 하나 차이 없이** 그대로 읽힙니다(2개 파일에서 띄어쓰기 1칸씩만 달라졌습니다).
이번 판은 아직 겪지 않은 형태의 파일을 위한 것입니다 — 겪고 나서 고치면 그때는 이미 누군가의
문서가 한 줄로 붙어 나온 뒤입니다.

## 재 보고 하지 않기로 한 것

좌표를 얻었으니 **줄을 위에서 아래로 정렬**해 볼 수 있었습니다. 1,102쪽을 재 보니 938쪽이
"앞 줄보다 위에 그려진 줄"을 갖고 있었습니다 — 정렬할 이유처럼 보였습니다.

실제로 정렬해서 눈으로 봤습니다.

- 두 단짜리 보고서: 오른쪽 단이 왼쪽 단 사이로 끼어들고, 머리글·꼬리글이 본문 위로 올라옴 — **나빠짐**
- 거래내역서: 표의 칸들이 흩어져 `"1 /"` 만 열두 줄 — **훨씬 나빠짐**
- 슬라이드형 PDF: **차이 없음**

**그리는 순서가 대개 읽는 순서**였습니다. 정렬은 넣지 않았습니다. 숫자가 크다고 고치는 게 아니라,
고쳐서 나아지는지 보고 고칩니다.
