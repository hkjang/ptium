# Ptium v1.39.0

관리자 고도화 — **이 오류가 지금 이 배포의 것인지** 말해 줍니다.

## 열린 오류 8건. 그중 몇 건이 지금 이 버전의 문제입니까

오류 센터는 무엇이 언제 몇 번 일어났는지는 기록했지만, **무엇에서** 일어났는지는
적지 않았습니다. 그래서 두 달 전에 올라온 critical 하나를 열어 놓고도 운영자는
판단할 수 없었습니다 — 이 버전에도 남아 있는 결함인지, 이미 지나온 버전에서
끝난 일인지.

실제로 이번 개발 중에 그 상황이 그대로 재현됐습니다. 템플릿 업로드에서 나던
nil 패닉이 오류 센터에 critical·2회로 열려 있었고, 그것이 **24분 뒤 릴리스에서
이미 고쳐진 결함**이라는 사실은 git 로그를 뒤져야 알 수 있었습니다. 폐쇄망 현장에는
git 로그가 없습니다.

## 기록에 버전이 붙습니다

```
처음 발생 버전   1.13.9
마지막 발생 버전  1.13.9

마지막 발생은 1.13.9이고, 지금 실행 중인 버전은 1.39.0입니다.
이 그룹은 1.39.0에서는 아직 기록되지 않았습니다.
```

- 같은 결함이 다시 나면 **마지막 발생 버전만** 올라갑니다. 처음 발생 버전은 그대로 —
  두 값이 다르면 업그레이드를 넘어서 살아남은 결함이고, 같으면 그 버전에서 멈춘
  결함입니다.
- 목록에서도 한 줄로 보입니다: `1.13.9에서 마지막 발생` / `현재 버전 1.39.0`.
- 관리자 개요의 「열린 오류」 카드가 **현재 버전에서 발생 2** 처럼 나눠서 셉니다.
  점검 리포트에도 `열린 오류 5 (이 버전에서 발생 0)` 으로 들어갑니다.

## 고쳐졌다고는 말하지 않습니다

제품은 결함이 고쳐졌는지 알 수 없습니다. 아는 것만 말합니다.

- **이 버전에서는 아직 기록되지 않았습니다**는 아직 열려 있는 그룹에만 붙습니다.
  해결 처리된 그룹은 재발하면 새 그룹으로 열리므로, 거기서의 침묵은 아무 뜻이 없습니다.
- 이전 릴리스에서 기록된 오류에는 버전이 비어 있습니다. 비어 있음은 **모른다**는
  뜻이지 "이전 버전"이라는 뜻이 아니어서, 재발해도 처음 발생 버전을 오늘 것으로
  채우지 않고, 개요 카드도 그 경우에는 버전 이야기를 꺼내지 않습니다.
- 버전 스탬프 없이 빌드된 프로세스는 없는 버전을 적는 대신 아무것도 적지 않습니다.

## 업그레이드

마이그레이션 두 줄이 늘어납니다(`first_seen_version`, `last_seen_version`).
기존 기록은 비어 있는 채로 남고, 이 버전부터 쌓이는 기록에 버전이 붙습니다.
