# 1.67.1 — 가로 막대 차트를 찾을 수 있게 됩니다

`docs/deck-source.md` 는 작성자가 무엇을 쓸 수 있는지 배우는 곳입니다. 파서는
컴포넌트 15개를 예순 개 남짓한 이름으로 받는데, **가로 막대 차트만 어느 이름으로도
문서에 없었습니다.**

가로 막대는 `hbars`, `barchart`, `ranking`, `가로막대` 로만 닿습니다. 문서에는
그 넷 중 아무것도 없었습니다. **찾을 수 없는 컴포넌트는 없는 컴포넌트입니다.**

## 게다가 이름이 엇갈려 있었습니다

문서는 `columns` 와 `bars` 를 나란히 적어, 서로 다른 두 차트인 것처럼 보였습니다.
둘 다 **세로** 막대입니다. 순위를 가로 막대로 그리려고 `::bars` 를 쓴 사람은
세로 막대를 받습니다.

그려진 그림으로 확인했습니다.

- `::bars` — 바닥 축에서 위로 솟습니다 (세로)
- `::hbars` — 왼쪽 축에서 오른쪽으로 뻗습니다 (가로)

이제 문서가 둘을 갈라 적습니다. 분기별 수치처럼 시간이 가로로 흐르면 `columns`,
순위처럼 이름이 막대 옆에 붙어야 읽히면 `hbars`. `bars` 와 `bar` 는 `columns` 의
옛 이름이라고 밝혀 두었으니, 그렇게 쓰던 덱은 그리던 것을 그대로 그립니다.

`::bullets` 와 `!출처` 도 빠져 있어 함께 적었습니다.

## 다시 어긋나지 않게

파서가 받는 모든 컴포넌트가 문서에서 **작성자가 실제로 쓸 수 있는 이름으로**
찾아지는지 검사하는 시험을 두었습니다. 그 이름 목록이 파서와 어긋나면 그것도
시험이 잡습니다.

## 확인

- 그려진 SVG 의 축과 막대 방향으로 두 차트가 서로 다른 것임을 확인했습니다.
- 문서에서 가로 막대의 이름을 모두 지우면 시험이 무너지는 것을 확인했습니다.
- 스윕에 두 차트가 각각 이름대로 그려지는지 확인하는 검사를 넣었습니다.
