# Ptium v0.59.0

이번 판은 **실제로 생성한 덱**을 검사기에 통과시켜 보고, 나온 지적 네 개를 하나씩 따져
봤습니다. 두 개는 진짜였고 두 개는 오탐이었습니다.

## 슬라이드에 "…을 단계별로 적" 이 찍혀 있었습니다

생성기는 `이행 | 국내 결제 시스템 이중화 계획을 단계별로 적용` 이라고 씁니다. 컴포넌트의 값은
24자에서 **글자 수로 그냥 잘렸습니다.** 결과가 `단계별로 적` — 適用의 반쪽이고, 잘렸다는
표시조차 없습니다. 읽는 사람은 **덱이 잘못된 건지 제품이 잘못된 건지 알 수 없습니다.**

두 가지를 고쳤습니다.

- **단어 사이에서 자르고, 잘랐다고 말합니다** (`…`). 같은 계산을 본문 텍스트도 씁니다 —
  본문 쪽 함수는 경계를 **바이트로** 세어 글자 수와 비교하고 있었고, 한국어에서는 3배 헐거워
  안전장치가 사실상 꺼져 있었습니다.
- **값의 한도를 종류별로 나눴습니다.** KPI의 값은 숫자와 단위(24자면 충분)지만, 프로세스 ·
  전후 비교 · 타임라인의 값은 **문장**입니다. 숫자 폭으로 문장을 자르면 슬라이드가 말이
  되지 않습니다. 이제 60자입니다.

## 생성기가 슬라이드 제목을 본문에서 그대로 되풀이했습니다

`제목: 국내 결제 시스템 이중화 계획` / `본문: 국내 결제 시스템 이중화 계획을 단계별로…`
— 검사기의 `같은 말 반복` 지적이 맞았고, 틀린 쪽은 **생성기**였습니다. 영어판 문구는 이미
제목을 되풀이하지 않고 있었습니다(`The order this happens in.`). 한국어 세 곳을 같은 원칙으로
바꿨습니다 — 제목이 이미 말한 것을 본문이 다시 말하지 않습니다.

## 검사기가 일정표에 "출처를 대라"고 하고 있었습니다

`첫 2주에 할 일` · `6개월 안에 확인할 지표` — 계획의 **시점**이지 주장이 아닙니다. 회의실에서
출처를 묻는 대상은 돈 · 비율 · 수량입니다. 날짜와 기간은 숫자로 세지 않습니다.
(`2026년 매출은 1,240억` 은 그대로 묻습니다.)
