# Ptium v0.4.0

PPT 자동생성을 전면적으로 다시 만들었습니다. 세 가지 문제가 있었고, 뿌리는 하나였습니다.
덱이 곧바로 슬라이드 객체로 조립되었기 때문에, 프롬프트는 주제 문자열을 끼워 넣는
역할만 했고, 생성과 완성 파일 사이에 사람이 보고 고칠 것이 없었습니다.

## 덱을 코드로 쓰고 바로 PPT로 변환합니다

덱은 이제 작은 슬라이드 언어로 작성되고, 그 텍스트를 템플릿에 컴파일해 그립니다.

```
# 전환 대상과 우선순위
> 42개 시스템을 세 묶음으로 나눴습니다.
::kpi 규모
- 전환 대상 | 42개
- 예상 절감 | 18%
::
!notes 1차 범위만 승인받으면 나머지는 실적으로 설득합니다.
```

`#` 제목, `@` 슬라이드 종류, `>` 리드, `-` 항목(두 칸 들여쓰기로 하위 항목),
`::종류 … ::` 컴포넌트(`label | value`), `!notes` 발표 노트. 문법은 이것이 전부입니다.

- 편집기에 **코드** 탭이 추가되었습니다. 덱 전체를 텍스트로 열어 고치고, **검사**로
  몇 장이 되는지 확인한 뒤 **적용**하면 템플릿에 맞춰 다시 그립니다.
- 컴파일은 템플릿이 아는 것을 모두 적용합니다. 슬라이드마다 실제 레이아웃을 고르고,
  그 레이아웃이 가진 실제 슬롯에 넣고, 슬롯이 담을 수 있는 분량으로 맞추고, 컴포넌트가
  들어갈 자리가 없으면 문장으로 바꿉니다. 무엇을 조정했는지는 경고로 알려 주며, 조정을
  이유로 생성을 실패시키지 않습니다.
- 반대 방향도 동작합니다. 캔버스에서 고친 덱을 텍스트로 다시 읽을 수 있고, 왕복해도
  같은 슬라이드가 나옵니다(테스트로 고정).
- `GET/PUT /api/v1/presentations/{id}/source`. 자세한 문법은
  [docs/deck-source.md](deck-source.md)를 보십시오.
- 컴포넌트 13종(kpi·hero·steps·timeline·comparison·columns·bars·line·share·meter·
  table·quote·callout)은 이미지가 아니라 PowerPoint 도형으로 그려집니다.

## 업로드한 템플릿의 테마를 그대로 씁니다

템플릿의 정체성은 색 조합이 아니라 배경 사진, 브랜드 바, 로고, 그라디언트 패널에
있는데, 분석기는 그것을 하나도 기록하지 않았습니다. 단색 사각형 최대 12개만 담았기
때문에, 구글 슬라이드에서 내보낸 덱이나 디자이너가 만든 덱은 미리보기에서 흰 화면으로
보였고 — 실제로 무시되고 있었으므로 — 테마가 적용되지 않은 것으로 보였습니다.

- 레이아웃을 **그리는 순서대로** 기록합니다. 사진(자르기 포함), 그라디언트(스톱과
  투명도), 외곽선, 회전과 반전, 그룹 도형의 좌표 변환, 템플릿이 직접 쓴 정적 텍스트.
  배경은 단색·그라디언트·사진을 모두 처리합니다.
- 미리보기가 그 전부를 그립니다. 사진은 그려질 크기에 맞춰 축소·재인코딩해 데이터 URI로
  넣습니다(`<img>`로 불러온 SVG는 외부 리소스를 가져오지 않으므로 참조로는 아무것도
  보이지 않습니다).
- **플레이스홀더가 없는 레이아웃에도 글을 씁니다.** 이것이 문제의 나머지 절반이었습니다.
  그런 레이아웃에는 쓸 수 없었기 때문에 모든 슬라이드가 플레이스홀더를 가진 평범한
  레이아웃 하나로 몰렸고, 브랜드 레이아웃은 쓰이지 않았습니다. 이제 그림이 비워 둔 가장
  큰 사각형을 찾아(전면 사진은 장애물이 아니라 배경으로 취급) 제목·리드·본문 영역을
  만듭니다. 글자 크기는 슬라이드 기준으로, 글자 색은 뒤에 놓인 그림의 평균 색과의
  대비로, 글꼴은 테마에서 가져옵니다.
- 이렇게 만든 영역은 일반 텍스트 상자로 내보내므로 레이아웃의 그림은 건드리지 않고,
  PowerPoint에서 계속 편집할 수 있습니다.

## 프롬프트를 읽습니다

폐쇄망 작성기는 프롬프트를 장식하지 않고 읽습니다. 프롬프트가 말한 주제, 기간, 숫자를
꺼내고, 각 주제를 어떤 방식으로 논증할지 결정한 뒤(순서·타당성·비교·리스크·기대효과·현황)
그 구조를 씁니다.

- "2026년 하반기 클라우드 전환 로드맵과 투자 타당성"은 단계로 그린 로드맵 슬라이드와
  비용·효과 슬라이드가 됩니다. 사내 문구에 주제만 끼워 넣던 결과와 다릅니다.
- 프롬프트의 숫자는 KPI 타일로 올라갑니다. 연도는 숫자가 아니라 기간으로 읽습니다.
- 조사 제거가 조심스러워져 효과·속도·자료·평가가 잘리지 않습니다.
- **"3장으로"라고 쓰면 3장이 나옵니다.** 슬라이드 수 조절기를 건드리지 않은 채 분량을
  프롬프트에 쓰면, 조절기의 기본값이 아니라 프롬프트를 따릅니다. 언어와 대상도 같습니다.
- 클라이언트가 프롬프트 앞부분을 잘라 보낸 제목이나 "Untitled presentation" 같은
  자리표시자는 제목으로 쓰지 않고, 주제들로 제목을 만듭니다.
- 한 주제에 여러 장이 배정되면 같은 내용을 반복하지 않고 다른 측면(기대효과, 리스크,
  선택지)을 논증합니다.

## 그 외

- AI 공급자가 요청한 장수와 다르게 응답해도 생성을 실패시키지 않습니다. 넘치면 뒤에서
  자르고, 부족하면 부족한 대로 전달하며 두 경우 모두 경고로 알립니다.
- AI가 만든 덱도 소스로 저장되므로 사람이 쓴 덱과 똑같이 편집할 수 있습니다.
- 컴포넌트 캡션이 프레임 아래쪽에 떨어져 있지 않고 내용 위에 붙습니다. 비교 카드는
  내용 높이에 맞춰 그려지고, 문구 길이에 따라 글자 크기가 단계적으로 줄어듭니다.
- `presentations.source` 컬럼이 기동 시 자동 추가됩니다.
- 템플릿 분석 형식이 4로 올라갔습니다. 기존에 업로드한 템플릿은 다음 미리보기나
  내보내기에서 자동으로 다시 분석되어 저장됩니다.

## 오프라인 설치

```bash
gzip -dc ptium-0.4.0.tar.gz | docker load
sha256sum -c ptium-0.4.0.tar.gz.sha256
```

이미지 태그만 바꾸면 업그레이드됩니다.
