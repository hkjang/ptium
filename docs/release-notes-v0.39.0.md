# Ptium v0.39.0

편집기의 **코드** 화면이 지금 덱이 아니라 **덱이 출발한 자리**를 보여 주고 있었습니다.

## 편집한 것이 코드 화면에는 없었습니다

작업 공간은 저장된 소스가 **아직 지금 슬라이드를 설명할 때만** 그 소스를 보여 줍니다. 그런데
"아직 설명한다"의 판단이 **슬라이드 수 · 제목 · 레이아웃** 세 가지만 비교하고 있었습니다.

슬라이드를 캔버스에서 고치거나, AI로 한 장을 다시 쓰거나, 측정 결과의 **안전 수정**으로
발표자 노트를 넣어도 — **제목은 그대로입니다.** 그래서 저장된 옛 텍스트가 계속 "지금 것"으로
통과했고, 코드 화면은 그 옛 텍스트를 덱인 양 보여 줬습니다.

문제는 보여 주는 데서 끝나지 않습니다. 그 화면에서 **적용**을 누르면 방금 넣은 노트와 방금
고친 문장이 **조용히 사라집니다.**

실제로 재현한 것: 2장짜리 덱에 안전 수정으로 노트를 넣었더니 슬라이드에는 `실적: 매출 1,240억`이
들어갔는데, 코드 화면의 소스에는 `!notes` 줄이 없었습니다.

## 소스 언어 자신이 판단합니다

이제 양쪽을 **소스 언어의 역함수**(`Format`)로 다시 써서 비교합니다. 저장된 소스를 컴파일한
결과와 저장된 슬라이드를 각각 텍스트로 되돌려 같은지 봅니다.

- 텍스트가 **표현할 수 있는 것 전부**가 비교 대상입니다 — 요점, 컴포넌트, 이미지, 노트, 리드.
- 텍스트가 **원래 담지 않는 것**은 비교에서 빠집니다 — 캔버스에 얹은 개체, 그리고 작성자가 적어
  둔 주석과 빈 줄. (양쪽 다 같은 관문을 지나므로 주석 때문에 소스가 갈아엎히지 않습니다.)

## 확인

- 회귀 테스트 1건: 발표자 노트를 넣었을 때, 그리고 요점 한 줄을 고쳤을 때 — 둘 다 제목은
  그대로인데 옛 텍스트가 더 이상 "지금 것"으로 통과하지 않습니다.
- 브라우저로 확인한 것들: 버전 이력 열기·복원(3장 → 2장), 측정 결과의 안전 수정, 발표 화면과
  발표자 보기(다음 장·노트·타이머) — 콘솔 오류 0.
- 전수 점검: api · edges 0 실패.
