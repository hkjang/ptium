# Ptium v0.34.0

브라우저에서 **처음 쓰는 사람처럼** 가져오기를 해 봤습니다. 두 가지가 보였습니다.

## 가져온 덱의 마지막 장이 매번 "마무리"가 됐습니다

마이크로소프트의 보통 본문 레이아웃은 타입이 `obj`인데, 읽는 쪽이 그것을 몰라 슬라이드가
**성격 없이** 들어왔습니다. 그러면 덱의 위치 규칙이 대신 정합니다 — 마지막 장은 마무리. 그런데
대부분의 마무리 레이아웃은 한 줄짜리라서 **그 장의 요점이 흘림 글씨로 떨어졌습니다.**

Office 파일이 실제로 쓰는 레이아웃 타입을 전부 알아보게 했습니다. 이제 가져온 슬라이드는
**파일이 말한 그대로의 성격**을 지킵니다.

## 컴파일러의 메모를 사용자에게 보여 주고 있었습니다

한국어 토스트가 이렇게 끝났습니다:

> 4장을 가져왔습니다. `line 11 (slide 4): layout "마무리" has no free body region, so its points were kept as plain text`

이 문장은 **템플릿을 디버깅하는 사람**을 위한 것이지, 자기 덱을 돌려받고 싶었을 뿐인 사람을
위한 것이 아닙니다. 응답이 이제 둘을 나눕니다.

- `warnings` — **파일에 무슨 일이 있었는지**: 그림을 몇 장 넣었고, 표를 다시 그렸고, 차트는 두고 왔다
- `notes` — **템플릿에 붙이며 무엇을 조정했는지** (기술적인 것)

작업 공간은 앞의 것만 보여 줍니다.

실측: 같은 4장짜리 회사 덱을 다시 가져오면 **네 장 모두 원래 성격 그대로**(표지 · 본문 · 본문 ·
본문), 조정할 것이 없으니 **메모도 경고도 0건**.

## 오프라인 설치

gzip -dc ptium-0.34.0.tar.gz | docker load
