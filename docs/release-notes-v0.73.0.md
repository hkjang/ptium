# Ptium v0.73.0

Ptium은 기업 덱이 늘 쓰는 격자 셋을 그립니다 — **RACI 담당 체계**, **준비 상태 체크리스트**,
**영향·가능성 매트릭스**. 그런데 생성된 덱에서 이 셋을 한 번도 본 적이 없습니다.

## 모델에게 말해 주지 않았습니다

모델에게 주는 안내에는 컴포넌트 13가지가 적혀 있었고, **`::grid` 만 빠져** 있었습니다.
존재를 모르는 도구는 쓰이지 않습니다. 담당 체계를 물으면 모델은 글머리표로 씁니다.

이제 브리프가 **정의 자체에서 만든 목록**을 싣습니다.

```
Named grids this deployment draws, for ::grid <name>:
- raci (담당 체계 (RACI)): cells are one of R, A, C, I
- matrix (영향 · 가능성): cells are one of 높음, 중간, 낮음
- checklist (준비 상태): cells are one of 완료, 진행, 미착수, 위험
```

정의에서 생성하므로 안내와 실제가 어긋날 수 없습니다.

**실제 모델로 확인했습니다.** "이관 프로젝트의 담당 체계와 준비 상태" 브리프를 보냈더니 모델이
`::grid raci` 로 4×5 RACI 표를 쓰고, 리스크는 `::grid matrix` 로 썼습니다. 그려 보면 역할
칩이 색으로 구분되고 아래에 범례가 붙은, 컨설팅 덱에서 보던 그 슬라이드입니다.

## 그리고 모델이 `::checklist` 라고 썼습니다

같은 덱에서 체크리스트는 `::grid checklist` 가 아니라 **`::checklist`** 로 썼습니다.
당연합니다 — 이름의 목록을 받았으면 이름을 씁니다. 그런데 Ptium은 이것을 **없는 컴포넌트**로
보고 경고한 뒤, 그 줄들을 앞 슬라이드의 요점에 섞어 버렸습니다.

이제 **정의 이름을 그대로 울타리로 쓸 수 있습니다.** `::checklist 이관 준비 상태` 는
`::grid checklist` 와 같습니다. 정의에 없는 이름(`::flowchart`)은 여전히 "없는 컴포넌트"라고
분명히 말합니다.
