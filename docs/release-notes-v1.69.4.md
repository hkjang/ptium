# Ptium 1.69.4

## 화면 낭독기가 이름을 읽을 수 없던 조작 요소 여섯 개

화면 낭독기에 전달되는 것은 우리가 쓴 마크업이 아니라 브라우저가 그로부터 계산한
접근성 트리입니다. 그 트리를 크롬에게 직접 물어보니, 이름이 비어 있는 조작 요소가
여섯 개 있었습니다. 낭독기는 이런 요소를 종류만 읽습니다. "콤보 상자"라고만
들리고, 무엇을 거르는 상자인지 알려면 값을 바꿔 봐야 합니다.

거르개 네 개는 이름이 처음부터 없었습니다.

- 관리 · 사용자: 역할, 계정 상태
- 관리 · 오류: 심각도
- 관리 · 감사 기록: 동작

색상 칸 두 개는 이름을 옆의 색 견본에 빼앗겼습니다. `<label>`은 자기 밑의 첫
번째 조작 요소 하나만 이름 짓습니다. 색 견본과 16진값 칸이 한 `<label>` 안에
나란히 있었으니, 이름은 견본이 가져가고 16진값 칸에는 아무것도 남지 않았습니다.

- 개인 설정: 브랜드 강조 색상의 16진값 칸
- 관리 · 브랜딩: 대표 색상의 16진값 칸

여섯 곳 모두 이름을 붙였습니다.

## 지키는 장치

`scripts/e2e/ui.py`가 이제 들르는 화면마다 브라우저의 접근성 트리를 읽어, 이름
없는 조작 요소가 하나라도 있으면 그 화면과 함께 실패로 적습니다. 우리가 짐작한
규칙이 아니라 브라우저가 실제로 계산한 이름을 봅니다. 고침을 되돌려 돌리니 일곱
줄(개인 설정은 두 번 들릅니다)이 그대로 실패로 나오는 것을 확인했습니다.

한 가지 바로잡은 짐작: 새 프레젠테이션 화면의 브리프 입력칸도 이름이 없다고
보았지만, 브라우저는 안내 문구를 이름으로 삼고 있었습니다. 손으로 만든 규칙이
틀렸고 브라우저가 맞았습니다.
