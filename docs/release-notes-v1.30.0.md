# Ptium v1.30.0

**폐쇄망 배포에서 "AI로 다듬기"를 누르면 덱이 사라졌습니다.**

## 무슨 일이 있었나

이 제품은 모델 없이도 **브리프로 새 덱을 씁니다**(내장 생성기). 하지만 **이미 있는 덱을
다시 쓰는 것**은 내장 생성기가 대신할 수 없습니다 — 그러면 사용자의 덱이 아니라
브리프에 대한 새 덱이 되어버리니까요. 이 판단은 옳습니다.

문제는 그다음입니다.

```
잘 만들어진 4장짜리 덱 → "AI로 다듬기" → 대기열 → 실패
편집기:  "슬라이드 생성에 실패했습니다"
        "AI 제공자가 설정되어 있지 않습니다. 관리자에게 서비스 설정을 확인해 달라고 요청하세요"
목록:    실패
```

- 덱의 4장은 **데이터베이스에 그대로 있는데 화면에서는 볼 수 없습니다.**
- 관리자가 고칠 것은 **아무것도 없습니다.** 배포는 출고된 그대로입니다.

가져온 덱(import)도 같습니다 — 원문이 있는 덱을 다시 생성하면 이 경로로 갑니다.

## 덱은 그대로 둡니다

이제 **이미 슬라이드가 있는 덱**은 다시 쓰기가 실패해도 `completed`로 남습니다.
슬라이드는 그대로 보이고, 무슨 일이 있었는지는 **편집기의 안내 패널**(1.29.3에서
가져오기 안내가 들어간 그 자리)에 적힙니다.

```
before: completed 4 slides → 다듬기 실패 → failed  (화면에서 사라짐)
after : completed 4 slides → 다듬기 실패 → completed 4 slides + 안내
```

모델이 잠깐 죽었을 때도 마찬가지입니다. **가진 덱을 잃지 않습니다.**

## 사실대로 말합니다

```
덱을 다시 쓰려면 연결된 AI 모델이 필요합니다. 이 배포는 브리프로 새 덱을 쓰는
내장 생성기만 갖고 있어서, 이미 있는 덱은 다시 쓰지 못합니다. 덱은 그대로입니다.
```

- 관리자를 부르지 않습니다. 고칠 것이 없으니까요.
- **무엇이 필요한지**와 **덱은 무사하다**는 것을 말합니다.
- 한국어 · English · 日本語 · 中文 모두.
- 진짜로 잘못 설정된 배포(`unsupported AI provider`)는 **여전히** 설정을 확인하라고 합니다.

## 검사

- 슬라이드가 있는 덱은 실패해도 `completed`로 남고 이유가 노트에 들어가는지, 빈 덱은
  그대로 실패로 남는지 데이터베이스로 확인합니다.
- 문구가 배포를 탓하지 않는지, 진짜 오설정은 여전히 잡는지 고정했습니다.
- REST 훑기가 덱을 만들어 다듬기를 시켜 보고, **슬라이드가 있는데 실패로 남으면** 실패합니다.
  되돌리면 그 자리에서 잡습니다(`failed 4 slides`).
