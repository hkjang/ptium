# Ptium v0.41.0

50장짜리 덱을 만들어 성능을 재고, 나온 슬라이드를 한 장씩 늘어놓고 봤습니다. 성능은 문제가
없었고(소스 적용 43ms · 내보내기 19ms · 미리보기 6ms), 대신 **모든 본문 슬라이드에서 같은 것**이
눈에 걸렸습니다.

## 슬라이드의 한 줄 요약이 요점 목록에 섞여 있었습니다

```
• 이 장의 한 줄 요약입니다
• 첫 번째 요점
• 두 번째 요점
```

소스에 `>` 로 적은 **리드**는 그 장이 무엇을 말하는지 한 문장으로 밝히는 줄입니다. 그런데
템플릿 레이아웃에 부제 자리가 없으면 — **대부분의 본문 레이아웃이 그렇습니다** — 리드는 본문
영역의 첫 줄로 들어가면서 **글머리 기호를 달았습니다.** 그러면 요점 중 하나로 읽힙니다.
슬라이드의 층위가 사라지는 것입니다.

이제 본문에 들어간 리드는 **리드로 그려집니다.**

- 글머리 기호가 없습니다. 자리 표시자는 글머리를 템플릿에서 물려받으므로, 내보낸 파일에서
  `buNone` 을 직접 말합니다.
- 아래에 **6pt 의 공기**를 둡니다. 뒤따르는 요점들이 그 문장을 떠받치는 것으로 읽히도록.
  미리보기도 같은 만큼 띄웁니다 — 화면과 파일은 같은 문서여야 하니까요.

## 그리고 왕복에서 요점으로 강등되고 있었습니다

같은 이유로 `>` 리드는 **다시 소스로 쓸 때 `- ` 요점**이 되어 있었습니다. 덱을 열었다 닫을
때마다 리드가 한 단계씩 내려앉는 셈입니다. 이제 리드로 표시된 문단은 `>` 로 되돌아옵니다.

(v0.39에서 고친 것과 같은 종류입니다: 소스는 덱을 설명해야 하고, 왕복은 손실이 없어야 합니다.)

## 확인

- 회귀 테스트 2건: 컴파일된 리드가 표시되어 있고 본문의 맨 앞이며 **`> ` 로 되돌아온다**는 것,
  그리고 내보낸 파일에서 리드만 `buNone` 과 여백을 갖는다는 것.
- 성능(50장): 소스 적용 43ms · 내보내기 19ms(182KB) · 미리보기 6ms · 측정 6ms.
- 전수 점검: api 75 · edges 32 · package · flows 0 실패.
