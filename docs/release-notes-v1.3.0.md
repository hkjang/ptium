# Ptium v1.3.0

링크는 **보는 것** 까지였습니다. 검토의 나머지 절반 — **"4번 슬라이드 이게 틀렸어요"** — 는
여전히 메일로 돌아왔고, 저자는 그 메일을 덱 옆에 띄워 놓고 *"비용 얘기하는 두 번째 장"* 이
어느 장인지 맞춰야 했습니다.

## 의견은 그 슬라이드에 붙습니다

**슬라이드 id 로** 붙습니다. 그래서 덱의 순서를 바꿔도 그 자리에 그대로 있습니다.

이름은 **검토자가 적은 이름** 입니다. 그 사람에게는 계정이 없고, *"이 숫자는 지난 분기
기준입니다"* 한마디 하자고 계정을 만들라고 하는 것이 **검토가 일어나지 않는 방법** 입니다.

## 링크를 연 사람 쪽

슬라이드 아래에서 이름을 한 번 적고(브라우저가 기억합니다) 하고 싶은 말을 씁니다. 아래 레일은
**의견이 달린 장에 점** 을 찍습니다. 링크를 가진 사람들은 **같은 대화** 를 봅니다 — 네 사람에게
보낸 링크라면 원래 그런 것입니다.

## 덱 주인 쪽

편집기에 `의견 3` 처럼 **아직 답하지 않은 수** 가 붙은 버튼이 생겼습니다. 각 의견은 자기
슬라이드 이름을 달고 있고, 누르면 **그 슬라이드로 갑니다.**

반영한 의견은 **사라지지 않고 흐려집니다** — *"그건 이미 고쳤습니다"* 는 같은 검토자가 다음에
물어볼 때 읽을 가치가 있습니다. 지우는 것은 주인의 몫이고, 아무에게도 알림은 가지 않습니다.

## 경계

- **다른 덱의 슬라이드에 다는 의견은 거절** 합니다 — 한 덱의 링크는 다른 덱에 쓰는 방법이
  아닙니다
- 한 덱은 **500건** 까지 받고, 그 뒤로는 그렇다고 답합니다

## 점검

api 스윕이 **낯선 사람으로 의견을 남기고**, 주인이 그것을 읽고, 반영 표시를 하고, 다른 덱의
슬라이드에는 쓰지 못하는 것까지 걷습니다 — **96 checks, 0 failures.** 웹 테스트 56개 통과.

## 설치

오프라인 설치 방법은 [docs/offline-deployment.md](offline-deployment.md) 를 보세요. 이미지에
Postgres 와 nginx 는 들어 있지 않습니다 — 배포할 때 `DATABASE_URL` 로 DSN 을 지정합니다.
