# Ptium v1.57.1

**밀린 큐를 보러 들어간 화면이 "100건"이라고 했습니다. 실제로는 472건이었습니다.**

## 두 관리자 화면이 서로 다른 말을 했습니다

v1.57.0에서 사용 현황 목록을 고친 뒤, 같은 방식으로 나머지 관리자 목록을 봤습니다.
오류·사용자·감사·공유는 모두 `meta.total`로 전체 개수를 함께 내주고 있었습니다.
**생성 큐만 그렇지 않았습니다.**

큐에 240건을 넣고 두 화면을 나란히 봤습니다.

```
개요 화면이 세는 대기열       : 240
큐 화면이 '대기 · 작성 중'이라 함 : 100
```

큐 화면의 세 숫자는 모두 **받아 온 행을 센 것**이고, 받아 오는 행은 최대 100개입니다.
운영자가 "얼마나 밀렸나"를 보러 여는 바로 그 화면이 밀린 정도를 100에서 잘라
말하고 있었습니다. 바로 옆 개요 화면은 제대로 세고 있었으므로, 두 화면이 서로
어긋났습니다.

## 담고 있는 것을 셉니다

목록과 같은 조건으로 `count(*)`를 따로 세어 행 옆에 함께 내줍니다. 화면의 숫자는
그것을 쓰고, 목록이 잘렸을 때는 잘렸다고 적습니다.

```
대기 · 작성 중  240
최근 24시간 실패  0
맡은 워커가 조용하거나 15분 넘게 대기  3 (아래 목록 안에서)

가장 오래 기다린 100건만 아래에 보입니다. 큐에는 모두 240건이 있습니다.
```

"워커가 조용한" 수는 행마다 들여다봐야 알 수 있어 목록 안에서만 셀 수 있습니다.
그래서 **목록 안에서 센 것이라고 적습니다** — 세지 못한 것을 센 척하지 않습니다.

## 답의 모양은 그대로 두었습니다

처음에는 행과 개수를 한 덩어리로 묶어 `data`를 객체로 바꿨습니다. **api 점검이 바로
걸렸습니다** — 큐를 목록으로 읽던 곳이 객체를 받았기 때문입니다. 다른 관리자 목록이
이미 하는 대로, `data`는 행 그대로 두고 개수는 `meta`에 넣었습니다.
