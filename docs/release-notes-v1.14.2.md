# Ptium v1.14.2

## 어제 막은 문의 옆문 (보안)

1.14.1 은 "키는 자기가 갖지 않은 권한을 줄 수 없다" 를 넣었습니다. 그 고침을 다시
두들겨 보니, **범위를 아예 적지 않으면** 그대로 통과했습니다.

```
프레젠테이션 "조회"만 가진 키로:
  POST /api/v1/api-keys  {"name": "자식 키"}    ← scopes 를 안 씀
  → 201, 발급된 키의 권한: [조회, 편집, 템플릿 조회, MCP]   ← 기본값
  → 그 키로 덱 생성: 성공
```

범위를 안 적으면 배포본의 **기본 권한**이 붙는데, 기본에는 편집이 들어 있습니다. 어제의
검사는 "요청에 적힌 것" 을 봤고, 적힌 것이 없으니 볼 것도 없었습니다. 판정해야 하는 것은
**그 키가 실제로 갖게 될 권한**입니다.

이제:

- **사람**이 범위 없이 만들면 예전처럼 배포본 기본값입니다
- **키**가 범위 없이 만들면 **그 키 자신의 권한**을 물려줍니다 — 안전하고, 자동화하는
  사람이 원하는 동작이기도 합니다
- 어느 쪽이든 실제로 부여될 권한을 놓고 1.14.1 의 규칙을 다시 확인합니다

## 검사

- 좁은 키가 범위 없이 키를 만들면 그 키에 편집 권한이 있으면 안 됩니다 (tenancy 99 checks)
- 고침을 빼면 이 검사가 `[조회, 편집, 템플릿 조회, MCP]` 로 실패합니다
- 사람이 범위 없이 만들면 여전히 기본 4종을 받습니다

## 설치

```bash
gzip -dc ptium-1.14.2.tar.gz | docker load
```
