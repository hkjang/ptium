# Ptium v1.46.0

**"2024년 4분기 PoC 시작" — 오늘은 2026년 8월입니다.**

## 프롬프트로는 막지 못했습니다

1.45.0에서 "계획은 오늘부터 앞으로 간다"는 규칙을 프롬프트에 넣었지만, 효과를
입증하지 못했다고 적었습니다. 그 뒤로도 모델은 계속 이렇게 씁니다:

```
슬라이드 8: 결정 요청: 전환 프로젝트 즉시 승인
  · 2024년 4분기 PoC 시작을 위한 즉시 조치 필요
```

브리프가 목표를 2026년 3분기로 못박았고, 프롬프트가 오늘 날짜를 알려 줬는데도
**첫 단계가 방을 2년 뒤에 두고 시작합니다.** 그리고 제품은 아무 말도 하지 않았습니다.

모델에게 부탁하는 것으로 안 되면, **재는 수밖에 없습니다.**

## `stale` — 이미 지난 날짜로 세운 계획

두 가지 신호 중 하나라도 있어야 지적합니다.

1. 지난 연도 + **앞으로의 일을 말하는 말**(시작·착수·예정·계획·추진·즉시·kick-off·launch)
2. 지난 연도로 **시작하는 일정 줄이 한 장에 둘 이상** — `Q4 2024: PoC 수행` 처럼
   "하겠다"는 말 없이 언제인지만 적는 로드맵 형식

그리고 **이미 일어난 일은 지적하지 않습니다**: 했·였·었·지난·완료된·completed가
있으면 그 줄은 기록입니다.

## 과하게 울리지 않는지 재 봤습니다

지난 일을 다루는 브리프로 오프라인 덱을 만들어 확인했습니다.

| 브리프 | 지적 |
| --- | --- |
| AI 엔지니어링팀 1분기 업무 성과와 2분기 계획 | 0 |
| 2024년 매출 실적과 2025년 상반기 추이 | 0 |
| 지난해 장애 사례와 재발 방지책 | 0 |
| 클라우드 비용 최적화 3개년 로드맵 | 0 |

한 장에 날짜로 시작하는 줄이 **하나뿐이면** 일정으로 보지 않습니다 — 실적 장이
`2024년: 매출 120억` 처럼 연도를 앞세우는 것은 흔한 일이기 때문입니다.

## 실제로 잡습니다

같은 브리프로 모델 덱 네 개를 만들어 보니 지난 연도를 담은 덱이 셋, 그중 **셋 모두**
지적됐습니다.

```
"PMO 조직 구성 및 2024 Q4 착수" — 2024년은 이미 지났습니다
"2024 Q4: POC 및 3개 DB 전환 완료" — 2024년은 이미 지났습니다
"2025년 4분기: 12개 DB 중 4개 시스템 PoC" — 2025년은 이미 지났습니다
```

편집기에서는 `이미 지난 날짜로 계획함` 으로 보이고, 무엇을 고쳐야 하는지 그 줄을
그대로 보여 줍니다.
