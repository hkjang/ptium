# Ptium v1.6.1

지난 판에서 만들다 만 검사 — "슬라이드가 가진 글자가 그림에 다 있는가" — 를 제대로 세웠습니다.
저장된 덱 **8,271장** 에 돌렸고, **진짜 하나** 가 남았습니다.

## 여섯 번째 단계는 어느 슬라이드에도 없었습니다

```
::steps
| Phase | Action
| 1 | Assess current manual dispatch inefficiencies
| 2 | Define the dedicated scheduling system solution
| 3 | Compare alternatives against the new system
| 4 | Outline the two-phase implementation roadmap
| 5 | Calculate the financial impact of the investment   ← 그려지지 않음
::
```

단계 컴포넌트는 한 줄에 **5개까지** 그립니다. 슬라이드 폭에 여섯 칸을 늘어놓으면 읽을 수 없으니
합리적인 설계입니다. 문제는 **말을 안 한다는 것** 이었습니다. 작성자는 여섯을 썼고, 다섯이
그려졌고, **아무도 여섯 번째가 빠졌다고 알려 주지 않았습니다.** 하필 그게 "재무 영향을
계산한다" 였습니다.

## 이제 몇 개 중 몇 개인지 말합니다

측정에 **"일부가 안 그려짐"** 을 더했습니다.

> 단계 컴포넌트가 6개 중 5개만 그립니다. 나머지는 어느 슬라이드에도 없습니다

고정된 한도가 있는 컴포넌트만 대상입니다 — 단계 5, 달성률 5, 타임라인 6, 비교 카드 3.
**자리에 따라 달라지는 것은 세지 않습니다.** 숫자를 모르면서 아는 척하는 지적이 되니까요.

점수에서는 **가독성** 축의 조언이고 가중치 **10** 입니다. 빽빽한 것(6)보다 무겁고, 출처 없는
숫자(12)보다 가볍습니다 — **없는 것은 빽빽한 것보다 나쁩니다.**

## 오탐을 두 번 걸러 냈습니다

1,019개 덱 census 를 세 번 돌렸습니다.

| 무엇을 셌나 | 걸린 덱 |
|---|---|
| 처음 (모든 컴포넌트에 한도 적용) | 7 |
| 비교 **행렬** 은 행 단위로 다 그린다는 걸 반영 | 3 |
| 자리에 따라 달라지는 한도(8)는 세지 않기로 | **2** |

남은 2건은 **그림을 직접 확인** 했습니다. 여섯 번째 단계가 정말 SVG 에 없습니다.

## 검사기 자체의 오류도 걸러 냈습니다

"그림에 없는 글자" 검사는 처음에 24장을 지적했는데, 대부분 **검사기가 틀린 것** 이었습니다 —
추이 차트는 눈금 이름을 `"1월, 2월, 3월"` 한 덩어리로 보관하고 그릴 때 하나씩 나눠 그립니다.
덩어리째 찾으면 당연히 없습니다. 쉼표·구분자로 **쪼갠 뒤 조각마다** 확인하도록 고쳤고,
잘려 그려질 수 있는 긴 글은 **앞부분으로** 맞춰 봅니다.
