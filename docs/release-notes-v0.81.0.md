# Ptium v0.81.0

모델이 목차 슬라이드의 **첫 항목을 리드 줄에** 썼습니다.

```
# 목 차
@content
> 1. 시장 성장과 시스템 리스크
- 2. 장애 현황 및 영향 분석
- 3. 이중화 투자 계획
- 4. 투자 대비 위험 비용 비교
- 5. 승인 요청 및 일정
```

그대로 그리면 `1.` 만 **불릿 없이, 리드의 굵기로** 목록 위에 앉고 `2.`~`5.` 가 목록 전체처럼
보입니다. 부제 영역이 있는 레이아웃이었다면 더 나빴을 겁니다 — **1번 항목만 부제로 떨어져**
나머지 목록과 슬라이드 반대편에 놓입니다.

**번호가 전부인 슬라이드에서 번호가 깨집니다.**

## 리드가 아니라 첫 항목입니다

리드가 `1.` 이고 첫 요점이 `2.` 라면 그건 리드가 아닙니다. 목록의 첫 항목입니다. 목록으로
돌려보냅니다.

| 항목 번호로 봄 | 아님 |
|---|---|
| `1.` `2)` `③` `12.` | `1.5배 늘었다` |
| | `2026년 상반기` |
| | `12억 원 요청` |

숫자로 시작하는 리드가 전부 끌려 내려가지 않도록, **두 자리까지의 항목 번호** 만 항목으로
읽습니다.

## 확인

문제를 만든 그 덱을 다시 컴파일했습니다.

```
body ["1. 시장 성장과 시스템 리스크", "2. 장애 현황 및 영향 분석",
      "3. 이중화 투자 계획", "4. 투자 대비 위험 비용 비교",
      "5. 승인 요청 및 일정"]
```

다섯 항목이 **하나의 목록** 으로 그려집니다.

## 덤: 우리 점검 스크립트가 거짓말을 했습니다

api 스윕이 "등록한 슬라이드가 사용으로 집계되지 않았다" 며 실패했습니다. 확인해 보니
`useCount` 는 **정상적으로 1** 이었습니다. 스크립트가 라이브러리 목록의 **첫 100줄만** 읽었고,
즐겨찾기가 101개 쌓인 작업 공간에서는 새 슬라이드가 그 앞쪽 페이지 밖으로 밀려나 있었을
뿐입니다. 이제 **id 로 직접** 물어봅니다. 스스로를 못 믿게 만드는 점검은 없느니만 못합니다.

## 설치

오프라인 설치 방법은 [docs/offline-deployment.md](offline-deployment.md) 를 보세요. 이미지에
Postgres 와 nginx 는 들어 있지 않습니다 — 배포할 때 `DATABASE_URL` 로 DSN 을 지정합니다.
