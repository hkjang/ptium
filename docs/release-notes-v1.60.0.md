## 별표가 벽에 찍혔습니다

```
그려진 슬라이드:  • **이 부분은 굵게 ***이 부분은 기울임 *이 부분은 그냥
내보낸 PPTX:      같은 글자 그대로 · b="1"(굵게) 0회
```

작성자가 굵게 써 둔 것이 **굵은 글씨가 아니라 별표 문자**가 되어 슬라이드에 찍히고,
내보낸 파일에도 그대로 나갔습니다. 강조는 사라졌습니다.

## 마침표 하나 차이였습니다

읽는 쪽은 멀쩡했습니다. `readEmphasis`는 **공백으로 닫히는 표시를 강조로 읽지
않습니다** — 모든 마크다운 리더가 지키는 규칙입니다.

```go
if strings.Contains(inner, "\n") || strings.HasSuffix(inner, " ") {
    return "", "", 0, false      // "a * b * c"는 곱셈이지 기울임이 아니다
}
```

쓰는 쪽이 그 규칙을 어기고 있었습니다. 파워포인트의 글 조각은 **다음 조각과 띄우는
공백을 자기 안에 갖고** 있습니다 — `"이 부분은 굵게 "`. 가져오기는 그 공백째로
표시를 둘렀습니다.

```
쓴 것:  **이 부분은 굵게 **      ← 공백으로 닫힘 → 읽는 쪽이 거절
고침:   **이 부분은 굵게** ' '   ← 공백은 표시 밖으로
```

고친 뒤:

```
소스:        - **이 부분은 굵게** *이 부분은 기울임* 이 부분은 그냥
그려진 글:    이 부분은 굵게 이 부분은 기울임 이 부분은 그냥   (별표 없음)
내보낸 파일:  b="1" '이 부분은 굵게' · i="1" '이 부분은 기울임' · 보통 나머지
```

파워포인트 → Ptium → 파워포인트를 지나 강조가 그대로 돌아옵니다.

## 검사가 이걸 놓친 이유

`TestAnImportedDeckKeepsItsLinksAndEmphasis`는 이미 있었고, 고치기 전에도
통과했습니다. 그 검사는 마크업을 **사람이 손으로 올바르게 적어** 넣습니다 —
`"**전환 대상** 42개와 *검토 중* 3개"`. 즉 **읽는 쪽만** 시험하고, 결함이 있던
**쓰는 쪽**은 한 번도 지나가지 않았습니다.

새 검사 3건은 `markedUpRun`이 쓴 것을 그대로 `SplitRuns`에 먹입니다. 공백을 표시
안으로 되돌리면 물립니다.
