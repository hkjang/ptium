# Ptium v1.30.1

어제(1.30.0) **다듬기가 안 될 때 덱을 잃지 않도록** 고쳤습니다. 그런데 어제 만든
두 가지가 남아 있었습니다.

## 같은 안내가 누를 때마다 쌓였습니다

```
1번 누름 → 안내 1개
2번 누름 → 안내 2개   (같은 문장)
3번 누름 → 안내 3개   (같은 문장)
```

편집기 안내 패널이 같은 문단으로 채워집니다. 이제 **덱이 이미 갖고 있는 문장은 다시
쓰지 않습니다.**

## 애초에 대기열에 넣지 않습니다

이 배포가 이미 아는 답을 위해 **대기열에 넣고, 워커가 집어가고, 실패시키고, 안내를
남기는** 과정을 거칠 이유가 없습니다. 사용자는 그동안 회전하는 표시를 봅니다.

이제 **누르는 즉시** 답합니다.

```
POST /presentations/{id}/generate  →  422 rewrite_needs_model
"덱을 다시 쓰려면 연결된 AI 모델이 필요합니다. 이 배포는 브리프로 새 덱을 쓰는 내장
 생성기만 갖고 있어서, 이미 있는 덱은 다시 쓰지 못합니다. 덱은 그대로입니다."
```

- 글이 있는 덱(다시 쓰기)에만 해당합니다. **글이 없는 덱은 그대로 생성됩니다** —
  실패한 덱의 "생성 다시 시도"도 그대로 동작합니다.
- **MCP로 연결한 에이전트도 같은 답**을 받습니다. 폴링하며 기다리지 않습니다.
- 모델이 연결된 배포는 아무것도 달라지지 않습니다.

## 검사

- 모델이 연결되었는지 판단하는 네 가지 경우(출고 상태 · 키 없는 제공자 · 키 있는
  제공자 · 설정 없음)를 고정했습니다.
- REST 훑기가 완성된 덱에 다시 쓰기를 시켜, **422면 문구를 확인하고**, 어느 쪽이든
  **덱이 슬라이드를 잃지 않았는지** 확인합니다.
- OpenAPI에 422 `rewrite_needs_model`을 적었습니다.

전체 Go 테스트 · REST 585개 · 화면 훑기 · deep 0 failures.
