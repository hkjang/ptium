# Ptium v1.13.0

관리자 화면에 두 가지가 생깁니다. 둘 다 **이미 데이터베이스에 있던 것을 꺼내는 일**이고,
둘 다 운영자가 물어보는 질문에 답하지 못하던 자리입니다.

## 감사 기록을 읽을 수 있습니다

이 서버는 **서른다섯 군데에서** 감사 기록을 씁니다 — 설정 변경, 덱 생성·삭제, 키 발급·회수,
사용자 권한 변경, 템플릿 등록. 그리고 **읽는 길이 하나도 없었습니다.** "누가 AI 제공자를
켰나", "그 덱은 누가 지웠나" 는 psql 로만 답할 수 있는 질문이었습니다.

`관리자 → 감사 기록` 이 생겼습니다. 운영자가 실제로 들고 오는 세 가지 질문 그대로 거릅니다:

- **무슨 동작** — `presentation` 이라고 치면 덱과 관련된 모든 기록, `presentation.delete` 면 삭제만
- **누가** — 이메일이나 사용자 id
- **무엇에** — 대상 종류, 또는 그 한 덱의 id

기간은 오늘·7일·30일·1년이고, 검색은 동작·대상·행위자·**함께 기록된 값**까지 훑습니다.
행위자는 uuid 가 아니라 **이메일과 이름으로** 보여 줍니다 — 사람은 주소로 알지 uuid 로 알지
않습니다. 한 줄을 열면 그때 함께 기록된 값이 그대로 나오고, 거기서 "이 행위자의 기록" ·
"이 대상의 기록" 으로 바로 넘어갑니다.

덱 하나의 일생이 이렇게 읽힙니다:

```
20:14:57  presentation.trash          by ops@example.com
20:14:57  presentation.source_update  by ops@example.com
20:14:57  presentation.create         by ops@example.com
```

API 로도 열려 있습니다(관리자 전용): `GET /api/v1/admin/audit`, `GET /api/v1/admin/audit/actions`.

## 개요가 "생성이 돌고 있는지" 를 말합니다

대기 건수만으로는 아무것도 알 수 없습니다. **12건이 방금 들어온 바쁜 아침**과 **한 건이 세
시간째 멈춰 있는 죽은 작업자**가 같은 숫자로 보입니다. 둘을 가르는 건 *가장 오래 기다린
것의 나이* 입니다.

개요에 생성 상태가 붙습니다:

- 가장 오래 기다린 덱이 몇 분째인지 — 15분을 넘기면 **"멈춤 의심"**
- 최근 24시간 실패 건수
- 마지막으로 완성된 덱이 언제인지

## 확인

- 저장소 테스트: 한 대상의 기록이 **최신순**으로 오는지, 행위자가 **사람으로** 읽히는지,
  동작·행위자·대상·기간·검색 필터가 각각 맞는지. 네 가지를 하나씩 되돌려 전부 무는지 확인
- 스윕이 API 계약을 지킵니다: 덱 하나를 만들고 지운 뒤 그 기록이 남는지, 최신순인지,
  행위자가 이름으로 읽히는지, 그리고 **관리자 역할이 없는 계정은 403** 인지 (290 checks)
- 화면 스윕이 새 페이지를 방문합니다
