# Ptium v1.24.1

어제 브랜드 색상이 그림에 닿게 만들었습니다. **그 다음 날 할 일은 그것이 누구의 덱에
닿았는지 보는 것**입니다.

## 아무도 고르지 않은 보라색이 모든 덱을 칠할 뻔했습니다

색을 지운 프로필로 덱을 만들어 봤습니다.

```
슬라이드마다 accent: #7C3AED   ← 개인 설정에는 아무 색도 없는데
미리보기에서 그 색으로 그려진 장: 있음
```

`#7C3AED` 는 **이 제품이 처음 심어 두는 기본값**입니다. 브랜딩 화면을 한 번도 열지 않은
배포에도 그대로 들어 있습니다. 어제까지는 이 값을 **아무도 읽지 않아서** 아무 일도 없었는데,
그림이 읽기 시작한 순간 — **회사 템플릿으로 만든 모든 덱의 컴포넌트가 아무도 고르지 않은
보라색으로** 칠해집니다.

이 제품의 가장 큰 약속은 그 반대입니다. **업로드한 템플릿의 색은 그 회사의 것입니다.**

## 고른 색만 칠합니다

- **사람이 고른 색**(개인 설정의 브랜드 색상) → 컴포넌트에 적용
- **배포가 고른 색**(관리자가 브랜딩 화면에서 바꾼 값) → 적용
- **제품이 심어 둔 기본값** → **적용하지 않음.** 템플릿의 색이 그대로 남습니다
- 아무 데도 색이 없으면 → 예전 그대로

```
색을 고르지 않았을 때: 슬라이드 accent 없음 · 그려진 장 없음   ← 템플릿 그대로
개인 색을 골랐을 때  : accent #0F62FE · 2번 장에 적용
```

## 왜 이렇게까지

색 하나가 **모든 덱의 모든 컴포넌트**에 닿습니다. 어제 고친 것이 오늘 조용히 회사 템플릿을
덮어쓰는 일은, 다음 날 실제로 만들어 보지 않으면 알 수 없습니다.

## 검사

네 가지를 고정했습니다 — 심어 둔 기본값(칠하지 않음) · 배포가 고른 색(칠함) · 사람이 고른
색(둘보다 우선) · 아무것도 없을 때. 되돌리면 그 자리에서 실패합니다.
