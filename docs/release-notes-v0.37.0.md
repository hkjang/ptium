# Ptium v0.37.0

지난 판에서 영어 덱을 고치며 남겨 둔 것 — **일본어와 중국어** — 를 이번에 했습니다. 같은
브리프를 네 언어로 넣고 나온 덱을 나란히 놓고 봤습니다.

## 띄어쓰기가 없는 언어에서는 규칙이 하나도 작동하지 않았습니다

브리프를 읽는 코드는 전부 **단어 단위**입니다. 그런데 일본어·중국어 문장을 단어로 쪼개면
문장 하나가 통째로 한 단어입니다. 그래서 아무것도 다듬어지지 않았고, 길이를 맞추려는 자르기는
**단어 한가운데**에 떨어졌습니다.

`決済プラットフォームを二つのリージョンに冗長化する計画。目標可用性99.95%、予算4億、3段階で移行。`

이 브리프로 만든 덱은 이랬습니다.

| 전 | 후 |
| --- | --- |
| 표지: `予算4億, 3段階で移行` | 표지: `決済プラットフォームを二つのリージョンに冗長化する計画` |
| 제목: `予算4億` (숫자가 제목) | `::kpi` 카드: `予算 \| 4億` |
| 제목: `つのリージョンに…` (단어 중간에서 잘림) | `二つのリージョンに冗長化する計画` |
| 리드: `の現在地を整理します。` | `現在地を整理します。` |

바뀐 것은 네 가지입니다.

- **자를 자리를 문자로 찾습니다.** 조사(を·は·が·に·で·と, 的·和·在·为…)와 문장부호가 절의
  경계이고, 문구는 거기서만 끊깁니다. 단어 한가운데로는 떨어지지 않습니다.
- **문장 끝을 압니다.** `。！？` 뒤에 공백이 없어도 문장이 끝난 것으로 읽습니다. 이전에는
  공백을 요구해서 브리프 전체가 한 문장이었습니다. 표지 제목은 **첫 문장**에서 끊습니다.
- **그 언어의 단위를 읽습니다.** 億·亿·万·円·元·人·件·個·个·か月·小时… 그리고 億円·亿元 같은
  조합까지. 브리프가 준 숫자가 이제 제목이 아니라 지표로 들어갑니다.
- **주어가 빠진 자리의 조사를 함께 지웁니다.** 제목이 이미 말한 주어를 리드에서 덜어 내면
  `の`나 `を`가 남았습니다. 일본어는 주어를 생략해도 되는 언어라, 조사까지 지우면 문장이 됩니다.

## 세 바이트짜리 문자를 한 바이트로 세고 있었습니다

숫자 앞의 이름을 읽을 때 구분자를 건너뛰는 코드가 **바이트 위치**로 계산하고 있었습니다.
`、`는 세 바이트입니다. 그래서 지표 이름이 `<0xFFFD>予算`으로 나왔습니다 — 한국어에서는 쉼표가
한 바이트라 드러나지 않던 버그입니다. 그리고 소수점은 이제 절의 경계가 아닙니다: `99.95%`가
`99.` 과 `95%`로 갈라지던 것을 막습니다.

## 확인

- 회귀 테스트 2건 추가(일본어·중국어): 표지 제목, 지표 카드, **숫자가 제목이 되지 않을 것**,
  리드가 조사로 시작하지 않을 것, 그리고 라벨이 온전한 문자일 것.
- 한국어·영어 덱은 기존 회귀 테스트 그대로 통과합니다.
- 전수 점검: api 75 · package 0 실패.
