# Ptium v0.43.0

같은 덱을 **50가지 기본 디자인 전부에** 지어 넣고, 측정하고, 눈으로 봤습니다. 측정은 결함 0을
보고했습니다. 눈은 두 가지를 봤습니다 — **둘 다 작성자가 쓴 것이 조용히 사라지는 종류**였고,
50개 디자인 전부에서 똑같이 일어나고 있었습니다.

## 인용문이 문장 한가운데서 잘렸습니다

> 데이터 처리 속도는 단순한 기술 지표가 아니라 시장 변화에 얼마나 빠르게 대응할 수 있는지를
> 결정하는 **핵심**

`::quote` 로 쓴 한 문장이 컴포넌트의 **항목 이름**으로 실려 다녔고, 항목 이름은 60자에서
잘립니다. 인용문은 이름이 아니라 문장입니다. 이제 항목 하나짜리 인용·강조는 문장으로 옮겨져
**300자까지** 갑니다. 위 문장은 이제 `…결정하는 핵심 경쟁력입니다` 로 끝납니다.

## 여섯 개를 적으면 네 개만 그려졌습니다

지표 카드는 한 줄에 최대 넷이고, **다섯 번째부터는 말없이 버려지고** 있었습니다. 작성자가 찾아
적은 숫자입니다.

이제 긴 줄은 **접힙니다.** 다섯·여섯 개는 3+3, 일곱·여덟 개는 4+4로 두 줄이 되고, 카드 높이는
두 줄이 들어갈 만큼 줄어듭니다. 한 줄에 여섯 개를 욱여넣어 여섯 조각을 만드는 대신, 사람이
그렇게 놓듯 두 줄로 놓습니다.

## 측정이 못 보던 것

두 가지 다 **측정을 통과했습니다.** 잘린 인용문은 영역 안에 잘 들어가 있었고, 사라진 지표는
그려진 적이 없으니 넘칠 일도 없었습니다. 측정은 "그려진 것이 제자리에 있는가"를 보고, 이번 것은
"작성자가 준 것이 그려지기는 했는가"였습니다. 그래서 50장씩 늘어놓고 보는 일을 계속합니다.

## 확인

- 회귀 테스트 2건: 여섯 지표가 **모두** 그려지고 **두 줄**이 된다는 것, 그리고 60자가 넘는
  인용문이 온전히 남는다는 것.
- 50개 디자인 · 9장 덱(지표·차트·표·단계·인용 포함) 측정: 결함 0 · 컴파일 경고 0.
- 전수 점검: api 75 · edges 32 · package 0 실패.
