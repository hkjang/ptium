# Ptium v0.25.0

## 표가 진짜 표로 나갑니다

Ptium은 모든 컴포넌트를 직접 그립니다. 그래야 미리보기와 내보낸 파일이 **똑같기** 때문입니다.
그런데 표에서는 그 선택이 틀렸습니다. `::table`을 쓰면 PowerPoint에는 **도형 15개와 사각형
26개**가 열렸습니다. 숫자 하나 고칠 수 없고, 행을 더할 수 없고, 다른 문서로 복사하면 표가
아니라 도형 뭉치가 붙었습니다. **표의 사진**이었습니다.

이제 **PowerPoint에서 편집 가능한 진짜 표**로 나갑니다.

- 생김새는 그대로입니다 — 상자 없는 편집형 표, 머리글 아래 굵은 선, 행 사이 얇은 선, 이름은
  왼쪽·숫자는 오른쪽, 디자인의 글꼴과 색.
- **그룹 밖에 놓습니다.** PowerPoint는 그룹 안의 표에 들어가지 못하게 합니다. 캡션은 도형으로
  옆에 남습니다.
- 셀 수정 · 행 추가 · 표 스타일 적용 · 워드나 메일로 복사 — 전부 됩니다.

### 짧은 표가 늘어지지 않습니다

행이 영역 전체를 나눠 가져서, 세 줄짜리 표가 슬라이드 반쪽에 흩어져 **표가 아니라 떠 있는 세
줄**로 보였습니다. 행 높이에 상한을 두어 짧은 표는 위에 모입니다. 그리는 쪽과 내보내는 쪽이
**같은 계산**을 쓰므로 둘이 어긋날 수 없습니다.

## 우리가 만든 파일을 남의 도구로 읽습니다

.pptx를 Ptium이 직접 씁니다. 그렇다면 정직한 검증은 **우리 코드가 아닌 것으로 읽어 보는
것**입니다. 전수 점검에 `scripts/e2e/package.py`를 더했습니다 — `python-pptx`(PowerPoint와
같은 OOXML을 파싱합니다)로 내보낸 파일을 열어 확인합니다.

- 표가 **표**로 읽히는가 (3×3, 머리글 `항목 · 1분기 · 2분기`)
- 표가 그룹 안에 있지 않은가
- 발표자 노트가 노트로 읽히는가
- 표지에는 페이지 번호가 없고, 본문에는 있는가
- 슬라이드 제목이 제목 자리 표시자로 읽히는가

실측: 27KB · 3장 · 표 1개(3×3) · 노트 1장 · 표지 번호 없음 — **0 실패**.

> 마무리 레이아웃처럼 **마스터 도형을 끄는 디자인**에는 번호가 들어가지 않습니다. 전면 배경을
> 직접 칠하는 페이지에 번호 자리를 두지 않은 것은 디자이너의 결정이고, PowerPoint도 같은 결과를
> 냅니다.
