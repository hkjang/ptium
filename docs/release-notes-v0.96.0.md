# Ptium v0.96.0

**모델을 켜 두자 스윕이 실패했습니다.**

```
✗ generation wrote its own version of a slide the library already had
```

라이브러리에 등록해 둔 슬라이드가 있는데 덱이 **자기 버전을 썼습니다.** 이 점검은 지금까지
**항상 오프라인** 으로만 돌았습니다 — 오프라인 작성기는 브리프의 말을 제목에 그대로 쓰기 때문에
매칭이 쉬웠고, 정작 **중요한 경로는 한 번도 검증된 적이 없었습니다.**

세 가지가 잘못돼 있었습니다.

## 1. 덱에게 라이브러리가 있다고 말한 적이 없습니다

치환은 슬라이드 **제목** 과 등록된 이름을 맞춰 봅니다. 그런데 모델은 회사 소개 슬라이드에
자기 마음대로 제목을 답니다.

이제 **두 패스 모두** 등록된 이름을 받습니다. 그리고 **브리프가 직접 그 이름을 부른 경우** —
저자가 대놓고 요청한 경우 — 는 "그 슬라이드를 **정확히 그 제목으로** 반드시 넣어라" 라고
말합니다.

## 2. "제목의 절반" 규칙을 바이트로 세고 있었습니다

한글 한 글자는 **3바이트**, 숫자는 **1바이트** 입니다. 그래서 `보안 아키텍처 475660` 은
무게로 치면 **3분의 2가 id** 입니다.

덱이 슬라이드를 `보안 아키텍처 475660의 2026 전략적 중요성` 이라고 이름 붙였을 때 —

```
바이트로: 24 × 2 = 48  <  49   → 안 맞음 (1바이트 차이!)
글자로:   12 × 2 = 24  ≥  23   → 맞음
```

**1바이트 차이로** 등록된 슬라이드 대신 새로 쓴 것입니다. 이제 **글자 수** 로 셉니다.

## 3. 이름 끝의 숫자는 이름이 아닙니다

`회사 소개 471936` 로 등록된 슬라이드를 덱이 `회사 소개` 라고 쓰면 이제 찾습니다 — **그
줄기(stem)를 가진 슬라이드가 하나뿐일 때만.** `매출 2025` 와 `매출 2026` 은 둘 다 `매출` 로
줄어드니, 그때는 **아무것도 치환하지 않습니다.** 잘못 바꾸는 것은 안 바꾸는 것보다 나쁩니다.

## 정직하게

실제 모델에서는 이제 덱이 그 슬라이드를 **알아볼 수 있게 이름 붙이는 경우가 더 많아졌지만,
매번은 아닙니다.** 제목은 결국 모델이 쓰는 문장입니다.

## 설치

오프라인 설치 방법은 [docs/offline-deployment.md](offline-deployment.md) 를 보세요. 이미지에
Postgres 와 nginx 는 들어 있지 않습니다 — 배포할 때 `DATABASE_URL` 로 DSN 을 지정합니다.
