# Ptium v1.33.0

관리자 고도화 첫 번째 — **설정 변경 감사와 되돌리기**입니다.

## 지금까지 남던 기록

설정을 실제로 바꾸고 감사 기록을 읽어 봤습니다.

```json
{"action":"settings.update_batch","metadata":{"count":1}}
```

**무엇이 바뀌었는지, 이전 값이 무엇이었는지, 아무것도 없습니다.** "지난달에 누가 자동
수정을 껐고 원래 몇이었나"를 이 기록으로는 답할 수 없습니다. 이 설정들은 이 배포에서
만들어지는 **모든 덱이 어떻게 쓰이는지**를 정하는 값입니다.

## 이제 남는 기록

```
응답 제한 시간        300 → 600      Ptium Developer · 1초 전   [되돌리기]
생성 후 자동 수정      7 → 3          Ptium Developer · 5분 전   [되돌리기]
API 키              값이 바뀌었습니다 — 비밀 값은 기록하지 않습니다   되돌릴 수 없음
```

- 설정 **하나마다 한 줄**: 키 · 이전 값 · 새 값 · 누가 · 언제.
- **비밀 값은 기록하지 않습니다.** 바뀌었다는 사실과 누가 바꿨는지만 남습니다.
- 화면을 저장하면 모든 칸이 함께 전송되는데, **그대로 돌아온 값은 변경으로 기록하지
  않습니다.**

## 되돌리기

기록을 읽고 예전 값을 손으로 다시 타이핑하는 자리가 두 번째 실수가 나는 자리입니다.
**[되돌리기]** 한 번이면 이전 값으로 돌아갑니다.

- 되돌리는 값도 **다른 변경과 똑같이 검증**합니다(범위를 벗어나면 거절).
- 되돌린 것 자체도 **변경으로 기록**됩니다 — 누가 되돌렸는지 남습니다.
- 비밀 값(`secret_not_recorded`)과 이전 값이 없는 변경(`nothing_to_revert`)은
  되돌릴 수 없다고 말합니다.

## 어디에 있나

**서비스 설정** 화면 아래 **"최근 설정 변경"** 패널. API로는 —

```
GET  /api/v1/admin/settings/changes?limit=8[&key=ai.timeout_seconds]
POST /api/v1/admin/settings/changes/{id}/revert
```

## 검사

- REST 훑기: 변경이 기록되는지, **이전 값이 실제 값과 같은지**, 누가 했는지 남는지,
  되돌리면 값이 돌아오는지, **비밀 값이 기록에 새어 나가지 않는지**, 비밀은 되돌리기가
  거절되는지. 기록을 빼 보면 세 자리에서 실패합니다.
- 화면: 값이 사람 말로 보이는지(사용/사용 안 함/없음/비어 있음), 되돌릴 수 있는 것과
  없는 것을 가르는지 단위 테스트로 고정했습니다.
- 실제 화면에서 되돌리기를 눌러 값이 돌아오는 것을 확인했습니다.
