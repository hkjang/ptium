# Ptium v1.7.0

지난 판에서 설계 단계 한 번이 **302초** 걸리는 걸 봤습니다. 기본 제한 시간이 **300초** 입니다.
그 숫자를 맞추러 갔다가, 맞출 필요가 없다는 걸 알았습니다.

## 문 두 개, 경비원 한 명

모델에게 "생각하지 말고 답하라"고 요청하는 스위치가 있습니다(`ai.reasoning`). 덱을 **쓰는**
패스는 이 스위치를 보냅니다. 덱을 **설계하는** 패스는 다른 함수를 거쳤고, **그 함수는 스위치를
보내지 않았습니다.**

같은 프롬프트, 같은 모델, 스위치만 다르게 해서 재 봤습니다.

| 설계 패스 | 시간 | 출력 토큰 | 결과 |
|---|---|---|---|
| 스위치 **없이** (기존 동작) | **302초** | **6,495** | 2,634자 |
| 스위치 **보내고** | **65초** | **1,349** | 3,104자 |

**300초 제한 시간에 302초짜리 요청** 을 보내고 있었습니다. 8,000 토큰 예산의 **81%** 를 한
번에 쓰고 있었습니다. 이 세션 내내 붙어 있던 "구성을 먼저 설계하는 단계를 건너뛰고 바로
썼습니다" 알림의 정체가 이것입니다 — **관리자가 고른 설정이 한쪽 문에서만 지켜지고 있었습니다.**

이제 **문이 하나** 입니다. 두 패스가 같은 함수를 거치고, 스위치를 보내지 않던 우회로는
지웠습니다. 어느 쪽 한 곳만 고쳐도 다시 어긋나지 않도록 **두 패스를 함께 검사하는 테스트** 를
붙였습니다.

## 결과

기본 제한 시간 **300초 그대로** 두고 같은 브리프를 태웠습니다.

| | 전 | 후 |
|---|---|---|
| 9장 덱 생성 전체 | 420~480초 | **110초** |
| 설계 단계 | 자주 버려짐 | **통과** |
| 점수 | 94~96 | **98** |

제한 시간을 늘릴 필요가 없었습니다. **요청이 4배 빨라졌습니다.**

## 설정 설명도 고쳤습니다

`ai.timeout_seconds` 의 설명은 "자체 호스팅 모델은 수십 초면 답합니다" 였습니다. 재 보니
생각을 켜면 5분이 넘습니다. 이제 실제 측정값으로 적혀 있습니다.

그리고 **설명은 기존 설치에도 갱신** 됩니다. 지금까지는 새로 설치할 때만 반영돼서, 틀린 설명을
고쳐도 이미 쓰는 곳은 계속 옛 설명을 읽고 있었습니다. **값은 절대 건드리지 않습니다** —
관리자가 정한 것은 관리자의 것입니다.
