# Ptium v1.49.0

**인쇄도 같은 방식으로 서버를 죽였습니다.**

## 1.48.1에서 템플릿을 막고 나니, 같은 질문이 남았습니다

설치 문서는 파드 메모리를 쓰는 곳으로 **두 가지**를 듭니다 — 템플릿 분석과 인쇄.
템플릿 쪽은 1.48.1에서 막았습니다. 인쇄 쪽은 아무것도 막고 있지 않았습니다.

```
사진이 매 장에 있는 40장짜리 덱 8개를 동시에 인쇄
  →  8개 중 0개 반환 · OOMKilled — 프로세스 사망
```

여덟 명이 동시에 인쇄를 누르면 파드가 죽고, **그 순간 다른 일을 하던 사람들도 함께**
죽습니다.

## 한 번에 세 개까지 그립니다

대기열은 **그리는 자리**에 둡니다. 덱을 읽는 일은 가볍고, 다른 사람이 그리는 동안
읽어 두어도 되기 때문입니다.

```
고치기 전:  8개 동시  →  0개 반환 · 프로세스 사망
고친 뒤:    8개 동시  →  8개 반환 · 15.3초
고친 뒤:   16개 동시  →  16개 반환 · 29.9초 · 최대 424 MiB (제한의 절반 이하)
```

60초를 기다려도 자리가 없으면 `503 printing_busy` 로 답합니다.

## 왜 셋인가

1.48.1에서 배운 것을 그대로 적용했습니다 — 갓 시작한 프로세스에서 통과하는 숫자가
일하던 프로세스에서는 통과하지 않습니다. 그래서 여유를 두고 골랐고, 16개 동시
요청에서도 제한의 41%만 씁니다.

## 함께 확인한 것

- 1.48.1 배포 이미지에서 60 MB 템플릿 8개 동시 업로드 → **8개 모두 201**, 죽지 않음
- 동시성 스위프 재실행 → **49,136건, 실패 0**
