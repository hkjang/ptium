# Ptium v0.74.0

지난 판에서 격자가 안내에서 빠져 있던 것을 고쳤습니다. 같은 자리를 마저 훑었더니 **더 큰 것**이
있었습니다.

## 요청한 적 없는 것을 측정하고 있었습니다

검사기는 "숫자가 있는데 출처가 없다"를 지적합니다 — 이 계정의 덱 235개에서 **160건**.
그런데 모델에게 주는 언어 설명에 **`!source` 가 아예 없었습니다.**

쓸 수 있다고 말한 적 없는 것을 안 썼다고 지적하고 있었던 것입니다.

이제 안내에 있습니다.

```
!source name | locator   where a figure on this slide came from
```

규칙은 분명합니다 — **브리프가 출처를 말한 경우에만** 답니다. **지어내지 않습니다**: 브리프가
출처 없이 준 숫자에는 아무것도 달지 않습니다. 근거 없는 각주는 없는 것보다 나쁩니다.

**실제 모델로 확인했습니다.** "통계청 2026 소비 동향(표 3)에 따르면 … 내부 결제 로그 기준 …"
브리프를 보냈더니 모델이 각 슬라이드에 이렇게 달았습니다.

```
!source 통계청 2026 소비 동향 | 표 3
!source 내부 결제 로그 | 2025-08~2026-08
```

그려 보면 슬라이드 발 밑에 `출처: 통계청 2026 소비 동향, 표 3` 이 붙습니다 — v0.56에서 만든
그 줄이, 이제 생성 경로로도 닿습니다.

두 칸 슬라이드 문법(v0.69에서 자란 두 번째 `>`)도 안내에 없어서 함께 넣었습니다.

## `!notes이` 에서 `이` 가 사라지고 있었습니다

같은 덱에서 모델이 이렇게 썼습니다.

```
!notes이 성장세는 곧 시스템 부하로 이어집니다.
```

한국어에서 다음 단어가 조사로 시작하면 띄어쓰기가 붙어 버리는 일이 흔합니다. Ptium은 이것을
`notes이` 라는 한 덩어리로 읽고 **`이` 를 버렸습니다.**

이제 **디렉티브 이름 뒤에 붙은 말은 말로 읽습니다** — 한글이나 숫자로 시작할 때만. 영문자로
이어지면 디렉티브 이름의 일부일 수 있으므로 자르지 않습니다.

## 확인

- Go 전 패키지 통과. 안내에 `!source` 와 두 칸 문법이 실리는지, 붙어 쓴 디렉티브가 말을
  지키는지, 영문자는 자르지 않는지 각각 확인합니다.
- 모델이 단 출처가 슬라이드 발 밑에 나오는 것을 **그려서** 확인했습니다.
- api 88 · edges 32 · package · flows · ui 0 실패.
