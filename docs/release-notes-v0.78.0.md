# Ptium v0.78.0

브리프는 이렇게 말했습니다.

```
내부 결제 로그 기준 지난 12개월 장애 2회·4시간 17분
```

모델은 이렇게 인용했습니다.

```
!source 내부 결제 로그 | 2026-03
```

시스템은 진짜입니다. **2026-03 은 아무도 말한 적이 없습니다.**

## 이름만 검사하고 있었습니다

v0.75 부터 지어낸 출처는 지워 왔습니다. 그런데 검사하는 것은 `|` **앞** 뿐이었습니다.
이름이 브리프에 있으면 통과였고, 그 뒤에 무엇이 붙든 보지 않았습니다.

이게 더 나쁜 종류의 날조입니다. 이름이 맞기 때문에 **나머지도 맞다고 믿게 만듭니다.** 그리고
회의실에서 "2026년 3월 로그 좀 볼까요" 라는 말이 나오는 순간 끝납니다.

## 지우고, 출처는 남깁니다

숫자와 달리 위치 표기는 **떼어낼 수 있습니다** — 문장 안에 있지 않으니까요. 그래서 지웁니다.
인용은 그대로 남고 슬라이드 아래에는 `내부 결제 로그` 만 찍힙니다. 이건 참입니다.

> 출처의 위치 표기 2건은 브리프에 없어 지우고 출처 이름만 남겼습니다. 표나 페이지를
> 아신다면 직접 적어 주세요.

**남기는 것**: 브리프가 준 위치(`표 3`, `지난 12개월`, `12페이지`), 그리고 **스프레드시트
셀 범위**.

## 셀 범위가 진짜 수확이었습니다

저장된 덱으로 인구조사를 돌리자 이것이 걸렸습니다.

```
!source 매출-415626.csv | A1:B4
```

브리프에 `A1:B4` 가 있을 리 없으니 지워야 할 것 같지만 — **이건 Ptium 이 직접 쓴 것입니다.**
첨부한 시트로 덱을 만들 때 `internal/docs` 가 `Sheet1!A1:C9` 형식으로 어디서 가져왔는지
적습니다. 내용에 대한 주장이 아니라 **첨부 파일 안의 좌표** 이고, 브리프에 있을 이유가 없으며,
지웠다면 **참인 것을 지운 것** 이 됩니다.

인구조사가 없었으면 이걸 릴리즈에 실었을 겁니다. 인용 있는 덱 20개 중 오탐 11건 → **5건 전부
진짜 날조** 로 정리됐습니다.

## 지시도 같은 것을 말합니다

```
- The part of !source after "|" is where in the source it is — a table, a
  page, a period the brief itself names. If the brief does not say where,
  write the name alone.
```

## 결과

실제 모델(vLLM)로 같은 브리프:

- 지워진 위치 표기 **2건** (`2026-03`, `2026-08`)
- `!source 통계청 2026 소비 동향 | 표 3` — **그대로**
- 출처 이름 **2건 모두 유지**

## 설치

오프라인 설치 방법은 [docs/offline-deployment.md](offline-deployment.md) 를 보세요. 이미지에
Postgres 와 nginx 는 들어 있지 않습니다 — 배포할 때 `DATABASE_URL` 로 DSN 을 지정합니다.
