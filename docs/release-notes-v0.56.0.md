# Ptium v0.56.0

"이 숫자 어디서 나온 겁니까"에 **슬라이드가 직접 답합니다.**

## 출처가 발표자 노트에만 있었습니다

v0.46부터 `!source` 로 적은 출처는 슬라이드와 함께 저장되고, 발표자 노트 끝에 목록으로
붙었습니다. 그런데 **파일은 돌아다닙니다.** 전달되고, 인쇄되고, 몇 달 뒤에 열립니다. 그 사람들은
발표자 노트를 열지 않습니다. 그들에게 그 숫자는 **출처 없는 숫자**입니다.

이제 인용이 있는 슬라이드는 발 밑에 한 줄을 답니다.

```
출처: 통계청, 2026 소비 동향, 표 3                                              2
```

디자인이 이미 쪽 번호를 위해 비워 둔 띠에, 번호와 같은 크기·같은 색으로 들어갑니다. 디자인에
드는 비용이 없습니다. 그 띠가 비어 있지 않으면 — 쪽 번호가 없는 템플릿이거나, 내용이 아래까지
내려오는 슬라이드면 — **넣지 않습니다.** 노트의 목록은 그대로 남아 있으니 잃는 것은 없습니다.

너무 길면 한 줄에 맞춰 자르고 `…` 를 남깁니다. 전체 목록은 언제나 노트에 있습니다.

## "통계청"은 각주 기호가 아니라 기관 이름입니다

`!source 통계청 | 2026 소비 동향 | 표 3` 을 넣으면, 파서가 **`통계청` 을 각주 기호로 읽고
있었습니다.** 기호는 세 글자 이하면 기호라고 판단했기 때문입니다.

한국어·일본어·중국어 기관 이름은 두세 글자가 **정상**입니다 — 통계청, 한은, 기재부, 국토부.
이제 라틴 문자 밖의 기호는 **한 글자**까지만 기호입니다. `가`는 기호, `통계청`은 이름입니다.
`1` · `a` · `*` · `†` 는 그대로 기호입니다.

## 화면과 파일이 글자를 같은 자리에서 시작합니다

미리보기는 모든 템플릿이 PowerPoint 기본 여백(0.1인치)을 쓴다고 **가정**하고 있었습니다.
Ptium이 만드는 디자인은 `lIns="0"` 이라 글자를 상자 끝에서 시작합니다. 그래서 화면의 모든 줄이
파일보다 0.1인치 오른쪽에 있었습니다 — 아래 한 줄이 같은 왼쪽 선에 맞아야 하는 순간 바로
보이는 차이입니다.

이제 레이아웃에서 실제 여백을 읽어 씁니다(`ManifestVersion` 5, 기존 템플릿은 자동 재분석).
제목 · 본문 · 출처 줄이 화면에서도 파일에서도 같은 선에서 시작합니다.

## 확인
