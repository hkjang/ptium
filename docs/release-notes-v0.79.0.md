# Ptium v0.79.0

작성 규칙은 이렇게 말합니다.

> 브리프가 출처 없이 말한 숫자에는 `!source` 를 붙이지 마세요.

그리고 측정은 같은 슬라이드를 이렇게 지적했습니다.

> 숫자가 있는데 출처가 없습니다.

**규칙을 지키면 감점되는 구조** 였습니다. v0.76 의 밀도 문제와 정확히 같은 종류입니다 —
시키는 것과 재는 것이 서로 다른 말을 하고 있었습니다.

## 12억 원을 요청하는 덱

이사회에 12억 원을 요청하는 덱은 그 숫자를 여러 장에서 반복합니다.

```
# 이중화 투자 계획
> 결제 시스템 이중화 구축 비용 12억 원 요청

# 투자 대비 위험 비용
- 12억 원 초기 비용
```

이 숫자의 출처는 **브리프를 쓴 사람 자신** 입니다. 인용할 곳이 없습니다. 그런데도 두 장 모두
지적을 받았고, 저자는 지울 수 없는 경고를 두 개 안고 있어야 했습니다. 지울 수 없는 경고는
**전부 무시하게 만듭니다.**

## 브리프를 덱과 함께 재게 했습니다

이제 브리프가 덱에 실려 측정까지 따라갑니다. **브리프가 준 적 없는 숫자만** 묻습니다.

| 슬라이드 | 이전 | 이번 |
|---|---|---|
| `구축 비용 12억 원 요청` (브리프에 있음) | 지적 | **묻지 않음** |
| `온라인 거래액 28.5% 증가` (브리프에 있음) | 지적 | **묻지 않음** |
| `가용성 99.99% 확보` (브리프에 없음) | 지적 | **지적** |

브리프가 없는 덱 — 파일에서 가져왔거나 손으로 쓴 덱 — 은 예전처럼 **모든 숫자** 를 묻습니다.
그 숫자가 저자의 것이라고 말해 주는 게 아무것도 없기 때문입니다.

## 어떤 숫자인지 말합니다

```
figures with no source: 28.5%, 1,200건
```

> 브리프에 없는 숫자에 출처가 없습니다: 28.5%, 1,200건.

예전에는 "숫자가 있는데 출처가 없습니다" 라고만 해서, 저자가 슬라이드를 훑으며 **어느
숫자인지 찾아야** 했습니다.

## 저장된 덱으로 재측정

- 이 문제를 만든 덱: **96점 · 지적 2건 → 100점 · 지적 0건**
- 남은 `source` 지적은 전부 모델이 스스로 들여온 숫자: `99.99%` · `0.2%` · `1,200건` · `15%`

숫자 비교는 이제 생성과 측정이 **같은 함수 하나** 를 씁니다. 두 번째 것을 쓸 때 이미 그랬어야
했습니다.

## 설치

오프라인 설치 방법은 [docs/offline-deployment.md](offline-deployment.md) 를 보세요. 이미지에
Postgres 와 nginx 는 들어 있지 않습니다 — 배포할 때 `DATABASE_URL` 로 DSN 을 지정합니다.
