# Ptium v1.36.0

관리자 고도화 네 번째 — **디자인 운영**입니다.

## 조직이 무엇으로 덱을 쓰는지 볼 수 없었습니다

- 업로드한 템플릿은 **올린 사람만** 볼 수 있습니다. 관리자도 마찬가지였습니다.
- 표준 디자인은 서비스 설정의 **글자 칸**이었습니다. `slate-classic`이라고 적혀 있으면
  그것이 무엇인지, 실제로 쓰이는지 알 방법이 없었습니다.

## 관리자 · 디자인

```
63 (이 배포의 디자인)   0 (모두에게 공개된 업로드)   13 (올린 사람만 쓰는 업로드)

[표준] 내장  Ptium Slate Classic   2,423개 · 최근 30일 1,180개   모두 (내장)      [표준으로]
       업로드 회사 표준 템플릿        14개 · 최근 30일 14개        a@b.com만        [표준으로] [모두에게]
```

- 내장 50개와 **올라온 템플릿 전부**를, 누구 것이든 한 자리에서.
- **얼마나 쓰이는지**: 전체 덱 수와 최근 30일. "아직 쓰이지 않았습니다"와 "최근 30일은
  없음"을 구분합니다 — 한 번도 안 쓴 것과 요즘 안 쓰는 것은 다른 이야기입니다.
- **모두에게 / 비공개로**: 한 사람의 업로드를 조직 전체가 쓰게 하거나 되돌립니다.
  내장 디자인은 이미 모두의 것이라 거절합니다.
- **표준으로**: 새 덱이 아무것도 고르지 않았을 때 들어갈 디자인을 지정합니다. 이것은
  설정의 그 값이며, **설정 변경 기록에 무엇이 되었는지 남습니다**(1.33.0).

## 만들다가 찾은 것: 표준이 실제로는 적용되지 않았습니다

업로드한 템플릿을 표준으로 지정하고 **덱을 만들어 봤습니다.**

```
표준: 1월5주간업무보고_AI엔지니어링 (업로드)
덱이 들어간 곳: Ptium Slate Classic     ← 지정한 것과 다릅니다
```

표준값을 **내장 디자인 이름으로만** 읽고 있었습니다. 업로드 템플릿의 id는 어떤 디자인
이름과도 맞지 않아 조용히 첫 번째 내장 디자인으로 떨어졌습니다. 화면만 만들었다면
**아무 일도 하지 않는 버튼**을 드릴 뻔했습니다.

이제 표준값이 **업로드 템플릿의 id**여도 그대로 씁니다(내장이면 팔레트 키, 업로드면 id —
디자인 이름은 낱말이고 템플릿 id는 uuid라 서로 헷갈릴 수 없습니다). 다시 확인 —

```
덱이 들어간 곳: 1월5주간업무보고_AI엔지니어링   ✓
```

## 검사

- 데이터베이스: 업로드 id가 그 템플릿으로, 내장 키는 그 디자인으로, 아무 것도 아닌 uuid는
  기존처럼 기본 디자인으로 떨어지는지. uuid 경로를 빼면 그 자리에서 실패합니다.
- REST 훑기: 목록이 내장을 담고 있는지, 사용 수가 "최근 30일 > 전체"가 되지 않는지,
  표준을 자처하는 디자인이 둘 이상이 아닌지, 내장 공개 시도는 422인지, 표준으로 지정하면
  그 디자인이 표준으로 읽히는지.
- 화면 훑기: 세 화면(공유 링크 · 사용 현황 · 디자인)이 **데이터가 그려질 때까지 기다렸다가**
  확인합니다. 제목만 보고 바로 세던 첫 판이 빈 화면을 결함으로 신고했습니다.
