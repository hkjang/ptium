# 1.67.0 — API 설명서가 실제 서버와 맞습니다

`api/openapi.yaml` 은 이 제품이 API 를 쓰는 사람에게 하는 약속입니다. 손으로
쓰고 있었고, 라우트와 맞춰 주는 것이 아무것도 없었습니다.

## 답을 하는데 설명서에 없던 다섯 곳

| | |
| --- | --- |
| `GET /api/v1/presentations/{id}/export.pptx` | 파일 이름이 붙는 내려받기 |
| `GET /api/v1/presentations/{id}/export.pdf` | 1.55.3 에서 추가하고 설명서에 적지 않았습니다 |
| `POST /api/v1/presentations/{id}/source` | `PUT` 과 같은 동작 |
| `DELETE /api/v1/api-keys/{id}` | `POST .../revoke` 와 같은 동작 |
| `GET /auth/me` | 예전 클라이언트용, `/api/v1` 밖에 있습니다 |

없는 엔드포인트가 아니라, **이 저장소 밖에서는 있는지 알 수 없는** 엔드포인트
였습니다. 다섯 곳 모두 설명을 적었습니다 — 무엇과 같은 동작인지, 왜 따로
있는지까지.

## 아무것도 가리키지 않던 참조 두 개

`#/components/responses/ValidationError` 를 두 곳에서 참조하는데, 그런 이름의
컴포넌트가 없었습니다. 이 설명서로 클라이언트를 만들면 그 두 곳의 422 응답이
사라지거나 생성이 실패합니다. 실제 이름(`UnprocessableEntity`)으로 고쳤습니다.

## 다시 어긋나지 않게

서버에 등록된 라우트와 설명서의 경로·메서드가 **양쪽 다** 맞는지, 그리고 모든
`$ref` 가 실제로 있는 것을 가리키는지 검사하는 시험을 두었습니다. 설명서에서
경로 하나를 빼거나 없는 이름을 참조하면 시험이 무너집니다.

## 확인

- 다섯 곳 모두 실제로 200 을 답하는 것을 서버에 물어 확인했습니다.
- 시험을 두 방향 모두 되돌려 무너지는 것을 확인했습니다.
- 설명서의 모든 `$ref` 가 풀리는 것을 확인했습니다 (고치기 전 2개 실패).
