# Ptium v1.13.5

관리자 개요의 "서비스 상태" 는 무슨 일이 있어도 **"연결됨"** 이라고 말했습니다. 그 배지들은
재고 있는 것이 없었습니다 — 화면이 떴다는 사실 말고는요.

## 제공자가 답하는지 물어봅니다

폐쇄망 배포에서 진짜로 끊기는 것은 데이터베이스가 아니라 **모델 호스트**입니다. 그런데
제공자를 설정한 뒤 그게 실제로 답하는지 알아볼 방법이 **덱을 하나 만들어 보는 것뿐**이었습니다.

`관리자 → 서비스 설정 → AI 모델` 에 **지금 확인** 이 생겼습니다. 저장된 설정 그대로 한 번
물어보고, 아무것도 바꾸지 않습니다:

```
247ms 만에 답했습니다 · "ok"
닿지 않았습니다 — AI request failed: Post "http://127.0.0.1:9/v1/chat/completions": …
오프라인 작성기로 씁니다 — 모델 호스트를 쓰지 않습니다
```

개요의 배지도 이제 **그 결과**를 말합니다 — 응답함 / 응답 없음 / 오프라인 작성기. 화면을
열 때 한 번만 묻습니다: 이건 남의 모델 호스트로 나가는 요청이고, 열어 둔 화면이 계속
두드려서는 안 됩니다.

확인한 사람도 감사 기록에 남습니다(`settings.provider_check`) — 여러 배포가 한 호스트를
나눠 쓰는 곳에서는 누가 언제 두드렸는지가 그 자체로 정보입니다.

API: `POST /api/v1/admin/provider-check` (관리자 전용).

## 확인

- 스윕이 세 가지 상태를 지킵니다: 어느 제공자에게 물었는지 말하는지, **제공자가 없는
  배포가 "응답함" 이라고 하지 않는지**, 아무것도 없는 주소를 가리켰을 때 그렇게 말하고
  **이유를 함께 주는지**, 그리고 관리자 역할 없는 계정은 403 (330 checks)
- 검사는 설정을 잠시 바꿔 본 뒤 **원래대로 되돌립니다**
