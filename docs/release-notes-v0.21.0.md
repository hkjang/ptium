# Ptium v0.21.0

이미지를 올리면 **목록**에 쌓였습니다. 스무 개쯤 되면 그 목록이 곧 문제였습니다 — `logo.png`가
세 개, 그중 무엇이 진짜인지 알 수 없고, 3월에 쓴 제품컷을 찾을 방법이 없습니다. 디자인도
마찬가지였습니다. 50종이 있는데, **이 사람이 실제로 무엇으로 덱을 만드는지**는 아무도 기억하지
않았습니다.

이제 둘 다 **배우는 라이브러리**입니다.

## 내 이미지

새 화면 **내 이미지**(`/images`)와 편집기 오른쪽 패널이 같은 라이브러리를 봅니다. 컬렉션을
정리하는 일은 320픽셀 패널에서 하는 일이 아니기 때문입니다.

| | |
| --- | --- |
| **즐겨찾기** | 별표를 누르면 어떤 정렬에서도 맨 앞. 로고처럼 매번 쓰는 것에 |
| **태그** | 로고·제품컷·배경처럼 **자기 말**로 묶기. 태그 막대는 이미 쓴 말을 개수와 함께 보여 줍니다 |
| **덱 N개** | 그 이미지를 **실제로 쓰는** 덱의 수 |
| **정렬·검색** | 최근 올림 · 최근 사용 · 자주 사용 · 이름순, 이름과 태그로 검색 |
| **이름 바꾸기** | 이름을 두 번 눌러 그 자리에서. 덱은 id를 들고 있으므로 그대로 동작합니다 |

**"덱 3개"는 세어 둔 숫자가 아닙니다.** 슬라이드가 저장될 때마다 — 편집·복제·되돌리기·생성·
코드 적용 다섯 가지 경로 전부 — 그 덱이 어떤 이미지를 놓았는지 다시 읽어 맞춥니다. 그래서
덱에서 이미지를 빼면 그 즉시 줄어들고, 카운터가 어긋날 일이 없습니다. **지워도 되는 이미지**가
여기서 바로 보입니다.

**같은 파일을 다시 올리면** 사본을 만들지 않고 이미 있는 이미지를 돌려주며 그렇다고 말해 줍니다.
`logo.png`, `logo (1).png`, `스크린샷 2026-08-21.png`가 전부 같은 바이트인 라이브러리는
라이브러리가 아닙니다.

## 자주 쓰는 디자인

템플릿에도 별표가 생겼습니다. 별표는 **그 사람의 워크스페이스에 대한 메모**이므로 남의 템플릿을
고칠 권한이 필요 없고, 다른 사람에게는 아무 변화가 없습니다.

- 별표를 눌러 둔 디자인과 **실제로 덱을 만든** 디자인을 템플릿 화면과 새로 만들기 맨 앞에
  **자주 쓰는 디자인**으로 모아 보여 줍니다.
- 추천에도 반영됩니다. 어떤 브리프의 키워드보다, 그 사람이 그 디자인으로 아홉 번 덱을 만들었다는
  사실이 더 많은 것을 말해 줍니다.
- 카드의 **사용 횟수는 이제 내 덱의 수**입니다. 전사 인기도는 디자인을 고르는 순간에 묻는 질문이
  아닙니다.

## API

- `GET /api/v1/assets?q=&tag=&favorite=&sort=recent|lastUsed|used|name`
- `GET /api/v1/assets/tags` — 이 사람이 쓴 태그와 개수
- `PATCH /api/v1/assets/{id}` — 이름·태그 (`409`는 같은 이름이 이미 있다는 뜻)
- `PUT /api/v1/assets/{id}/favorite`, `PUT /api/v1/templates/{id}/favorite`
- 업로드가 이미 있는 바이트와 같으면 `201`이 아니라 **`200` + `reused: true`**
- `Asset`에 `tags` · `favorite` · `deckCount` · `lastUsed`, `Template`에 `favorite` · `lastUsed`

## 그 밖에

- **썸네일이 필터를 바꿀 때마다 깜빡이며 깨지던 문제.** 목록이 바뀔 때마다 blob URL을 새로
  만들고 이전 것을 회수했는데, 아직 `<img>`가 가리키고 있는 URL을 회수하면 보이던 썸네일이
  전부 깨집니다. 이제 라이브러리가 열려 있는 동안 유지하고, 이미지가 같은 이름으로 교체되면
  (체크섬이 바뀌므로) 다시 받아 옵니다. 필터를 여섯 번 바꿔도 요청은 처음 세 번뿐입니다.
- 삭제하려는 이미지를 쓰는 덱이 있으면 몇 개인지 말하고 확인을 받습니다.
