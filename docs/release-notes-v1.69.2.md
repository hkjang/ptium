# 1.69.2 — 보이지 않는 썸네일을 미리 그리지 않습니다

미리보기는 요청할 때마다 **서버가 그립니다.** 50장짜리 덱을 편집 화면에서 열면
50장을 전부 그리게 했습니다. 그때 화면에 보이는 것은 **여섯 장**이었습니다.

창은 900px, 썸네일 레일은 **7,111px**. 나머지 마흔네 장은 아무도 보지 않는
그림이었고, 덱이 길수록 낭비도 같이 늘었습니다.

| 50장 덱을 열 때 | 고치기 전 | 고친 뒤 |
| --- | --- | --- |
| 미리보기 요청 | **51건** | **6건** |
| 레일을 내린 뒤 | — | 12건 (필요한 만큼) |

이제 미리보기는 **창에 가까워지면** 그립니다. 여유를 600px 두었기 때문에,
스크롤을 내리면 그리기 시작하는 것이 아니라 이미 그려져 있는 것을 만납니다.
`IntersectionObserver` 가 없는 브라우저에서는 예전처럼 즉시 그립니다.

## 이번에 재 보고 고치지 않은 것

- **화면 일곱 개**를 같은 방법으로 쟀습니다. 덱 목록·이미지·오류·감사·공유·큐는
  모두 요청 서너 건으로 깔끔했습니다.
- 템플릿 화면만 22건이었는데, 세어 보니 **같은 디자인을 두 번 그린 것**이
  아니라 위쪽 "자주 쓰는 디자인" 칸과 아래 목록에 같은 디자인이 함께 나오기
  때문이었습니다. 화면이 그렇게 생긴 것이지 잘못이 아닙니다.
- 미리보기 응답은 `Cache-Control: no-store` 입니다. 같은 코드가 **덱 미리보기**
  에도 쓰이므로, 캐시 정책을 바꾸는 것은 이 배포가 정할 일이지 제가 혼자
  정할 일이 아닙니다. 그대로 두었습니다.

## 확인

- 브라우저에서 50장 덱을 열어 요청 51건 → 6건, 레일을 내리면 12건이 되는 것을
  확인했습니다.
- 화면 스윕에 "50장 덱을 열 때 미리보기 20건 이하" 검사를 넣고, 고침을 되돌려
  51건으로 무너지는 것을 확인했습니다.
