# Ptium v1.14.1

## 키가 자기보다 큰 권한을 줄 수 없습니다 (보안)

1.14.0 에서 권한 수정을 넣고, 그 문을 스스로 두들겨 보다가 **1.14.0 이전부터 있던 구멍**을
찾았습니다.

키에 권한 범위를 지정하는 것은 **그 키를 쥔 기계가 받은 것 이상은 할 수 없다**는 약속입니다.
그런데 `api_keys:manage` 를 가진 키는 그 약속을 스스로 깰 수 있었습니다.

```
프레젠테이션 "조회"만 가진 키로:
  POST /api/v1/api-keys  {"scopes": ["admin:users"]}   → 201 (관리자 키가 발급됨)
```

계정 주인이 관리자면 **읽기 전용으로 준 키가 관리자 키를 스스로 만들어 낼 수** 있었습니다.
1.14.0 의 권한 수정은 이 경로를 한 단계 더 짧게 만들었을 뿐, 구멍은 그전부터 열려
있었습니다.

이제 **API 키로 인증한 요청은 그 키가 갖고 있지 않은 권한을 줄 수 없습니다** — 발급도,
수정도 마찬가지입니다. 거절할 때는 어떤 권한 때문인지 이름을 댑니다:

```
403  This API key does not hold "admin:users", so it cannot grant it
```

바뀌지 않는 것:

- **키는 언제나 자기를 좁힐 수 있습니다** (가진 것보다 적게)
- **사람이 자기 계정으로 로그인해서 주는 것은 그대로입니다** — 자기 계정이고, 키 화면이
  그러라고 있는 자리입니다
- 가진 권한을 그대로 물려주는 것도 됩니다

## 검사

- 좁은 키가 넓히려는 네 가지 시도(발급/수정 × 일반/관리자 권한)가 모두 403 이어야 하고,
  자기를 좁히는 것과 주인이 넓히는 것은 200 이어야 합니다 (tenancy 97 checks)
- 이전 바이너리에서 이 검사는 `201` 로 실패합니다 — 좁은 키가 스스로 관리자 키를
  발급했다는 뜻입니다
