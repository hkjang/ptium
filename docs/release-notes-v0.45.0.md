# Ptium v0.45.0

Ptium은 그려진 덱을 여덟 가지로 재고 있었습니다 — 넘침 · 밖으로 나감 · 겹침 · 대비 · 외톨이 줄 ·
빽빽함 · 노트 없음 · 중복. 그 결과를 **목록으로만** 보여 줬습니다. 목록은 "무엇을 고칠까"에
답하지만, 사람들이 먼저 묻는 것은 다른 질문입니다.

> 이거, 지금 내보내도 되나?

## 품질 점수

편집기 위쪽 칩이 이제 **품질 92** 라고 말합니다. 눌러 열면 네 축과, 가장 낮은 슬라이드로 바로
가는 버튼이 있습니다.

| 축 | 무엇으로 재는가 |
| --- | --- |
| 가독성 | 넘침 · 밖으로 나감 · 빽빽함 · 외톨이 줄 |
| 구성 | 노트 없음 · 같은 말 반복 |
| 시각 | 겹침 |
| 접근성 | 대비 |

**규칙은 한 문장입니다.** 슬라이드마다 100에서 시작해 측정된 것만큼 깎입니다. 잘못 그려진 것은
크게(30~40), 다듬을 곳은 작게(4~6). 축 점수는 그 축에서의 슬라이드 평균, 덱 점수는 슬라이드
평균입니다. 20장 중 한 장이 빽빽한 것과 다섯 장이 빽빽한 것은 다른 소식이고, 평균이 그 차이를
말합니다.

**점수가 무엇이 아닌지도 화면에 적었습니다.** 점수는 그려진 것을 잰 결과입니다. 논지가
설득력 있는지, 숫자가 맞는지는 재지 않습니다 — 잘 조판된 빈 말은 100점이 나옵니다. 그 사실을
숨기면 점수가 거짓말이 됩니다.

API도 같이 열었습니다. `GET /presentations/{id}/inspect` 응답에 `score` 가 붙습니다 — 총점,
축별 점수와 **그 축이 무엇을 세었는지**(`counted`), 슬라이드별 점수와 가장 무거웠던 항목,
그리고 `weakest`.

## v2 계획서

코드를 읽고 정리해 주신 30개 제안을 받아, **지금 코드 기준으로** 다시 세운 계획을
`docs/roadmap-v2.md` 에 넣었습니다. 핵심은 이미 서 있는 것을 다시 만들지 않는 것입니다.

- 이미 있음: 생성 잡 큐(`FOR UPDATE SKIP LOCKED` · 크래시 잡 재확보), 브라우저 E2E 스윕,
  내보낸 파일의 외부 검증(python-pptx), 슬라이드 라이브러리, 측정 8종과 안전 수정,
  `.pptx` 가져오기(차트 숫자까지), 편집 가능한 표·차트, 모든 개체 대체 텍스트.
- 진짜 공백: **점수**(이번 판) → **근거·출처** → 문서에서 만들기 → 편집기 코파일럿 →
  라이브러리 먼저 찾기 → 편집기 분해와 프론트 유닛 테스트 → golden 파일 비교.

다음 판은 **근거·출처(Evidence)** 입니다. 기업 문서에서 AI가 쓴 숫자의 첫 질문은 언제나
"이거 어디서 나온 겁니까"이고, 지금 Ptium에는 그 답이 없습니다.

## 확인

- 회귀 테스트 1건: 깨끗한 덱은 100점·가장 낮은 슬라이드 없음, 결함 하나가 총점을 내리고
  **가독성 축에** 떨어지며, 같은 결함이 다섯 장에 퍼지면 한 장일 때보다 낮다는 것.
- 전수 점검에 한 줄 추가: 점수가 0~100이고, 모든 슬라이드를 덮고, 네 축을 모두 보고할 것.
- 전수 점검: api 76 · edges 32 · package 0 실패.
