# Ptium v1.6.0

지난 판에서 짠 그물은 **텍스트와 슬라이드** 사이만 봤습니다. 이번엔 같은 질문을 **그리는 쪽** 에
했습니다 — 컴포넌트 15종 × 역할 9종 × (리드 · 노트 · 출처) = **576가지 슬라이드를 전부 그려서**,
그림 안에 그 슬라이드의 글자가 다 있는지 봤습니다.

## 인용과 강조가 작성자의 한 줄을 지우고 있었습니다

```
# 인용 점검
@content
> 고객이 한 말입니다          ← 이 줄이
::quote
- 기다리는 게 제일 힘듭니다 | 고객 A
::
```

슬라이드에 **없습니다.** 경고도 없습니다.

부제 영역이 없는 레이아웃에서는 슬라이드의 리드가 **컴포넌트의 제목으로 보관** 됩니다(v1.5.1 에서
다룬 그 구조입니다). 그런데 인용·강조 컴포넌트는 그리기 직전에 **제목을 통째로 비우고** 있었습니다.
`::callout 유의` 의 "유의" 도 마찬가지로 사라졌습니다.

이제 그 줄을 **문장 위에 작은 라벨로** 그립니다. 인용문 위에 굵은 제목을 얹지 않는다는 원래
의도는 그대로 두되, 작성자가 쓴 글자는 슬라이드에 남습니다.

## 자리를 뺏지 않고, 자리를 요청합니다

라벨을 그리자 좁은 영역에서 **넘침 4건** 이 생겼습니다. 문장이 쓸 자리를 라벨이 가져간 것입니다.

그래서 라벨이 있는 인용·강조는 **필요한 줄 수를 하나 더 요구** 하게 했습니다. 그만한 자리가 없는
영역에서는 컴포넌트 대신 **본문 글로** 들어갑니다 — 넘쳐서 잘리는 것보다 낫고, 글자는 그대로
남습니다. 넘침은 다시 **0** 이 되었습니다.

## 576가지를 상시 검사합니다

| | |
|---|---|
| 결함(넘침·이탈·겹침·대비) | **0** |
| 빈 미리보기 | **0** |
| 그림에 없는 단어 | **0** (구분 슬라이드 제외) |

구분(`@section`) 슬라이드는 제목만 있는 레이아웃이라 컴포넌트를 놓으면 그릴 자리가 없습니다.
이것은 **테스트에 예외로 명시** 해 두었습니다 — 다른 어떤 모양이 글자를 잃으면 즉시 실패합니다.

## 재 봤지만 고치지 않은 것

`::comparison` 의 첫 열 이름("항목", "구분" 같은 말)이 그려지지 않는 것은 **의도된 동작** 이었습니다.
AI 가 습관적으로 채우는 빈 말이라 일부러 거릅니다. 코드에 그렇게 적혀 있고, 실제 이름
("임대료" 등)은 정상적으로 그려집니다.

gzip -dc ptium-1.6.0.tar.gz | docker load
