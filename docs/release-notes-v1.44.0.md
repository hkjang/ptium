# Ptium v1.44.0

**폐쇄망 모델은 API 키가 없습니다. 그래서 제품이 "모델이 없다"고 했습니다.**

## 이 배포에서 실제로 일어나고 있던 일

개발용 배포에는 자체 호스팅 122B 모델이 **호스트도 모델명도 저장된 채** 연결돼
있었습니다. 관리자 화면에도 그대로 보였습니다. 그런데:

| 무엇을 했을 때 | 무슨 일이 일어났나 |
| --- | --- |
| 슬라이드 다시 쓰기 | `503 이 배포에는 AI 제공자가 설정되어 있지 않습니다` |
| 덱 다시 쓰기 | `409 덱을 다시 쓰려면 연결된 AI 모델이 필요합니다` |
| 덱 생성 | **말없이 내장 오프라인 작성기로** 씀 |
| 모델 연결 확인 | `API 키가 비어 있어 제공자에 요청하지 않습니다` |

원인은 한 줄이었습니다. **`ai.api_key`가 비어 있으면 "제공자가 없다"로 읽고**
있었습니다 — 이 제품이 놓일 자리에서 그것만은 뜻할 수 없는 말입니다. 닫힌 망의
vLLM·Ollama는 **키 없이** 부릅니다.

## 이제

- 키는 **선택**입니다. 키가 있으면 `Authorization` 헤더를 보내고, 없으면 보내지
  않습니다. `Bearer ` 뒤에 아무것도 없는 헤더는 "자격 증명 없음"이 아니라
  "잘못된 자격 증명"이라 그것도 보내지 않습니다.
- 어떤 엔진이 쓰는지는 **프로바이더**가 정합니다. 키 저장 여부가 아니라.
- 모델 연결 확인은 호스트를 대신해 거절하지 않고 **직접 물어봅니다.**

실제 122B 호스트로 확인한 결과:

```
이전:  detail "API 키가 비어 있어 제공자에 요청하지 않습니다"   revise → 503
지금:  reachable true · answered true · 241ms · "ok"        revise → 200 (초안 도착)
```

모델 스위프(`withmodel.py`)가 이번 세션 처음으로 **23개 검사 0 실패**로 통과했습니다.
직전 실행의 실패 6건은 전부 "말없는 대체"의 결과였습니다 — 오프라인 작성기가 쓴 덱을
모델이 쓴 덱으로 알고 검사했으니까요. 지금은 덱이 자기가 들여온 숫자를 스스로 밝힙니다.

## 화면도 고쳤습니다

설정 화면은 키가 없으면 **"저장된 API 키가 없어 내장 초안 생성기를 사용합니다"** 라고
말했습니다. 모든 덱을 자기 모델로 보내고 있는 배포에게 정반대를 말한 것입니다.
이제 프로바이더 기준으로 말하고, 키 없이 연결된 경우 `키 없이 연결` 로 표시합니다.
API 키 입력란에도 비워 둘 수 있다고 적었습니다.

## 바꾼 기대값 하나

`modelConnectedTo` 테스트의 `"a provider with no key" → false` 를 `true` 로
바꿨습니다. 옛 가정을 그대로 못박아 둔 항목이고, 바꾼 이유를 테스트 안에 적어
두었습니다. 나머지 항목(`fallback`은 키가 있어도 false, 설정이 없으면 false)은
그대로입니다.
