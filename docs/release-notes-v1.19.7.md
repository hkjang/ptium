# Ptium v1.19.7

이번엔 **실제 API로 덱을 만들어** 처음부터 끝까지 읽었습니다. 두 번째 브리프에서 이런 것이
나왔습니다.

```
브리프: 신입 개발자 온보딩 절차 개선안을 팀에 공유할 자료로 5장 정도로 만들어줘

제목  : 절차 개선안을 팀에 할 자료로 정도로     ←
청중  : 신입                              ←
# 절차 개선안을 팀에 할 자료로 정도로
# 할 자료로 정도로
# 할 자료로 정도로 — 기대 효과
# 할 자료로 정도로 — 리스크와 대응
```

**사람에게 보여줄 수 없는 덱**입니다. 평범한 한 문장에서 구멍이 **네 개** 났습니다.

| 무엇이 | 왜 |
| --- | --- |
| `공유할` → `할` 이 남음 | 지시문에서 `공유` 만 떼어내고 **어미를 두고 감** |
| `팀에` 가 안 걸림 | 청중을 `[두 글자 이상]에` 로 찾고 있어서 **한 글자 팀은 통과** |
| `5장 정도로` → `정도로` 가 남음 | `5장` 다음에 **띄어쓰기가 있으면** `정도로` 를 못 붙임 |
| 청중이 `신입` | 브리프가 **무엇에 대한 것인지**(신입 개발자)를 **누구에게인지**로 읽음 |

## 고친 것

- 지시문의 동사는 **어미째** 떼어냅니다 — `공유할` · `보고하는` · `설명해서`
- 청중은 **한 글자여도 청중**입니다 — `팀에`, `실에`
- 장수 뒤에 붙는 말은 **띄어 써도** 같이 읽습니다 — `5장 정도로` · `10장 내외` · `세 장 이내`
- **누구에게인지를 브리프가 말하면 그게 청중**입니다. `팀에 공유할` 이라고 썼으면 청중은 팀이지,
  글의 소재(신입)가 아닙니다. `이사회에 보고` 는 예전처럼 **임원**으로 정규화됩니다
- 문장 끝에 동사가 오는 경우도 청중을 알아봅니다 — `개발팀에 배포 절차를 설명하는 자료` 의
  제목은 `배포 절차`, 청중은 개발팀
