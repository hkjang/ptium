# Ptium v0.12.0

실제 자체 호스팅 모델(vLLM, 100B급 추론 모델)에 붙여 생성부터 내려받기까지 반복 검증하고,
그 과정에서 드러난 결함을 고쳤습니다. 이번 릴리스의 변경은 전부 실제 호출에서 나온 것입니다.

## 추론 모델과의 대화

추론(thinking) 모델은 사고 과정만 반환하고 본문을 비웁니다. 그리고 어떤 제한 시간보다도
오래 생각합니다. 확인한 뒤에 대응하면 매번 제한 시간을 다 쓰고 실패하므로, 순서를 뒤집었습니다.

- 첫 요청부터 사고를 끄도록 요청합니다(`chat_template_kwargs.enable_thinking=false`).
  이 필드를 모르는 공급자가 4xx로 거부하면 필드 없이 즉시 재시도합니다.
- 사고만 있고 본문이 없는 응답은 그 사실을 밝히는 오류로 보고합니다. 빈 덱으로 취급하지
  않습니다.
- 관리자 **AI 모델** 화면에 응답 제어가 생겼습니다: `ai.reasoning`(자동·항상 끄기·모델
  기본값), `ai.max_output_tokens`(기본 8000), `ai.timeout_seconds`(기본 300).

## 모델이 실제로 쓰는 문법을 읽습니다

같은 프롬프트로 여러 번 돌려 보면 모델은 매번 조금씩 다르게 씁니다. 그 형태들을 의도대로
읽습니다.

- `| 기존 방식 | 신규 방식 |` — 마크다운 표로 쓴 행. 둘러싼 파이프와 `|---|` 구분선은
  문장 부호이지 빈 열이 아닙니다. 이름 없는 항목 네 개가 되던 문제를 고쳤습니다.
- 표를 만들라고 했을 때 컴포넌트 없이 그냥 항목으로 쓴 경우. 같은 열 수를 가진 행이 두 줄
  이상 이어지면 비교·지표·표 컴포넌트로 승격합니다.
- `@layout id=제목-및-내용` — 대입형 레이아웃 지정. 문자 그대로 읽으면 존재하지 않는
  레이아웃이 되어 슬라이드가 조용히 다른 레이아웃으로 옮겨갔습니다.
- `1 단계`, `15% 씩` — 숫자와 단위, 단위와 조사 사이의 공백을 붙입니다. 원문 소스는 모델이
  쓴 그대로 남고, 슬라이드에 그려지는 글자만 다듬습니다.

## 비교는 표로 그립니다

`::comparison`은 두 가지 모양을 담습니다. 이제 데이터를 보고 고릅니다.

- `이름 | 헤드라인 | 근거` 두세 행은 비교 대상 카드입니다(기존과 같음).
- `항목 | 기존 | 신규` 처럼 세 열이거나 행이 네 개 이상이면 **속성별 비교 표**입니다.
  카드로 그리면 속성 하나당 카드 하나가 되고 양쪽이 카드 안에 위아래로 쌓여, 아무것도
  비교되지 않았습니다.
- 머리글 행은 일반 명사(항목·구분·item…)나 한쪽을 가리키는 말(현재·목표, 기존·신규,
  before·after)로 알아봅니다. 그런 머리글 아래 두 열은 속성 열 없는 양쪽입니다.
- 행은 하나도 버리지 않습니다. 다 들어가지 않으면 글자 크기를 줄이고, 자리가 남으면 행에
  나눠 씁니다.

숫자가 아닌 값으로 만든 차트(`Q3 | 1시간`)는 그릴 수 없지만 버리지도 않습니다. 지표 행
또는 타임라인으로 그리고, 무엇을 바꿨는지 경고로 알립니다.

## 본문 전체를 쓰는 컴포넌트

비교 표·표·격자·차트가 2단 레이아웃의 한쪽 단에 들어가면 반대쪽이 비어 실수처럼 보입니다.
이런 컴포넌트는 같은 높이의 옆 영역까지 하나로 묶어 본문 전체 폭에 그립니다.

## 그려진 것을 측정합니다

검사기가 "이상 없음"이라고 한 슬라이드에서 리드 문장이 컴포넌트 첫 행을 덮고 있었습니다.
상자를 재고 있었기 때문입니다.

- 컴포넌트의 텍스트는 줄바꿈된 만큼의 높이로 측정합니다. 예약한 자리보다 크게 그려지면
  결함입니다.
- 컴포넌트 자기 글줄끼리 겹치면 결함입니다.
- 자리가 좁아 아무것도 그리지 못한 컴포넌트도 결함입니다. 슬라이드에 구멍이 남는 쪽이
  좁은 것보다 나쁩니다.
- 줄바꿈 계산 자체를 단어 단위로 바꿨습니다. 여섯 em 폭에 다섯 em 단어 네 개는 네 줄이지,
  총 너비를 나눈 세 줄이 아닙니다. 한 줄 차이가 그대로 넘침이 됩니다.
- 컴포넌트의 리드(머리글)는 줄바꿈된 만큼 자리를 잡습니다. 한 줄만 예약하고 두 줄을 그리면
  둘째 줄이 컴포넌트 위에 얹힙니다.

## 복호화할 수 없는 설정

암호화 키나 `DATABASE_URL`이 바뀌면 저장된 API 키를 열 수 없습니다. 그때 설정 페이지 전체가
500으로 실패했습니다 — 키를 다시 넣어야 하는 그 순간에 정작 화면이 열리지 않았습니다. 이제
해당 항목만 "다시 입력 필요"로 표시하고 나머지는 정상 동작합니다.

## 확인한 것

실제 공급자(vLLM, `Qwen3.5-122B-A10B` 4.75bit)로:

- 5·7·8·10장 덱 생성 25~40초, 결함 0, 다듬을 곳 0
- `.pptx` 내려받기 정상, 밝은 템플릿과 어두운 템플릿 모두 확인
- 소스 편집 후 재컴파일에서 레이아웃이 유지됨(이전에는 다른 레이아웃으로 옮겨갔습니다)
