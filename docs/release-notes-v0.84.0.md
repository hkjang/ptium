# Ptium v0.84.0

컨택트 시트에서 마지막까지 눈에 걸린 것 — **위 3분의 1만 쓰고 아래가 텅 빈 슬라이드** 를
파고들었더니, 여백이 문제가 아니라 **한 줄에 눌러 담은 목록** 이 문제였습니다.

```
# 현재 물류 운영 현황 및 한계
@content
> 3개 창고, 일 12,000건 처리 중 / 오배송률 0.8% 유지 / 인력 의존도 높고 확장성 부족
```

슬라이드 전체가 이 한 줄입니다. 요점 셋을 한 줄에 이어 붙여 놓으니 빈 슬라이드 꼭대기에
**두 줄로 흘러넘치는 문장 하나** 로 그려집니다.

**어떤 측정도 이걸 잡지 않습니다.** 넘치지도 않고, 겹치지도 않습니다. 요점이 여섯 개였으면
지적했을 텐데, 셋을 한 줄에 욱여넣은 것은 지적하지 않았습니다.

## 목록이면 목록으로 그립니다

양옆에 공백을 둔 슬래시(` / `)는 어구 안에 쓰지 않습니다. 그리고 요점도, 컴포넌트도, 둘째 단도
없는 슬라이드라면 **나눠서 경쟁할 상대가 없습니다.** 그래서 그 줄은 원래의 요점들로 나뉩니다.

| 이전 | 이번 |
|---|---|
| `3개 창고, 일 12,000건 처리 중 / 오배송률 0.8% 유지 / 인력 의존도 높고 확장성 부족` | • 3개 창고, 일 12,000건 처리 중<br>• 오배송률 0.8% 유지 (고객 만족도 저하)<br>• 인력 의존도 높고 확장성 부족 |

**건드리지 않는 것**: 표지와 간지(부제는 덱에 대한 한 문장이지 목록이 아닙니다), 그리고 아래에
요점이 있는 리드(그건 진짜 리드입니다). 컴포넌트가 있는 슬라이드도 그대로 둡니다 — 나눈
줄들이 그림과 자리를 다투게 되니까요.

## 작성 안내도 같은 말을 합니다

```
The lead is one line, not the slide. Three things to say are three points,
each on its own "- " line; a lead holding them all separated by slashes is
a run-on sentence across the top of an empty slide.
```

재는 쪽이 못 잡는 것은 **쓰는 쪽에 말해 두는 편** 이 낫습니다. 컴파일러의 정리는 그다음
안전망입니다.

## 설치

오프라인 설치 방법은 [docs/offline-deployment.md](offline-deployment.md) 를 보세요. 이미지에
Postgres 와 nginx 는 들어 있지 않습니다 — 배포할 때 `DATABASE_URL` 로 DSN 을 지정합니다.
