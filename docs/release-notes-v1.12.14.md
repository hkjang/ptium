# Ptium v1.12.14

가져온 덱의 **요점 순서가 뒤바뀌고** 있었습니다.

## 파일은 그리는 순서로 저장합니다

파워포인트 파일은 도형을 **그리는 순서**(z-order)로 담습니다. 손으로 만든 덱에서는 그것이
읽는 순서와 자주 다릅니다 — 나중에 추가한 상자가 뒤에 오고, 위에 있는 상자가 아래 상자보다
뒤에 저장되는 일이 흔합니다. 게다가 읽는 쪽은 한 번 더 섞고 있었습니다: **텍스트 상자를 모두
먼저, 그다음 그림, 그다음 표** 순으로요.

```
슬라이드 위쪽 상자: "위에 있는 상자"   (y=1,200,000)
슬라이드 아래쪽 상자: "아래에 있는 상자" (y=4,000,000)

읽힌 순서:  아래에 있는 상자 → 위에 있는 상자
```

가져오기가 옮기려는 것은 **그 덱의 논증**입니다. 순서가 뒤집히면 옮긴 것이 아닙니다.

## 이제 페이지를 읽는 순서로 읽습니다

위에서 아래로, 같은 줄이면 왼쪽에서 오른쪽으로. 같은 줄인지 판단할 때는 **1/4인치의
여유**를 둡니다 — 나란히 놓인 두 상자가 EMU 단위까지 정렬돼 있는 경우는 드물고, 머리카락
한 올 아래에 있다는 이유로 오른쪽 단이 먼저 읽히면 안 되기 때문입니다.

그룹 안의 도형은 **그룹의 자리**에 놓고 자기들끼리의 순서를 지킵니다. 그룹은 페이지 위에서
하나의 덩어리이기 때문입니다.

## 확인

되돌려서 확인했습니다 — 처음 쓴 테스트는 정렬 함수를 **직접** 불러서 되돌려도 통과했습니다.
`ReadDeck` 을 지나가게 고치니 그제서야 물었습니다:

```
read "세 번째 두 번째 첫 번째", want "첫 번째 두 번째 세 번째"
```

## 설치

```bash
gzip -dc ptium-1.12.14.tar.gz | docker load
```

## 검사가 또 이미지를 탓할 뻔했습니다

이 릴리즈를 빌드하다 도커가 포트를 열어주지 않아 검사가 멈췄습니다(호스트의 포트 전달기가
500 을 돌려줍니다). 두 가지를 고쳤습니다:

- **재시도가 같은 포트를 다시 달라고 했습니다.** 실패한 것이 바로 그 포트인데 말입니다.
  이제 다른 포트를 골라 다시 시작하고, 검사는 실제로 열린 포트로 서버와 이야기합니다
- **포트를 누가 잡고 있으면 도커는 성공합니다.** 그리고 검사는 서버에 닿지 못한 채
  `"the image never became ready"` — 이미지 탓을 했습니다. 이제 컨테이너가 살아 있고
  로그가 "listening" 이라고 말하면, 이것은 호스트 이야기이므로 그렇게 말합니다:
  `"the container is up and listening; this host will not forward its port"` (exit 2)

두 번째는 포트를 실제로 붙잡아 두고 확인했습니다 — 예전에는 실패 1건으로 릴리즈를
멈추면서 이미지를 탓했고, 지금은 exit 2 로 "검사를 돌리지 못했다" 고 말합니다.
