# Ptium v1.12.10

이 제품의 약속은 **재는 것과 그리는 것이 같다** 는 것입니다. 폭 표를 실제 글꼴의
advance 와 문자별로 대조해 봤더니, 어긋나는 쪽이 하필 넘치는 쪽이었습니다.

## 무엇이 어긋나 있었나

ASCII 밖의 기호는 **전부 하나의 기본값 0.6** 으로 떨어지고 있었습니다:

```
—  U+2014   0.89 로 그려짐 → 0.60 으로 측정   (-33%)
…  ※  →  ★  ≥          같음
%  U+0025   0.89 로 그려짐 → 0.52 로 측정   (-42%)
```

`—` 는 이 제품이 쓰는 **거의 모든 절 제목**에 들어갑니다("배치 지연 — 기대 효과").
`%` 는 **모든 비중·KPI 블록**에 들어갑니다. 좁게 재면 글자 크기를 줄이지 않고, 넘치는 줄을
결함으로도 잡지 못합니다 — 재는 쪽과 그리는 쪽이 갈라지는 그 자리입니다.

## 이제

- `—` `…` `※` 0.95, 화살표·도형·수학 기호 0.9, `%` 0.85, 인용부호 0.45, `·` 0.5
- ASCII 기본값 0.52 → 0.55 (Arial 0.556, 내장 글꼴 0.56~0.59 — 4% 좁게 재고 있었습니다)
- 이모지와 기본 다국어 평면 밖 한자는 전각(1.0)

기호 한 줄의 오차가 **-28% 에서 +3%** 로 바뀝니다. 넘치는 쪽이 아니라 **여유 있는 쪽**으로
어긋나게 두는 것은 의도한 것입니다: 조금 크게 재면 글자가 조금 작아질 뿐이지만, 좁게 재면
넘칩니다.

## 확인

- 폭 표가 PDF 가 실제로 그리는 글꼴과 맞는지 문자별·문장별로 검사하는 테스트를 넣고,
  고친 것을 되돌려 8건이 걸리는지 확인했습니다
- 실제 덱 35 개를 이 판정으로 다시 재 봤습니다: **결함 0, 권고 103 — 하나도 바뀌지 않았습니다.**
  이미 여유가 있던 덱들이라 판정이 흔들리지 않는다는 뜻이고, 교정이 안전하다는 뜻입니다
