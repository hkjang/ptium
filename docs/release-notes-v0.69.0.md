# Ptium v0.69.0

지난 판에서 모델이 직접 쓴 덱을 **슬라이드로 그려 눈으로 봤습니다.** 좋았습니다 — 지표는 KPI
카드로, 원인은 2단으로. 그런데 2단 슬라이드에서 이것이 보였습니다.

## 오른쪽 칸의 제목이 사라지고 있었습니다

모델은 2단 슬라이드를 이렇게 씁니다 — 사람도 그렇게 씁니다.

```
# 성장과 위축의 원인 분석
@twoContent
> 시장 환경 변화
- 디지털 전환 가속화로…
- 소비자가 가격 비교와…
> 내부 채널 갈등
- 대리점 가격 경쟁력 약화로…
- 직영과 대리점 간 가격 정책…
```

두 번째 `>` 를 **슬라이드의 리드에 이어 붙이고** 있었습니다. 그려 보면 이렇게 나옵니다.

```
시장 환경 변화 내부 채널 갈등          ← 두 제목이 한 줄로, 왼쪽 칸 위에
• 디지털 전환 가속화로…                • 대리점 가격 경쟁력 약화로…
• 소비자가 가격 비교와…                • 직영과 대리점 간 가격 정책…
```

오른쪽 칸은 **제목 없이** 남습니다. 무엇에 대한 목록인지 말해 주지 않는 칸입니다.

이제 **요점이 시작된 뒤에 오는 `>` 는 다음 칸의 제목**입니다. 각 칸이 자기 제목을 이고 자기
요점을 담습니다. 칸이 하나뿐인 레이아웃에서는 제목을 요점 사이에 그대로 남깁니다 — 잃지 않는
쪽을 택합니다.

## 그리고 왕복에서도 지켰습니다

이 언어는 **쓰고 · 컴파일하고 · 다시 쓰는** 것을 반복합니다. 두 번째 칸의 제목이 컴파일에서는
살아남고 다시 쓸 때 사라지면, 편집기에서 코드를 한 번 열었다 닫는 것만으로 지워집니다.
그렇게 되고 있었습니다.

이제 각 칸의 제목이 `>` 로 다시 나옵니다. 두 번 왕복해도 같은 글이 나오는지 테스트로
고정했습니다.

## 확인

- Go 전 패키지 통과. 2단 배치 · 칸 하나뿐인 경우 · 왕복 안정성을 각각 확인합니다.
- 모델이 쓴 그 슬라이드를 다시 그려 **눈으로** 확인했습니다.
- api 87 · edges 32 · package · flows · ui 0 실패.
