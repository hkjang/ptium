# Ptium v1.53.0

**캡처한 화면을 Ctrl+V로 슬라이드에 바로 붙여넣습니다.**

## 이미 있던 기능이 거의 닿지 않았습니다

붙여넣기 자체는 전부터 있었습니다. 다만 조건이 하나 붙어 있었습니다.

```js
if (!editorRoot.current?.contains(document.activeElement)) return
```

캔버스가 **이미 포커스를 쥐고 있을 때만** 받았다는 뜻입니다. 그런데 사람들이 실제로
하는 순서는 이렇습니다.

```
화면 캡처 → 브라우저로 돌아옴 → Ctrl+V
```

이 순서에서 포커스는 `<body>`에 있습니다. 덱을 열고 아무 데도 누르지 않은 상태가
바로 그것입니다. 그래서 붙여넣기는 **아무 일도 하지 않고, 왜 안 되는지도 말하지
않았습니다.** 캔버스를 한 번 클릭한 사람만 쓸 수 있는 기능이었습니다.

거기에 이 처리는 자유 배치 캔버스 안에만 있었으므로, **코드**와
**템플릿 미리보기**에서는 같은 키가 아예 죽어 있었습니다.

## 브라우저에서 직접 쟀습니다

실제로 돌아가는 서버에 크로미움을 붙여, 진짜 PNG를 실은 `paste` 이벤트를
보냈습니다. 고치기 전:

```
  실패  아무것도 클릭하지 않고 편집에서 붙여넣기       이미지 0 → 0
  실패  코드 편집기에 커서를 둔 채 붙여넣기            이미지 0 → 0
  실패  템플릿 미리보기에서 붙여넣기                   이미지 0 → 0
  통과  캔버스를 클릭한 뒤 붙여넣기                    이미지 0 → 1
```

다섯 중 셋이 죽어 있었습니다. 고친 뒤:

```
  통과  아무것도 클릭하지 않고 편집에서 붙여넣기       이미지 0 → 1
  통과  코드 편집기에 커서를 둔 채 붙여넣기            이미지 0 → 1
  통과  템플릿 미리보기에서 붙여넣기                   이미지 0 → 1
  통과  캔버스를 클릭한 뒤 붙여넣기                    이미지 0 → 1
  통과  글이 함께 담긴 붙여넣기는 텍스트 상자 몫       이미지 0 → 0
```

## 무엇이 바뀌었나

**포커스를 따지지 않습니다.** 붙여넣기는 이제 창 전체에서 받습니다. 덱을 열자마자,
아무것도 클릭하지 않고 눌러도 지금 슬라이드에 들어갑니다.

**어느 화면에서나 받습니다.** 코드나 템플릿 미리보기에서 붙여넣어도 슬라이드에
올라가고, 편집 화면으로 돌아가 어디에 놓였는지 보여 줍니다.

**글이 같이 담긴 것만 양보합니다.** 문서에서 문단을 복사하면 그림도 같이 실려
옵니다. 그것이 텍스트 상자에 떨어지면 그 사람은 글을 쓰는 중이므로 상자에
맡깁니다. 반대로 **그림만 담긴 붙여넣기는 코드 편집기 한가운데서도 슬라이드가
받습니다** — 텍스트 상자는 그림을 받아도 아무것도 넣지 못하고 삼키기만 하므로,
양보할 대상이 없습니다.

**items도 읽습니다.** 붙여넣은 그림을 `files`가 아니라 `items`로만 건네주는
브라우저에서는 전에도 지금도 조용히 아무 일도 일어나지 않았습니다. 이제 둘 다
읽습니다.

**대화 상자가 열려 있으면 받지 않습니다.** 그때 키보드는 그 상자의 것입니다.

## 규칙을 한곳에 두었습니다

판단은 `web/src/pages/editor/pasteimage.ts` 하나에 있습니다 — 그리는 일이 아니라
규칙이기 때문입니다. 캔버스는 그림이 담긴 붙여넣기를 알아보면 **비켜섭니다.**
두 곳이 같은 붙여넣기를 두고 다투면 등록 순서에 따라 결과가 달라지므로, 주인을
하나로 두었습니다.
