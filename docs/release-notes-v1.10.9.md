# Ptium v1.10.9

두 가지입니다. 하나는 어제 릴리즈에 제가 넣은 버그이고, 하나는 그걸 찾다가 잰 무게입니다.

## 공유 화면이 가끔 슬라이드를 안 그리던 것 (v1.10.8 회귀)

공유 화면은 덱 정보(몇 장인지)를 받고 나면 미리 받아 둘 범위를 다시 계산합니다. 그런데
그 시점에 **이미 받고 있던 그림이 버려지고**, 그 슬라이드는 "받았음"으로 표시된 채
남았습니다. 결과는 **영원히 도는 스피너** 입니다. 타이밍 문제라 열 때마다 재현되지는
않습니다 — 릴리즈 직전 브라우저 확인은 통과했고, 오늘 다시 돌리니 걸렸습니다.

날아온 그림은 이제 **무슨 일이 있었든 보관합니다.** 덱 안에 있는 슬라이드의 그림이고,
다음에 필요할 때 다시 받을 이유가 없습니다.

## 링크가 없으면 그림, 있으면 직접 그리기

v1.10.6·v1.10.8 에서 발표 화면과 공유 화면이 슬라이드를 **직접 그리게** 했습니다. 눌러야
하니까요. 그런데 직접 그리는 건 공짜가 아닙니다. 재 봤습니다:

**사진 한 장이 들어간 슬라이드의 그림 = 859 KB** (대부분 base64). 발표 화면은 앞뒤로 네
장을 미리 들고 있으니 **3 MB 넘는 문자열** 을 브라우저가 문서로 파싱하고 있게 됩니다.
그림(`<img>`)이면 브라우저가 한 번 디코드하고 끝날 일입니다.

그래서 규칙을 읽는 사람이 말할 법한 대로 바꿨습니다 — **슬라이드는 그림입니다. 링크가
들어 있기 전까지는.** 요청 수는 어느 쪽이든 슬라이드당 한 번으로 같습니다.

브라우저에서 확인했습니다: 링크 없는 장은 `<img>` 1개, 링크 있는 장은 직접 그린 슬라이드
1개에 링크 1개.

## 설치

```bash
gzip -dc ptium-1.10.9.tar.gz | docker load
```
