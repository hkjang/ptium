# Ptium v1.12.0

## 폐쇄망에서도 숫자를 **그립니다**

젠스파크 같은 도구와 나란히 놓고 부족한 부분을 찾다가, 재 보고 확인했습니다.

이 워크스페이스가 만든 덱 중 **차트가 든 것 461개는 전부 사람이 직접 쓴 것** 이고,
**생성된 것은 3개** 였습니다. 경로를 갈라 보니 원인이 분명했습니다 — 숫자만 있는 브리프를
주면:

| 경로 | 결과 |
| --- | --- |
| 모델 있음 | `line` · `share` · `columns` · `meter` |
| **모델 없음(폐쇄망)** | `steps` · `comparison` — **차트 0** |

이 제품이 실제로 배포되는 쪽이 받은 숫자를 시각화하지 못하고 있었습니다.

이제 브리프의 숫자를 읽어 **모양이 맞을 때만** 그립니다:

```
::share 구성비            ::columns 비교
- 직판 | 46%             - 2023년 | 820억
- 대리점 | 33%            - 2024년 | 910억
- 온라인 | 21%            - 2025년 | 1,040억
::                       ::
```

- **구성비**: 100%가 되는 3~5개의 퍼센트
- **비교**: 같은 단위의 3~6개 값 (연도든 지역이든 이름이 그대로 축에 남습니다)
- **목표 대비**: 합이 100이 아닌 퍼센트
- 모양이 아니면 **아무것도 그리지 않습니다.** 단위가 섞이면(억 옆에 %) 그리지 않고,
  한 덱에 최대 두 개까지입니다
- 모든 행은 **브리프가 말한 숫자 그대로** 입니다. 계산하거나 지어내지 않습니다

## 그러다 찾은 진짜 결함: 브리프의 숫자 절반을 못 보고 있었습니다

숫자 추출이 최대 8개를 가져오는데, **연도(2023년·2024년…)도 그 8개에 포함된 뒤 버려지고**
있었습니다. 그래서

```
"매출은 2023년 820억, 2024년 910억, 2025년 1,040억. 비중은 직판 46%, 대리점 33%, 온라인 21%. 신규 고객 240곳"
```

이 브리프에서 실제로 읽힌 숫자는 **4개**뿐이었습니다 — 33%, 21%, 240곳은 **아예 존재하지
않는 것처럼** 처리됐습니다. 차트만의 문제가 아닙니다. KPI 행도, "브리프에 없는 숫자" 검사도
잘린 목록으로 돌아가고 있었습니다. 이제 숫자를 센 뒤에 자릅니다.

## 숫자 옆의 말이 제목과 축에 그대로 붙던 것

브리프의 숫자에는 **앞뒤 낱말이 따라옵니다.** 그게 그대로 나가고 있었습니다:

```
전: # 채널 비중은 직판 46% — 기대 효과      - 보고. 서울 | 1,200건      - 달성률은 매출 | 96%
후: # 채널 비중은 직판                     - 서울 | 1,200건            - 매출 | 96%
```

제목은 숫자로 끝나지 않고, 막대는 **세는 대상의 이름** 을 답니다. 이미 차트로 그린 숫자를
KPI 가 다시 늘어놓지도 않습니다(최대 4개까지만 헤드라인입니다).

## 확인

같은 브리프로 폐쇄망 생성: `share` + `columns` + `steps` + `comparison`, **결함 0 · 권고 0**.
모델 경로도 그대로 동작합니다(결함 0). 스윕 178 checks — 숫자만 있는 브리프가 차트를 그리지
않으면, 또는 막대 이름에 숫자가 섞이면 실패합니다.
