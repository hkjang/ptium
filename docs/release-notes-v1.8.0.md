# Ptium v1.8.0

## 글씨가 작아서 읽기 힘들었습니다

워크스페이스의 글씨는 **7~10px** 로 짜여 있었습니다. 측정 결과 패널도, 오른쪽 속성 패널도,
관리자 표도 **9px** 였습니다. 그건 읽는 크기가 아니라 장식 크기입니다.

**328곳의 글자 크기를 올렸습니다.**

| 전 | 후 | 어디 |
|---|---|---|
| 7px | 10px | 보조 설명, 작은 라벨 |
| 8px | 11px | 슬라이드 번호, 표 안 코드 |
| **9px** | **12px** | 측정 결과, 속성 패널, 탭, 관리자 표 |
| 10px | 13px | 항목 제목, 버튼 |
| 11~13px | 13.5~15px | 본문과 입력창 |

**슬라이드 자체는 건드리지 않았습니다.** 슬라이드 미리보기 안의 작은 글자(4px·6px)는 슬라이드
그림이지 읽는 글이 아니고, 캔버스는 덱 자신의 타이포그래피를 그대로 그립니다.

## 글씨를 키우니 드러난 것들

큰 글씨로 보니 원래 있던 겹침이 눈에 들어왔습니다. **바꾸기 전 화면에도 있던 문제** 입니다.

- **편집기 헤더**: 오른쪽 버튼 9개가 가운데 점수 표시 위에 겹쳐 그려지고 있었습니다.
  화면이 좁으면 버튼들이 **아이콘만 남기고 이름을 접습니다** (전부 마우스를 올리면 이름이 나옵니다).
- **오른쪽 패널 탭**: "격자" 가 잘려 있었습니다. 패널을 250 → 280px 로 넓히고 탭 줄은 가로로
  넘길 수 있게 했습니다.
- **측정 결과 줄**: 설명이 수정 버튼 아래로 들어가고 있었습니다. 버튼 자리를 확보했습니다.
- **API 문서의 긴 경로**: 옆의 설명과 겹쳤습니다. 이제 줄바꿈됩니다.

## 다른 서비스에서 템플릿을 골라 만들기

이미 되던 것을 확인하고, 부족한 것을 채웠습니다. **API 키만으로 처음부터 끝까지** 걸어 봤습니다.

```
1) GET  /api/v1/templates?kind=builtin&search=slate
2) POST /api/v1/presentations/generate   {"templateId": "...", "prompt": "...", "slideCount": 8}
3) GET  /api/v1/presentations/{id}       → status: completed
4) GET  /api/v1/presentations/{id}/export?format=pptx
```

목록에는 **기본 제공 디자인 17개와 업로드한 템플릿** 이 함께 나오고, 각 항목이 이름 · 설명 ·
레이아웃 수 · 화면비 · 태그 · 어두운 테마 여부를 담고 있습니다.

**이번에 더한 것:**

- `?kind=builtin` · `?kind=uploaded` · `?search=이름` 으로 **목록을 좁힐 수 있습니다.**
  고르는 쪽은 전부 받아서 직접 거를 필요가 없습니다. 모르는 kind 값은 오류가 아니라 무시합니다
  (전체 목록이 나옵니다).
- OpenAPI 명세에 두 파라미터를 적었습니다.
- 앱 안 **API 문서에 "템플릿을 골라 만들기" 순서** 를 넣었습니다. 지금까지 이 문서는 템플릿을
  한 번도 언급하지 않았습니다.
- e2e 검사에 넣었습니다 — 두 kind 의 합이 전체와 같은지, 이름으로 찾은 것이 그것인지, **고른
  템플릿으로 실제 덱이 나오는지** 까지 (110 → **116개**).

태그로는 좁힐 수 없습니다. 태그는 저장된 값이 아니라 목록을 만들 때 디자인에서 읽어 내는
것이라 데이터베이스에 견줄 대상이 없습니다. 없는 기능을 있는 척하지 않았습니다.
