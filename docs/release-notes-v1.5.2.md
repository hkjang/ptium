# Ptium v1.5.2

pptx 로 **내보냈다가 다시 들여오면** 덱이 그대로여야 합니다. 파일 안에 덱 원본이 함께 실려
나가니까요(`ppt/ptiumSource.xml`). 이 검사는 지금까지 **한두 개 덱** 으로만 돌고 있었습니다.

저장된 덱 **1,032개** 를 전부 내보냈다가 들여왔습니다.

**8장짜리 덱이 7장으로 돌아왔습니다.**

```
내보내기 전                     들여온 뒤
─────────────────────          ─────────────────────
# E2E가 고친 제목                # E2E가 고친 제목
# 지표          ← KPI 카드      ✗ 없음
  - 처리량 | 1,200건
  - 오류율 | 0.2%
# 이행 순서                      # 이행 순서
...                             ...
```

## 파일이 옛날 덱을 싣고 나갔습니다

덱은 **두 벌의 기록** 을 갖습니다 — 슬라이드와, 원본 텍스트. **슬라이드가 정본입니다.** 캔버스에서
편집하면 슬라이드만 바뀌고 텍스트는 그대로입니다.

코드 보기는 이걸 알고 있었습니다. 저장된 텍스트가 지금 슬라이드를 설명하지 못하면 **슬라이드에서
다시 만들어** 보여 줍니다. 그런데 **내보내기는 몰랐습니다.** 저장된 텍스트를 그대로 파일에 실었고,
들여오기는 그 텍스트를 믿었습니다. 그래서 **그림에는 8장이 있는데 파일 속 원본에는 7장** 인
파일이 만들어졌고, 들여오면 한 장이 사라졌습니다.

캔버스에서 슬라이드를 더하거나, 도형을 얹거나, 제목만 고쳐도 이 상태가 됩니다.

## 규칙을 한 곳에 두었습니다

"이 텍스트가 지금 슬라이드를 설명하는가"를 판단하던 규칙이 화면 쪽에만 있었습니다. 이제
`deck.MatchesSlides` 하나로 **코드 보기와 내보내기가 같은 판단** 을 씁니다. 텍스트가 뒤처졌으면
내보낼 때 **지금 덱을 다시 써서** 싣습니다.

## 1,032개로 확인했습니다

| | 전 | 후 |
|---|---|---|
| 내보내기 → 들여오기에서 달라진 덱 | **5 / 40** | **1 / 1,032** |

남은 1개는 내용을 잃은 것이 아니라, **템플릿에 없는 레이아웃 이름** (`@layout two-content`)
을 적어 둔 덱이라 들여올 때 대체 레이아웃이 쓰인 경우입니다. 들여오기 알림에 그렇게 적혀
나옵니다.
