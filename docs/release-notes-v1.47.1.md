# Ptium v1.47.1

**설치 안내서를 그대로 따르면 방금 올린 버전이 아닌 다른 버전이 뜹니다.**

## 배포된 파일로 직접 설치해 봤습니다

로컬 이미지가 아니라 **릴리스에 올라간 자산**을 내려받아, 문서에 적힌 순서 그대로
해 봤습니다. 그리고 첫 단계에서 걸렸습니다.

```
ptium-1.47.0.env.example  →  PTIUM_VERSION=0.11.0
docker-compose.ptium-1.47.0.yml  →  image: ptium-${PTIUM_VERSION:-1.4.0}:latest
```

1.47.0 번들인데 안에 적힌 버전은 **0.11.0**과 **1.4.0** 입니다. 문서는
*"`ptium-<version>.env.example` 을 `.env` 로 복사하고 남은 자리표시자를 모두
바꾸세요"* 라고 안내하는데, `PTIUM_VERSION` 은 자리표시자처럼 보이지 않습니다 —
그대로 두면 방금 `docker load` 로 올린 이미지가 아니라 **없는 이미지**를 찾습니다.
예전 버전이 남아 있는 장비라면 조용히 **다른 버전이 뜹니다.**

두 파일은 저장소에서 그대로 복사되고 있었고, 그래서 마지막으로 누가 손댄 시점의
버전이 얼어붙어 있었습니다.

## 이제 번들이 자기 버전을 말합니다

빌드가 두 파일에 그때의 버전을 새겨 넣고, **새겨졌는지 확인한 뒤에야** 다음으로
넘어갑니다. 릴리스 절차에도 같은 확인이 들어갔습니다 — 스키마·매니페스트·설치
문서의 버전을 이미 확인하던 자리 옆에.

## 끝까지 걸어 봤습니다

고친 번들로, 빈 데이터베이스에 처음부터:

```
체크섬 확인 → docker load(두 태그) → compose up → 준비 완료
관리자 비밀번호 로그인 → 200
덱 생성 → 8장 · 100점 · "사내 PostgreSQL 전환 타당성 검토 결과"
내보내기 → pptx 45,176 bytes · pdf 2,112,108 bytes
```

가는 길에 401을 한 번 봤는데 제품이 옳았습니다 — `Origin` 없는 상태 변경 요청을
막은 것이고, 제 스크립트가 브라우저처럼 굴지 않았을 뿐입니다.
