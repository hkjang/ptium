# Ptium v0.38.0

내보낸 파일을 PowerPoint **접근성 검사**로 열어 봤습니다. 슬라이드마다 오류가 있었습니다.

## 화면을 못 보는 사람에게 이 덱은 빈 슬라이드였습니다

Ptium은 지표·도해·차트·표를 **직접 그립니다.** 그런데 그려진 개체에는 **대체 텍스트가 하나도
없었습니다.** 스크린 리더에게 그것은 아무것도 아니고, PowerPoint 접근성 검사는 개체마다
"대체 텍스트 없음"을 오류로 보고합니다. 그 검사를 통과하지 못하는 파일은 공공기관·금융권의
많은 곳에서 **그대로는 제출되지 않습니다** — Ptium이 겨냥하는 바로 그 템플릿을 쓰는 곳들입니다.

이제 그리는 모든 개체가 **자기가 무엇이고 무엇을 보여 주는지** 말합니다.

| 개체 | 대체 텍스트 |
| --- | --- |
| 세로막대 차트 | `세로막대 차트. 분기 매출. 1분기 1,180; 2분기 1,240; 3분기 1,390` |
| 표 | `표. 채널별 매출. 항목 / 1분기; 매출 / 120억 (2열 3행)` |
| 지표 카드 | `핵심 지표. 전환 대상 42개; 절감 18%` |
| 그림 | 캡션. 캡션이 없으면 **이미지 라이브러리에 지어 둔 이름** |

문장은 **덱의 언어**로 씁니다. 영어 덱은 `column chart. Quarterly revenue. …`, 일본어 덱은
`縦棒グラフ`. 그리고 그 문장은 **그림이 그려진 블록에서** 만들어지므로 숫자가 바뀌면 설명도
함께 바뀝니다 — 손으로 적어 둔 설명이 낡는 일이 없습니다.

세부 두 가지:

- **같은 말을 두 번 하지 않습니다.** 차트나 표는 그룹 밖으로 나가므로, 남은 그룹(제목·캡션)은
  전체 설명이 아니라 **자기가 담고 있는 글자**로 설명됩니다. 비워 두면 그것 자체가 오류입니다.
- **파일명은 설명이 아닙니다.** `IMG_2481.png`는 대체 텍스트로 쓰지 않고, 사람이 지어 둔
  이름(`매장 전경`)만 씁니다.

## 이제 점검에 들어갑니다

`scripts/e2e/package.py`가 내보낸 파일의 **모든 개체**를 세어, 대체 텍스트가 없는 것이 하나라도
있으면 실패합니다. 사람이 기억해야 하는 규칙이 아니라 회귀 테스트가 됐습니다.

점검 자체의 결함도 하나 고쳤습니다. 점검이 올리는 그림의 색을 **시계에서 세 자리**로 뽑고
있어서, 시간이 지나 같은 색이 나오면 두 번째 실행은 첫 번째 실행이 올린 그림을 **재사용**하고
그 그림의 옛 이름으로 작업했습니다. 이제 실행마다 다른 그림을 올립니다 — 같은 데이터베이스에
몇 번을 돌려도 서로 밟지 않는 것이 이 점검들의 약속입니다.

## 확인

- 회귀 테스트 2건: 차트·표·지표의 대체 텍스트 문장, 그리고 **덱의 언어를 따를 것**.
- 전수 점검: api 75 · edges 32 · deep 0 실패, package는 **대체 텍스트 없는 개체 0**.
