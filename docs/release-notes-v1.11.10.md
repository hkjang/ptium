# Ptium v1.11.10

## 롤백: 문서에 없던 것을 재서 적었습니다

업그레이드 안내에는 "먼저 백업하라"만 있고, **되돌리는 것**에 대한 말이 없었습니다. 업그레이드가
잘못됐을 때 운영자가 가장 먼저 하는 일은 백업 복원이 아니라 **이전 태그를 다시 배포하는 것**
입니다. 그게 되는지 아무도 확인한 적이 없었습니다.

**됩니다.** 1.11.9 가 쓴 데이터베이스에 1.10.0 · 1.9.0 · 0.1.0 을 각각 올려 보았고, 셋 다
정상 기동해서 새 버전이 만든 덱을 그대로 읽었습니다. 마이그레이션이 무엇도 **빼앗지 않기**
때문입니다(0.1.0 은 자기 목록인 29개만 세고 나머지는 무시합니다).

다만 **예전 이미지는 자기가 몰랐던 것을 이해하지 못합니다.** 이것도 재서 적었습니다:

| | 1.11.9 | 1.10.0 으로 롤백 |
| --- | --- | --- |
| `[보이는 말](주소)` | 링크로 그려짐 | **대괄호와 주소가 그대로 그려짐** |
| `!skip` | 발표에서 빠짐 | 무시되어 발표에 다시 들어옴 |
| PDF 내보내기 | 200 | 422 (그 버전에는 없음) |

문서에 **"되돌리기"** 절을 추가했습니다 — 되돌려도 잃는 것은 없고, 되돌린다고 고쳐지는 것도
없다는 것까지.

## 그리고 매 릴리즈가 되돌리기까지 해 봅니다

지난 릴리즈에서 넣은 업그레이드 검사에 **세 번째 단계** 를 붙였습니다: 예전 이미지로 DB 를
만들고 → 새 이미지로 올리고 → **다시 예전 이미지로 내려서** 덱이 그대로 열리는지 봅니다.

어느 날 누군가 컬럼을 지우는 마이그레이션을 쓰면, 롤백이 불가능해졌다는 사실은 아무도
모르게 지나갑니다. 이 검사가 그날 실패합니다.

## 설치

```bash
gzip -dc ptium-1.11.10.tar.gz | docker load
```
