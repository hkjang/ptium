# Ptium v0.22.0

덱마다 **그 덱 얘기가 아닌 슬라이드**가 있습니다. 회사 소개, 팀, 연락처, 면책조항. 매번 다시
만드는 일은 이 제품에서 가장 재미없는 일이고, 다른 덱에서 복사해 오면 **그 덱의 디자인이
따라옵니다**.

## 저장한 슬라이드

편집기 오른쪽 **슬라이드** 탭에서 지금 슬라이드를 라이브러리에 저장하고, 어느 덱에서나 꺼내
넣습니다.

**그림이 아니라 덱 소스(글)로 저장합니다.** 넣는 순간 **그 덱의 템플릿으로 다시 컴파일**되므로,
같은 회사 소개가 밝은 템플릿에서는 밝게, 어두운 템플릿에서는 어둡게, 2단 레이아웃에서는 2단으로
나옵니다. 남의 디자인을 스크린샷처럼 붙여 넣는 것은 아무도 원하지 않습니다.

- **미리보기도 지금 덱의 디자인**으로 그려서 보여 줍니다. 넣기 전에 어떻게 될지 보입니다.
- 넣고 나면 **보통 슬라이드**입니다. 라이브러리에서 지워도 이미 넣은 슬라이드는 그대로입니다.
- 같은 이름으로 다시 저장하면 갱신됩니다 — 회사 소개를 고쳤을 때 하는 일이 그것입니다.
- **즐겨찾기 · 태그 · 검색 · 정렬**(최근 사용 · 자주 사용 · 최근 저장 · 이름순)은 이미지
  라이브러리와 같습니다. 찾는 행위가 같으므로 찾는 방법도 같아야 합니다.

## 사라지던 문장을 되찾았습니다

부제 슬롯이 없는 레이아웃에서는 컴파일이 슬라이드의 **리드 문장을 컴포넌트 제목으로 접어**
넣습니다. 그런데 덱을 다시 글로 쓸 때는 캡션만 적고 있었습니다. 그래서 **코드 탭을 열어 그대로
적용하면 그 한 줄이 사라졌습니다.**

이제 접혀 들어간 리드는 다시 `>` 리드로 나오고, 컴파일하면 원래 있던 자리로 돌아갑니다.
왕복이 왕복이 됩니다. 회귀 테스트를 붙였습니다.

## API

- `GET /api/v1/snippets?q=&tag=&favorite=&sort=` · `GET /api/v1/snippets/tags`
- `POST /api/v1/snippets` — `source`를 직접 주거나, `presentationId` + `slide`로 그 슬라이드를
  서버가 글로 받아 적습니다
- `PATCH` · `DELETE` · `PUT /api/v1/snippets/{id}/favorite`
- `POST /api/v1/snippets/{id}/render` — 대상 덱의 템플릿으로 컴파일해 넣을 슬라이드를 돌려줍니다
- `GET /api/v1/snippets/{id}/preview.svg?presentationId=` — 그 덱의 디자인으로 그린 미리보기
