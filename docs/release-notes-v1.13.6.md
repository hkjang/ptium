# Ptium v1.13.6

v1.13.5 를 넣고 나서 그것이 무엇을 만들어 내는지 따라갔더니, **제가 감사 기록을 오염시키고
있었습니다.** 그리고 그 김에 중단 버튼의 거짓말도 하나 나왔습니다.

## 화면이 보는 것은 행위가 아닙니다

개요는 열릴 때마다 제공자에게 물었고, 그때마다 **감사 기록에 한 줄씩** 남겼습니다. 대시보드를
다섯 번 새로 고치면 다섯 줄입니다 — 두 릴리즈 전에 만든 그 기록이, 자기를 보러 온 화면으로
채워집니다. 남의 모델 호스트를 새로고침마다 두드리는 것도 마찬가지로 예의가 아닙니다.

이제 **묻는 것과 보는 것을 가릅니다.**

- `POST` 는 사람이 **누른** 것입니다 — 항상 새로 묻고, 기록에 남습니다
- `GET` 은 화면이 **읽는** 것입니다 — 30초 안의 결과가 있으면 그것을 주고, 기록에 남기지
  않습니다

다섯 번 열어도 기록은 0줄, 한 번 누르면 1줄입니다.

## 끝난 덱을 "멈췄습니다" 라고 말하고 있었습니다

큐를 읽고 중단을 누르는 사이에 덱이 완성될 수 있습니다. 그때 중단은 **아무것도 하지 않고
200 을 돌려줬습니다** — 운영자는 멈췄다고 믿고, 덱은 멀쩡히 완성되어 있습니다.

이제 멈춤은 **무언가를 멈췄는지 답합니다.** 늦었으면 409 와 함께 그 덱의 현재 상태를 말합니다:
"그 덱은 멈추기 전에 끝났습니다."

## 확인

- 저장소 테스트가 두 번째 중단은 아무것도 멈추지 않는다고 답하는지 확인합니다
- 스윕이 **두 결말을 모두** 지킵니다: 멈췄으면 이유가 작성자에게 가는지, 늦었으면 그렇게
  말하고 **덱을 건드리지 않았는지**. 오프라인 작성기는 1초 안에 끝나므로 이 경주는 실제로
  일어납니다 — 세 번 연속 339 checks 0 failures
- 그리고 화면이 읽는 것은 기록에 남지 않고, 사람이 누른 것은 남는지
