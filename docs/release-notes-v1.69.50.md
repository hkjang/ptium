# Ptium 1.69.50

## 사일런트 SSO — 들어오는 건 됐고, 나가는 게 두 번 고장 나 있었습니다

코드는 이미 있었고 단위 테스트도 통과하고 있었습니다. **있는 것과 동작하는 것은 다르니**
실제 Keycloak 26.4 를 띄우고 실제 브라우저로 끝까지 돌려 봤습니다.

| 시나리오 | 결과 |
|---|---|
| Keycloak 세션 없음 → `prompt=none` 으로 **한 번** 다녀와 `/login?sso=none` 에 멈춤 | ✓ |
| 새로고침해도 다시 튕기지 않음 | ✓ |
| Keycloak 에 다른 곳에서 로그인 → 새 탭이 로그인 화면·비밀번호 없이 들어옴, 깊은 링크 유지 | ✓ |
| **로그아웃 → Keycloak 의 "Do you want to log out?" 영어 확인 화면에서 멈춤** | ✗ |
| **로그아웃 뒤 새 탭을 열면 곧바로 다시 로그인됨** | ✗ |

### 1. Keycloak 확인 화면에서 멈추던 로그아웃

Keycloak 은 `id_token_hint` 없이 로그아웃을 요청받으면 자기 확인 화면을 띄웁니다. 그 탭을 닫으면
Ptium 에서만 나가고 Keycloak 세션은 살아 있습니다 — 그리고 다음 탭에서 사일런트 SSO 가 그 세션으로
다시 들여보냅니다.

ID 토큰을 브라우저 저장소에 두면 페이지의 어떤 스크립트든 읽을 수 있습니다. 그래서 **로그인할 때 한
번 서버로 보내고, 스크립트가 읽을 수 없는 쿠키**(`ptium_id_hint`, HttpOnly, 경로 `/api/v1/auth` 한정)에
둡니다. 서버는 이 클라이언트의 · 이 사람의 토큰인지(`iss` · `aud` · `sub`) 확인한 것만 받습니다.
로그아웃할 때 서버가 그 토큰을 `id_token_hint` 로 붙인 종료 주소를 돌려주고, 쿠키는 세션과 함께
지웁니다.

→ 이제 확인 화면 없이 곧바로 Ptium 로그인 화면으로 돌아오고, Keycloak 계정 콘솔을 열면 로그인을
다시 요구합니다. **Keycloak 세션까지 끝났습니다.**

### 2. 새 탭에서 되살아나던 로그인

"로그아웃했음" 표시를 `sessionStorage` — 그 탭의 저장소 — 에 두고 있었습니다. 새 탭은 그 표시를 모르니
사일런트 SSO 를 시도했습니다. 측정 당시 새 탭의 저장소는 `{}` 로 비어 있었고, 경로는
`/dashboard → Keycloak auth → /auth/callback → /dashboard` 였습니다.

두 표시는 수명이 다릅니다. **"이미 시도함"은 탭 하나의 일**(새 탭은 다시 시도해야 함)이라
`sessionStorage` 에 두고, **"로그아웃함"은 이 브라우저에 대한 사람의 결정**이라 `localStorage` 로
옮겼습니다. 다시 로그인하면 지워지고, 그러면 새 탭의 자동 로그인도 되돌아옵니다(측정으로 확인).

## 로그인 화면 — appstore 처럼

조직 계정 부분을 appstore 로그인 화면과 같은 구조로 바꿨습니다.

- **자동 로그인이 안 된 이유를 한 줄로** — "회사 계정 세션이 없어 자동으로 로그인하지 않았습니다. 아래
  버튼으로 로그인하세요." (`?sso=none` 일 때만, 제공자가 없는 배포에서는 보이지 않음)
- **전폭 기본 버튼 "회사 계정으로 SSO 로그인"**
- **로컬 계정은 접어 둠** — OIDC 가 켜져 있으면 비밀번호 로그인은 "관리자 계정으로 로그인" 토글 뒤로
  들어가고, 펼치면 "SSO를 사용할 수 없을 때를 위한 복구용 관리자 계정입니다" 안내가 붙습니다.
  개발자 로그인만 있으면 "개발자 로그인" 으로 접힙니다.
- OIDC 가 없는 배포는 접지 않고 바로 보여 주며 "최초 설치 관리자 계정입니다…" 안내를 붙입니다.
- 로컬 폼에 오류가 있으면 토글이 닫혀 있어도 펼칩니다 — 오류가 접힌 곳에 숨지 않습니다.
- 토글은 `aria-expanded` · `aria-controls` 를 달고 키보드(Enter)로 열립니다. 390px 폭에서 가로 넘침 없음.

세 배포 형태(OIDC+관리자 비밀번호, OIDC+개발자, 관리자 비밀번호만)를 각각 띄워 확인했고, OIDC+관리자
배포에서는 접힌 폼으로 실제 관리자 로그인까지 했습니다.

## 이를 뽑아 본 결과

- `scripts/e2e/sso.py` 를 새로 넣었습니다. Keycloak 에 레알름·클라이언트·사용자를 만들고 자동 로그인을
  켠 뒤 **13가지**를 브라우저로 확인하고, 켠 설정을 원래대로 돌려놓습니다. 13/13.
- 힌트를 빼고(서버 재시작까지 한 뒤) 돌리면 로그아웃이 Keycloak 확인 화면에서 멈춥니다.
- "로그아웃함"을 다시 `sessionStorage` 에 두면 단위 테스트 10개 중 3개가 실패합니다(새로 넣은 "새
  탭에서도 로그아웃 유지" 포함).
- 로그인 화면 테스트 4개 — 아무것도 접지 않게 되돌리면 2개 실패.
- 서버 테스트 3개(토큰 받는 조건, 종료 주소의 힌트, 본문 없는 로그아웃은 예전처럼 204) — 힌트를 빼면
  실패.
- 전체 훑기: api 937 · edges 33 · race 72,588 요청 · tenancy 101 · flows · deep · ui — 0 실패.

### 측정하다 틀린 것 두 가지

- 처음 되돌림 실행 두 번은 무효였습니다. 서버가 시작할 때의 `index.html` 을 들고 있어서, 실행 중에
  `web/dist` 를 다시 빌드하면 옛 청크를 가리켜 화면이 비고 JS 가 아예 돌지 않았습니다. 빌드 뒤 서버를
  재시작하고 다시 쟀습니다. (운영에서는 이미지 안의 dist 가 바뀌지 않으므로 제품 문제는 아닙니다.)
- "Keycloak 세션도 끝남" 검사가 처음엔 `#username` 입력란이 있는지로 판단했는데, Keycloak 계정 콘솔의
  프로필 폼에도 같은 id 가 있어서 세션이 살아 있어도 통과했습니다. 로그인 페이지로 보내졌는지를 주소로
  보도록 고쳤습니다.

## 운영자가 할 일

Keycloak 클라이언트에 **Valid post logout redirect URIs**(`https://<Ptium 주소>/*`)가 없으면 로그아웃 뒤
Ptium 으로 돌아오지 않습니다. 관리자 가이드 3.2 절에 적었습니다.

`/api/v1/auth/logout` 은 본문 없이 부르면 예전처럼 `204` 입니다. `postLogoutRedirectUri` 를 보내면
`200` 과 `endSessionUrl` 을 돌려줍니다.
