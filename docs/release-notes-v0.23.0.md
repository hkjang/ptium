# Ptium v0.23.0

제품 전체를 **처음부터 끝까지 돌려 보는 점검**을 만들고, 거기서 나온 것들을 고쳤습니다.
점검은 [`scripts/e2e`](https://github.com/hkjang/ptium/tree/main/scripts/e2e)에 들어 있어
다음 점검은 명령 한 줄입니다.

- `api.py` — REST 전 구간의 정상 경로 (75가지 확인)
- `edges.py` — 한계값: 50장/51장, 16MiB, 개체 200/201개, 이모지·스크립트 태그·RTL, **동시 편집**
- `ui.py` — 모든 화면이 그려지고 콘솔에 아무것도 남기지 않는지
- `flows.py` — 생성 → 영역 편집 → 코드 적용 → 슬라이드 저장/삽입 → 내보내기 → 좁은 화면
- `deep.py` — MCP, **덱을 내보내 템플릿으로 되올리기**, 발표자 창 동기화, 키보드 접근성

## 점검이 찾아낸 것

### 좁은 화면 스타일시트가 **한 번도 적용된 적이 없었습니다**

반응형 규칙을 담은 파일을 기본 규칙보다 **먼저** 불러오고 있었습니다. 같은 우선순위라면
나중 규칙이 이기므로, 모바일 규칙은 전부 졌습니다. 420px 폭에서 모든 페이지가 96~181px씩
가로로 밀려 있었습니다. 진입 파일을 **불러오기만 남기고 순서를 바로잡았습니다** — 기본이
먼저, 화면들이 다음, **좁은 화면이 마지막**. 이제 휴대폰에서 제대로 접힙니다.

### Esc가 방금 쓴 문장을 말없이 버렸습니다

영역 편집을 Esc로 끝내면 입력한 내용이 **저장되지 않고 사라졌습니다.** 이제 Esc는 편집을
끝내고 **내용을 지킵니다.** 되돌리기는 Ctrl+Z가 하는 일입니다.

### 서버 잘못이 아닌 것을 500으로 답했습니다

- 빈 파일 업로드 → **422**, 이유와 함께 (인시던트도 남기지 않습니다)
- 16MiB를 넘는 업로드 → "multipart로 보내세요"가 아니라 **413 + 크기 한도**
- 저장할 슬라이드도 소스도 없이 온 요청 → **422**
- 본문에 UUID가 아닌 id → **404** (경로는 검사하고 있었지만 본문은 아니었습니다)

### F5가 브라우저를 새로고침했습니다

글을 입력하는 중에 F5를 누르면 발표가 아니라 **페이지 새로고침**이었습니다. 덱 편집기에서
F5는 발표입니다. 문장을 쓰다 페이지를 잃는 쪽이 훨씬 나쁩니다.

### 덱 제목이 주제를 잃어버렸습니다

"결제 시스템 이중화 계획을 실무진에게 설명하는 자료" →
**"이중화 계획을 실무진에게 하는 자료"**. 앞의 "결제 시스템"이 잘려 나가고, 동사를 지운
자리에 "하는"만 남았습니다. 제목과 소제목은 이제 **앞머리 명사구를 지키고 청중에서
자릅니다** → **"결제 시스템 이중화 계획"**. 슬라이드 본문에 쓰이는 주제도 같습니다.

### 브리프에 적은 장수를 무시했습니다

"6장짜리 자료"라고 써도 10장이 나왔습니다. 이제 브리프의 장수를 그대로 쓰고(슬라이더를
직접 움직이면 그때부터는 그쪽이 우선), 첫 화면에서 **"6장으로 만듭니다"**라고 미리 알려 줍니다.

### PDF

가이드가 제공하지 않는 PDF 내보내기를 약속하고 있었습니다. 사실대로 적고, **대신 무엇을
하면 되는지**를 적었습니다 — 받은 PPTX를 PowerPoint·LibreOffice에서 PDF로 저장하는 편이
글꼴 때문에 더 정확합니다.

## 점검이 확인해 준 것

- 오프라인 생성(AI 제공자 없이) 6장 · 결함 0
- 덱을 내보내 **그 파일을 템플릿으로 되올려** 다시 생성 → 레이아웃 10개 인식, 결함 0
- 동시 편집 두 건 → 하나는 200, 하나는 409
- 이모지·`<script>`·RTL·제로폭 문자를 넣은 덱 → 미리보기와 PPTX 모두 이스케이프, 이모지 보존
- 50장 저장, 51장 거부(잘라내지 않음), 개체 200개 저장, 201개 거부
- MCP `initialize`/`tools/list`/`tools/call` 정상, 발표자 창이 발표 화면을 따라옵니다
- 대시보드·템플릿·이미지·가이드의 모든 버튼과 링크에 접근 가능한 이름이 있습니다
