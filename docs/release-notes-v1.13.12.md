# Ptium v1.13.12

## 단으로 그린 슬라이드를 단대로 읽습니다

실제 덱 13개를 가져와 원문을 한 줄씩 읽어 보다가 나온 것입니다. 로드맵 슬라이드가 이렇게
들어와 있었습니다.

```
- 1단계: 검증
- 3단계: 전체 전환
- **1개월**
- **3~6개월**
- 테스트 환경 구축 쿼리 호환성 검증
- 전체 마이그레이션 서비스 오픈 및 안정화
- 2단계: 시범 운영
- **2개월**
- 파일럿 시스템 운영 성능 튜닝 및 최적화
```

세 단계가 서로 뒤섞였습니다. 가져오기가 하는 일이 바로 **읽는 순서를 지키는 것**인데
말입니다. 원인은 두 가지가 겹친 것입니다 — 슬라이드를 위에서 아래로(행 단위로) 읽고
있었고, 이 디자인은 가운데 단계를 아래로 내려 지그재그로 그렸습니다. 그래서 1, 3, 2.

이제 **단으로 그린 슬라이드는 단대로** 읽습니다. 왼쪽 단을 위에서 아래로 다 읽고, 다음
단으로 넘어갑니다. 위 슬라이드는 이렇게 들어옵니다.

```
- 1단계: 검증
- **1개월**
- 테스트 환경 구축 쿼리 호환성 검증
- 2단계: 시범 운영
- **2개월**
- 파일럿 시스템 운영 성능 튜닝 및 최적화
- 3단계: 전체 전환
- **3~6개월**
- 전체 마이그레이션 서비스 오픈 및 안정화
```

### 언제 "단"으로 보는가

아무 슬라이드나 단으로 읽으면 더 나빠집니다. 조건을 좁게 잡았습니다.

- **글이 있는 도형만** 보고 단을 찾습니다 — 디자인이 깔아 놓은 사진·도형·선은 단을 가로질러
  놓이기 일쑤여서, 그것까지 세면 모든 단이 하나로 붙어 버립니다
- 슬라이드 폭의 55%를 넘는 도형(제목·구분선·각주)은 단을 찾을 때 빼고, 위에 있으면 먼저,
  아래에 있으면 나중에 읽습니다
- **모든 단이 두 개 이상 쌓여 있어야** 단입니다. 제목 하나, 목록 둘, 각주 하나가 어쩌다
  세 덩이로 갈라진 것은 그냥 보통 슬라이드입니다

실제 덱 13개로 확인했습니다: **바뀐 것은 로드맵 슬라이드 두 장뿐**이고, 두 장 모두 줄은
그대로인 채 순서만 바로잡혔습니다. 나머지 11개는 한 글자도 달라지지 않았습니다.

## 검사

- 지그재그 3단 슬라이드를 만들어 가져오면 1·2·3 순서로 읽혀야 합니다
- 제목 + 목록 둘 + 각주짜리 보통 슬라이드는 **여전히 위에서 아래로** 읽혀야 합니다
- 스윕에도 같은 검사를 넣었습니다. 1.13.11 바이너리에서는 `1단계 · 3단계 · 1개월` 로
  실패합니다 (366 checks)
