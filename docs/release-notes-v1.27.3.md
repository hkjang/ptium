# Ptium v1.27.3

1.27.2에서 **업그레이드 훑기에 넣은 검사 자체가 틀렸습니다.** 그 판을 만들 때 훑기가
실패했고, 실패한 이유는 이미지가 아니라 검사였습니다.

## 무슨 일이었나

새 검사는 "예전 릴리스가 쓴 데이터베이스에 적용될 수 없는 설정값을 넣어 두고,
업그레이드 후 되돌아왔는지" 봅니다. 그런데 값을 `UPDATE`로 넣었습니다.

**아주 오래된 릴리스에는 그 설정 키가 아직 없습니다.** 행이 없으니 `UPDATE`는 아무것도
하지 않고, 새 이미지가 그 키를 처음 심어 기본값(8000)이 됩니다. 검사는 "관리자가 고른
16000이 사라졌다"고 말했습니다 — **넣은 적이 없는 값이 사라졌다고 한 것입니다.**

```
✗ the upgrade changed a setting the administrator chose: ai.max_output_tokens is 8000
```

이제 그 릴리스가 아는 키든 모르는 키든 **넣고 시작합니다**(`insert … on conflict do update`).
가장 오래된 이미지(0.1.0)에서 1.27.2로 올려 확인했습니다 — **0 failures.**
즉 **1.27.2 이미지 자체는 문제가 없었습니다.**

## 릴리스 절차도 고쳤습니다

빌드 스크립트는 훑기가 실패하면 `exit 1` 합니다. 그런데 제가 그 출력을 `| tail`로
넘겨 보고 있었고, **파이프라인의 종료 상태는 마지막 명령의 것**이라 실패가 가려졌습니다.
그래서 1.27.2는 훑기가 실패한 채로 태그와 릴리스까지 갔습니다. 앞으로는 로그로 받고
**종료 상태를 먼저 본 뒤** 출력을 읽습니다.

## 검사

- 업그레이드 훑기 0.1.0 → 1.27.3, 1.26.2 → 1.27.3 모두 0 failures.
- 되돌리기가 없던 판으로 올리면 여전히 네 가지를 잡습니다.

## 설치

```bash
gzip -dc ptium-1.27.3.tar.gz | docker load
```
