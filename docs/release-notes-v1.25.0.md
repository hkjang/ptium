# Ptium v1.25.0

지난 두 판(1.24.1 · 1.24.2)은 **아무도 고르지 않은 보라색이 남의 템플릿을 칠하는 것**을 막았습니다.
이번에는 그 색을 **화면이 어떻게 보여 주고 있었는지**를 봤습니다.

## 개인화 화면은 아무도 고르지 않은 색을 저장하고 있었습니다

개인화 화면의 **브랜드 강조 색상** 칸은 비어 있는 법이 없습니다. 내가 고른 색이 없으면
**조직 기본값**을 대신 보여 주고, 조직 기본값은 브랜딩 화면을 한 번도 열지 않은 배포에서는
**제품이 갖고 온 색(#7C3AED)** 입니다.

즉 **이름만 바꾸고 저장을 눌러도** 그 보라색이 "내가 고른 색"으로 저장되었습니다.
그리고 그 색은 1.24.2부터 **그림이 무시합니다.** 화면의 설명은 이렇게 적혀 있었습니다 —

```
브랜드 강조 색상
생성된 슬라이드의 강조선과 PPTX에 사용됩니다.   ← 그 값이면 쓰이지 않습니다
```

약속해 놓고 하지 않는 자리였습니다.

## 두 가지를 고쳤습니다

**하나 — 고르지 않은 색은 저장하지 않습니다.** 색을 직접 만지지 않고 저장하면 색은 기록되지
않습니다. 화면이 채워 준 값은 선택이 아닙니다.

**둘 — 설명이 사실을 말합니다.** 지금 칸에 있는 색이 제품이 갖고 온 색이면:

```
지금 값은 제품이 기본으로 갖고 온 색입니다. 이 값이면 템플릿이 가진 강조색을 그대로
둡니다 — 다른 색을 고르면 핵심 지표·단계처럼 Ptium이 직접 그리는 구성요소에 그 색을 씁니다.
```

직접 고른 색이면:

```
핵심 지표·단계처럼 Ptium이 직접 그리는 구성요소에 사용됩니다. 템플릿이 가진 강조색은
그대로 둡니다.
```

측정한 그대로입니다. 5장짜리 덱에서 고른 색이 실제로 그려진 곳은 **구성요소가 있는 장**이고,
나머지 장은 템플릿의 강조색을 그대로 씁니다.

**관리자 설정의 대표 색상**에도 같은 설명을 붙였습니다 — 워크스페이스 화면에 쓰이고,
색을 고르지 않은 사용자의 새 덱에도 쓰이며, 기본값 그대로면 업로드한 템플릿을 건드리지
않습니다.

## 화면이 어느 색을 "아무도 고르지 않은 색"으로 볼지

서버가 `GET /api/v1/settings`에 **`branding.seeded_brand_color`** 를 함께 답합니다.
화면이 그 값을 그림과 같은 기준으로 판단합니다. 두 벌로 갈라져 어긋나지 않도록,
웹이 갖고 있는 예비 상수가 서버의 값과 다르면 테스트가 실패합니다.

## 검사

화면 훑기에 두 가지를 넣었습니다 — 저장이 아무도 고르지 않은 색을 쓰면 실패하고,
칸이 그 색을 보여 주는데 설명이 사실을 말하지 않으면 실패합니다. 되돌려서 둘 다 실제로
잡는지 확인했습니다.
