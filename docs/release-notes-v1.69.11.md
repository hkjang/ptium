# Ptium 1.69.11

## 거절당했을 때 영어로 답하던 열다섯 곳

서버가 요청을 거절할 때 쓰는 문장은 영어입니다. API와 로그가 할 말이기 때문입니다.
화면은 그것을 다시 한국어로 씁니다. 규칙이 없는 문장은 서버가 쓴 그대로 나옵니다.

열다섯 개가 그대로 나오고 있었습니다. 대부분 사람이 실제로 마주치는 자리입니다.

- `이미지는 8MiB 이하여야 합니다` / `템플릿은 40MiB 를 넘을 수 없습니다` /
  `올리는 파일은 40MiB 를 넘을 수 없습니다` — 크기는 배포마다 다르므로 문장 안에서
  받습니다
- `먼저 슬라이드를 만들거나 추가한 뒤에 덱에 지시할 수 있습니다`
- `먼저 슬라이드를 만들거나 추가한 뒤에 점검할 수 있습니다`
- `모든 슬라이드가 건너뛰기로 표시되어 있어 PDF 에 넣을 쪽이 없습니다`
- `그 변경은 기록에 없습니다`
- `pptx 와 pdf 로만 내보낼 수 있습니다`
- 그 밖에 덱 소스 크기, 지시문 길이, 관리 화면 필터 값 등

OIDC 토큰 엔드포인트가 돌려주는 거절 세 개는 영어 그대로 둡니다. 화면에서 읽는
사람이 없고, 인증 클라이언트가 받는 응답입니다.

## 숫자 0 뒤의 조사를 틀리게 골랐습니다

1.69.8(화면)과 1.69.10(서버)에서 넣은 규칙에 숫자 0을 "받침 없음"으로 적었습니다.
**영은 ㅇ 받침으로 끝납니다.** 그리고 0으로 끝나는 긴 수는 십 · 백 · 천 · 만 · 억
으로 읽히는데, 모두 받침이 있습니다.

- 전: `2020를`, `v10는`
- 후: `2020을`, `v10은`

`server/internal/generation/repair.go` 안에 같은 일을 하는 규칙이 따로 하나 더
있었고, 그쪽은 0을 맞게 보고 있었습니다. 대신 로마자를 모두 받침 있는 것으로
보았습니다. 둘을 `internal/korean` 하나로 합쳤습니다.

## 지키는 장치

`web/src/api/codecover.test.ts` 가 서버 소스에서 `writeError` 문장을 모아,
한국어로 옮겨지지 않는 것이 있으면 실패합니다.

이 검사는 처음에 **아무것도 검사하지 않고 있었습니다.** `errorText(code, message)`
는 문장에 규칙이 없으면 코드로 물러섭니다. 검사가 `validation_error` 를 넘기고
있었으니, 어떤 문장을 주어도 한국어가 돌아왔습니다. 번역 한 줄을 지워 놓고 돌려
보았더니 그대로 통과했고, 그래서 알았습니다. 이제 어떤 표에도 없는 코드를 넘겨
문장만으로 판정합니다. 바꾸고 나니 열다섯 개가 드러났습니다.
