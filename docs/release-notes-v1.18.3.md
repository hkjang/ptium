# Ptium v1.18.3

가져온 덱을 **제품 자신의 품질 측정에 걸어 봤습니다.** PDF 세 개를 넣고 점수를 읽었더니
95 · 97 · 97 이었고, 지적된 항목 대부분은 원본 문서가 실제로 같은 말을 두 번 한 것이었습니다
(제목과 그 아래 불릿이 같은 말인 슬라이드 — 문서 탓이지 가져오기 탓이 아닙니다).

하나는 우리 탓이었습니다.

## 표지가 자기 제목을 두 번 말했습니다

> **효과적인 팀 협업 도구 소개**
> 효과적인 팀 협업 도구 소개 (1).pdf

표지 아래 줄은 "이 덱이 어느 파일에서 왔는지"입니다. 그런데 **문서는 대개 자기 내용을 이름으로
씁니다.** 그러면 제목과 그 아래 줄이 같은 말이 되고, **아무도 손대지 않은 덱을 열자마자 품질
패널이 "같은 말을 두 번 했습니다"라고 지적합니다.**

제품이 스스로 만든 것을 스스로 결함이라고 부르는 상태였습니다.

파일 이름이 제목과 같은 말이면(`(1)` 같은 중복 다운로드 표시까지 감안해서) **그 줄을 넣지
않습니다.** 파일 이름을 잃는 것도 아닙니다 — **모든 슬라이드에 이미 출처로 붙어 있습니다.**
이름이 다르면 예전처럼 그대로 넣습니다.

`.pdf` 만이 아니라 `.docx` · `.xlsx` · `.csv` · `.md` 전부 같은 자리를 씁니다.

- 효과적인 팀 협업 도구 소개: **95 → 96점**, 표지의 지적 사라짐
- 남은 지적들은 원본 문서 자신의 반복 — 고치지 않았습니다. 그건 사실이니까요.

## 검사

- 파일 이름이 제목과 같은 경우 3가지(`소개.pdf` · `소개 (1).pdf` · `소개 (12).pdf`)와
  **다른 경우 1가지**를 함께 고정했습니다. 되돌리면 실패합니다.
- REST 훑기에도 넣었습니다(476개 점검): **자기 이름을 딴 파일을 가져온 직후 표지에 반복
  지적이 있는지** 제품의 측정으로 직접 확인합니다.

gzip -dc ptium-1.18.3.tar.gz | docker load
