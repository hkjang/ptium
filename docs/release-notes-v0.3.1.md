# Ptium v0.3.1

로그인이 자주 풀리고 401이 반복되던 문제를 고쳤습니다. 원인은 두 가지였고 둘 다
브라우저가 세션을 어디에 들고 있는지에서 비롯됐습니다.

## 세션을 HttpOnly 쿠키로 보관

기존에는 세션 토큰을 `sessionStorage`에 두었습니다. `sessionStorage`는 탭 단위여서
탭을 닫거나 새 탭에서 열면 자격증명이 사라지고, 워크스페이스는 곧바로 401을 받아
로그인 화면으로 돌아갔습니다.

이제 로그인하면 서버가 `ptium_session` 쿠키를 내려 줍니다.

- `HttpOnly`, `Path=/`, `SameSite=Lax`, 그리고 요청이 TLS(또는 `X-Forwarded-Proto:
  https`)로 도달한 경우 `Secure`.
- 탭을 닫아도, 새 탭을 열어도 로그인이 유지됩니다. 스크립트는 값을 읽을 수 없습니다.
- 쿠키는 same-site 요청에서만 인정합니다. `SameSite=Lax`가 이미 크로스 사이트 쓰기에
  쿠키를 실어 보내지 않지만, 그래도 도달한 경우 `Sec-Fetch-Site`로 거부하고, fetch
  메타데이터가 없는 클라이언트는 쓰기 요청에 대해 `Origin`이 요청 호스트와 같아야
  합니다. 다른 오리진의 브라우저 클라이언트는 배포에 CORS로 등록된 오리진에서만
  쿠키를 쓸 수 있고, 와일드카드 등록은 인정되지 않습니다.
- `Authorization` 헤더가 항상 쿠키보다 우선합니다. 스크립트 클라이언트가 그 브라우저의
  마지막 로그인 사용자로 응답받는 일이 없습니다.
- `POST /api/v1/auth/logout`이 쿠키를 만료시킵니다. HttpOnly 쿠키는 브라우저가 스스로
  지울 수 없기 때문에 필요한 엔드포인트입니다.

## 활동 중인 세션은 자동 연장

세션 수명(`SESSION_LIFETIME`, 기본 12시간)이 지나면 작업 중이라도 갑자기 401이
떨어졌습니다. 이제 절반을 지난 세션은 다음 요청에서 다시 발급되어 쿠키로 내려갑니다.
작업을 계속하는 동안에는 로그아웃되지 않고, 아무 요청이 없는 세션은 예정대로 만료됩니다.

비밀번호 변경 시에는 갱신분이 아니라 변경 핸들러가 발급한 쿠키만 남도록 정리하므로,
변경 직후에도 그 브라우저는 로그인 상태를 유지합니다.

## OIDC 로그인도 Ptium 세션으로

공급자의 액세스 토큰은 보통 5~15분이면 만료되고, 리프레시 토큰은 의도적으로 브라우저에
내려가지 않습니다. 그래서 SSO로 로그인해도 몇 분 뒤 401이 반복됐습니다.

`POST /api/v1/auth/session`을 추가했습니다. 이미 인증된 신원을 갱신 가능한 Ptium
세션 쿠키로 교환하며, 워크스페이스는 OIDC 콜백 직후 한 번 호출하고 공급자 토큰을
보관하지 않습니다. API 키로는 호출할 수 없습니다(서버 간 자격증명은 브라우저 세션이
되지 않습니다).

`/api/v1/me`의 `authMethod`는 세션으로 인증한 경우 `session`을 반환합니다. 쿠키는
어느 문으로 들어왔는지 기록하지 않기 때문입니다.

## 오프라인 자산

`ptium-0.3.1.tar.gz`는 `ptium:0.3.1`과 `ptium-0.3.1:latest`를 담은 `docker load`
가능한 아카이브입니다. 데이터베이스는 포함하지 않으며 배포 환경이 `DATABASE_URL`로
제공합니다. 업그레이드는 이미지 태그만 바꾸면 되고, 기존 세션 쿠키는 없으므로 사용자는
한 번 다시 로그인합니다.
