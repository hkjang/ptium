# Ptium v1.28.2

큐 화면을 고쳤더니(1.28.1), **관리자 개요 화면**이 같은 말을 하고 있었습니다.

## 개요는 "작성 중"을 "기다리는 중"으로 세고 있었습니다

`oldestQueuedSeconds`는 **대기 중(queued)과 작성 중(generating)을 함께** 세고 있었습니다.
그래서 30분째 잘 쓰이고 있는 덱 하나가 —

```
가장 오래 기다린 덱 30분 — 작업자를 확인하세요        [멈춤 의심]
```

작업자는 멀쩡히 일하고 있습니다. 운영자는 확인하러 갔다가 **멀쩡한 생성을 중단**할 수도
있습니다.

## 기다림과 침묵을 따로 셉니다

```
oldestQueuedSeconds         아무도 아직 가져가지 않은 덱이 기다린 시간
quietestGenerationSeconds   작성 중인 덱 중 가장 오래 아무 말 없는 시간   ← 새로 답합니다
```

화면은 **침묵을 먼저** 말합니다. 큐가 잘 돌아도 조용한 덱 하나는 손봐야 하니까요.

```
작성 중인 덱이 7분째 응답이 없습니다 — 작업자를 확인하세요   [멈춤 의심]
가장 오래 기다린 덱 20분 — 작업자를 확인하세요               [멈춤 의심]
작성 중                                                        [정상]   ← 30분째 쓰는 중
```

판단 기준은 **큐 화면과 같은 규칙**을 씁니다(`queuehealth.ts`). 두 화면이 서로 다른 말을
할 수 없습니다.

## 검사

- 개요 답변: 30분째 쓰면서 10초 전에 말한 덱은 **기다림으로 세지 않고**, 7분 침묵은
  그대로 답합니다. 예전처럼 둘을 합쳐 세도록 되돌리면 그 자리에서 실패합니다
  (`a deck being written counts as 1800s of waiting`).
- REST 훑기가 두 숫자를 모두 답하는지 봅니다.
- 화면 규칙 9가지를 단위 테스트로 고정했습니다.

전체 Go 테스트(DB 포함) · REST 574개 · 화면 훑기 0 failures.
