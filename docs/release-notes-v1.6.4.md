# Ptium v1.6.4

지난 판의 생성 두 번에 이 알림이 붙어 있었습니다.

> 구성을 먼저 설계하는 단계를 건너뛰고 바로 썼습니다. **AI 서비스가 읽을 수 없는 답을 보냈습니다.**

덱을 쓰기 전에 **구성을 먼저 설계하는 단계** 가 있는데, 그게 실패하고 조용히 넘어간 것입니다.
무엇을 보냈길래 못 읽었는지 실제 모델에 직접 물어봤습니다.

## 답이 잘려 있었습니다

모델의 답을 그대로 받아 보니 **5,429자짜리 온전한 JSON** 이 오기도 하고, 어떤 회차는
**출력 한도에서 잘려서** 왔습니다. 그런데 코드는 이렇게 되어 있었습니다.

```go
if 내용이 비어 있고 && finish_reason == "length" {
    return 오류   // ← 아무것도 못 썼을 때만 실패로 봄
}
return 내용      // ← 5,000자 쓰다 잘린 것은 "정상 답변" 으로 통과
```

**한도에서 멈춘 답을 다 쓴 답으로 취급** 하고 있었습니다.

- 설계 단계에서는 → **반쪽 JSON** → 읽기 실패 → "읽을 수 없는 답" 이라며 설계 없이 진행
- 본문을 쓰는 단계에서는 → **뒷부분이 잘린 덱** → 마지막 슬라이드들이 사라진 채, 아무 말 없이

## 잘린 답은 답이 아닙니다

이제 `finish_reason == "length"` 면 **내용이 있든 없든 실패** 입니다. 그리고 이 실패에는
**고치는 방법이 하나뿐** 이라 그 숫자를 이름으로 말합니다.

> AI 서비스가 답을 끝내지 못하고 출력 한도에서 멈췄습니다. 관리자가 서비스 설정에서
> **최대 출력 토큰(ai.max_output_tokens)** 을 늘리면 해결됩니다.

한국어·영어·일본어·중국어 모두 넣었습니다.

## 실제 모델로 확인했습니다

바꾼 뒤 같은 브리프로 다시 태웠습니다.

| | 전 | 후 |
|---|---|---|
| 설계 단계 | 실패 → 건너뜀(알림) | **성공** |
| 알림 | 3건 | **없음** |
| 점수 | 96 | **98** |

조여도 멀쩡한 생성이 막히지 않는지가 확인하고 싶었던 것이고, 막히지 않았습니다.

## 덤으로 확인한 것

v1.6.3 에서 넣은 **수리 단계** 가 실제로 도는 것을 로그에서 봤습니다.

> 1 slide(s) were measured against the template and rewritten to fit
> slide 2 was left as written: steps draws 5 of its 6 entries

한 장은 다시 써서 나아졌고, 한 장은 **다시 쓴 결과가 더 낫지 않아 원래 것을 지켰습니다.**
모델에게 맡기되 재서 판단한다는 설계가 그대로 작동합니다. 남은 그 한 장은 작성자의 측정
패널에서 **버튼 한 번** 으로 나뉩니다(v1.6.2).
