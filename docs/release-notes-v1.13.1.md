# Ptium v1.13.1

v1.13.0 은 개요에 **"가장 오래 기다린 덱이 20분째"** 라고 말하게 했습니다. 그런데 그걸 읽은
운영자가 할 수 있는 일이 없었습니다 — 덱은 소유자의 것이고, 관리자는 남의 덱을 **볼 수조차**
없었습니다. 아는데 못 하는 것은 모르는 것보다 나쁩니다.

## 생성 큐

`관리자 → 생성 큐` 가 생겼습니다. 대기 중·작성 중인 덱 전부와 최근 24시간 실패가 한 화면에
있습니다 — 제목, **작성자 이메일**, 어느 단계인지, 몇 분째인지, 실패했다면 무슨 말이 남았는지.
15분을 넘긴 덱은 빨갛게 표시되고, 화면은 15초마다 스스로 새로 읽습니다.

할 수 있는 일은 두 가지입니다.

- **다시 큐에** — 실패했거나 죽은 작업자가 남긴 덱을 도로 밀어 넣습니다. 지금까지 작성자는
  처음부터 다시 요청하는 수밖에 없었습니다
- **중단** — 가지 않는 덱을 세웁니다. **이유를 적으면 그 이유가 작성자에게 그대로 보입니다**

두 동작 모두 감사 기록에 남습니다(`generation.requeue`, `generation.cancel`) — v1.13.0 에서
연 그 기록입니다.

## 중단한 이유가 지워지고 있었습니다

처음 만들었을 때, 중단하고 나면 작성자에게는 이렇게 보였습니다:

```
생성에 실패했습니다. 다시 시도해 주세요. 계속되면 관리자에게…
```

관리자가 적은 "예산 승인 전까지 중단합니다" 가 아니라요. 한창 쓰던 작업자가 조금 뒤에
끝나면서 **자기 실패 문구로 덮어썼기** 때문입니다.

이제 **이미 끝난 덱은 다시 실패시킬 수 없습니다** — 실패 처리는 아직 대기 중이거나 작성 중인
덱에만 적용됩니다. 작업자가 늦게 끝나도 운영자가 한 말이 그대로 남습니다.

## 확인

- 저장소 테스트: 큐에 남의 덱이 **작성자 이메일과 함께** 보이는지, 중단 이유가 작성자에게
  가는지, 그리고 **늦게 끝난 작업자가 그 이유를 덮지 않는지**. 둘을 되돌려 전부 무는지 확인
- 스윕: 덱 하나를 다른 계정으로 만들어 큐에 넣고 → 관리자가 보고 → 이유와 함께 중단하고 →
  작성자가 그 이유를 읽는지, 4초 뒤에도 그대로인지 → 다시 큐에 넣고 → **관리자 역할 없는
  계정은 403** (305 checks)
- 화면 스윕이 새 페이지를 방문합니다
