# Ptium v0.20.0

올린 이미지는 데이터베이스 안에 있었고, 쓰는 법은 어디에도 적혀 있지 않았습니다.
두 가지를 고쳤습니다.

## 1. 이미지를 볼륨(PVC)에 둘 수 있습니다

발표에 넣는 사진은 Ptium이 저장하는 것 중 **유일하게 끝없이 커지는 것**입니다. 기본값은
그대로 데이터베이스입니다 — 백업할 대상이 하나뿐인 것은 폐쇄망 배포에서 그 자체로 가치가
있습니다. 이미지가 많은 배포는 이제 마운트한 볼륨을 쓸 수 있습니다.

```yaml
ASSET_STORAGE: "filesystem"      # 기본값은 "database"
ASSET_DIR: "/var/lib/ptium/assets"
```

- 쿠버네티스 매니페스트 아래쪽의 `ptium-assets` PersistentVolumeClaim과 볼륨·마운트
  주석을 해제하고 ConfigMap 한 줄을 바꾸면 됩니다. Compose 파일에는 볼륨이 이미 있습니다.
- **바꿔도 잃는 것이 없습니다.** 데이터베이스에 있던 이미지는 그대로 읽히고, **처음 읽힐 때
  볼륨으로 옮겨집니다.** 한 번에 마이그레이션할 필요 없이 쓰이는 만큼 비워집니다.
- 볼륨이 없거나, 읽기 전용이거나, 다른 사용자 소유이면 **파드가 뜨면서 그 이유를 말하고
  멈춥니다.** 첫 사용자가 로고를 올릴 때 알게 되는 것은 너무 늦습니다.
- 행은 있는데 파일이 없으면 500이 아니라 **410과 함께 무엇이 없어졌는지** 답합니다.
- 파일은 임시 파일에 쓰고 rename으로 바꿔 넣으므로, 반쯤 쓰인 이미지를 읽는 일이 없습니다.
  자산 id는 UUID로만 경로가 되며, UUID가 아닌 것은 경로가 되지 못합니다.

레플리카가 2개인 기본 매니페스트에서는 ReadWriteMany 볼륨이 필요합니다(ReadWriteOnce라면
레플리카 1개 또는 데이터베이스 저장). 매니페스트 주석과
[offline-deployment.md](offline-deployment.md)에 정리해 두었습니다.

## 2. 사용 가이드

제품 안 **사용 가이드**(`/guide`)와 [docs/user-guide.md](user-guide.md)에 브리프부터 발표까지
한 페이지로 적었습니다. 여러 갈래로 나눈 도움말 센터가 아니라 한 페이지인 이유는, 발표 중에
무언가를 찾는 사람은 한 페이지는 읽어도 트리는 뒤지지 않기 때문입니다.

- 모델이 일할 수 있는 브리프는 무엇이 다른지(좋은 예·아쉬운 예)
- **템플릿 영역**과 **얹은 개체**의 차이 — 편집기 전체가 이 구분 위에 서 있습니다
- 덱 소스 문법 요약, 이미지 넣는 네 가지 방법, 발표자 보기
- 측정 배지의 "결함"과 "다듬을 곳"이 각각 무슨 뜻인지
- 잘 안 될 때 확인할 것들

## 3. 단축키가 실제로 생겼습니다

캔버스에는 단축키가 있었지만 **덱에는 없었습니다**. 이제 편집기가 답합니다.

| | |
| --- | --- |
| <kbd>Ctrl</kbd>+<kbd>S</kbd> | 지금 저장 (평소에는 자동 저장) |
| <kbd>F5</kbd> | 발표 시작 |
| <kbd>Ctrl</kbd>+<kbd>Enter</kbd> | 슬라이드 추가 |
| <kbd>Alt</kbd>+<kbd>↑</kbd>/<kbd>↓</kbd> | 슬라이드 순서 이동 |
| <kbd>Alt</kbd>+<kbd>PageUp</kbd>/<kbd>PageDown</kbd> | 이전·다음 슬라이드 선택 |

<kbd>?</kbd>를 누르면 편집기에서도, 발표 화면에서도 단축키 표가 뜹니다. 표는 **하나의 목록**을
가이드와 함께 씁니다. 세 곳에 각자 적어 두면 반드시 서로 달라집니다.

## 4. 이미지를 붙여넣고 끌어다 놓습니다

캡처한 화면을 슬라이드에 넣는 일은 지금까지 "이미지 탭 열기 → 올리기 → 목록에서 찾기 →
배치" 네 단계였습니다.

- **<kbd>Ctrl</kbd>+<kbd>V</kbd>** — 캔버스에 바로 붙습니다. 올라가면서 배치까지 됩니다.
- **끌어다 놓기** — 놓은 자리에 들어갑니다. 놓기 전에 어디에 들어갈지 보여 줍니다.
- 붙여넣은 이미지도 이미지 목록에 남아 다른 덱에서 다시 씁니다.

Ctrl+V는 이제 키 이벤트가 아니라 **클립보드 이벤트**로 처리합니다. 키 이벤트에서 기본 동작을
막으면 클립보드에 무엇이 있었는지 영영 알 수 없고, 클립보드에 있는 것은 복사한 도형보다
캡처한 화면일 때가 훨씬 많습니다.

## 그 밖에

- **청중 칸에 `general`이 그대로 보이던 문제.** 관리자 기본값은 키로 저장되는데 폼은 그것을
  한국어 문장 자리에 넣고 있었습니다. 이제 이름으로 보여 주고, 자주 쓰는 청중은 눌러서
  고릅니다.
- 홈에 **사용 가이드** 카드를, 편집기 머리말에 **단축키**·**도움말**을 두었습니다.
