# Ptium v1.11.8

## 릴리즈된 이미지를 실제로 띄워 보고 나서 릴리즈합니다

빌드 스크립트가 이미지를 만들고 tar.gz 로 묶은 다음, **그 이미지를 빈 데이터베이스에 붙여
실제로 띄워 봅니다.** 통과하지 못하면 릴리즈가 거기서 멈춥니다.

```
── ptium:1.11.8 on an empty database ──
   templates seeded: 50
   generated: completed with 6 slide(s)
   measured: defects 0 advisories 0
   pptx 39,746 bytes  pdf 2,110,262 bytes  handout 2,112,195 bytes
   preview 1,087 bytes · workspace 769 bytes
```

부트스트랩 관리자로 로그인하고, 덱을 만들고, 생성하고, 재고, 세 가지 형식으로 내보내고,
슬라이드를 그려 보고, 워크스페이스 화면이 나오는지까지 봅니다. PDF 안에 **이미지가 싣고
있는 폰트** 가 들어 있는지도 확인합니다 — 호스트에 한글 폰트가 있어서 되는 것과 이미지가
갖고 있어서 되는 것은 다르니까요.

### 왜 이걸 이제 넣었나

지금까지 이 저장소의 모든 검사는 **작업 트리에서 빌드한 바이너리** 와 **며칠째 살아 있는
데이터베이스** 를 상대로 돌았습니다. 운영자가 첫날 하는 일은 그 어느 쪽도 아닙니다 —
tar.gz 를 풀고, 비어 있는 PostgreSQL 을 가리키고, 관리자로 처음 로그인합니다. 그 경로만
검사에서 빠져 있었습니다.

돌려 본 결과 **이미지는 멀쩡했습니다.** 고칠 것이 나온 게 아니라, 그동안 확인하지 않고
있었다는 사실이 나온 것입니다.

### 확인하면서 배운 것 두 가지 (제품이 옳았던 것)

- 컨테이너 밖에서 개발용 인증 헤더는 통하지 않습니다. **의도된 동작** 입니다 — 개발 인증은
  루프백에서만 받습니다
- 쿠키 세션으로 **쓰기** 를 하려면 요청이 어디서 왔는지 증명해야 합니다(`Origin` ·
  `Sec-Fetch-Site`). 브라우저는 항상 보내고, 스크립트는 안 보냅니다. **CSRF 방어가
  살아 있다는 뜻** 이라 스크립트 쪽을 고쳤습니다

## 설치

```bash
gzip -dc ptium-1.11.8.tar.gz | docker load
```
