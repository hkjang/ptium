# Ptium v1.11.6

## 모델이 쓴 덱의 절반에 "무엇을 말할지"가 없었습니다

실제 모델(122B, 자체 호스팅)로 덱을 뽑아 재 봤습니다.

```
신규 서비스 출시 계획 — 8장,  defects 0,  advisories 5  {notes: 5}
   1. 신규 서비스 출시 계획      노트없음
   2. 왜 지금이 새로운 구독 모델의 시기인가?   노트없음
   4. 핵심 목표: 300곳 확보와 12억 달성      노트없음
   5. 기존 모델 vs. 신규 구독 모델          노트없음
   ...
```

**그려지는 것은 하나도 틀리지 않았습니다**(defects 0). 슬라이드는 자리에 잘 맞고 글자도 안
넘칩니다. 그래서 이 결함은 **끝까지 살아남아 회의실까지 갑니다** — 덱이 다 된 것처럼 보이니까요.
모델에게 주는 지시에는 "표지 빼고 모든 장은 `!notes` 로 끝난다"고 적혀 있지만, 8장 중 5장에서
그냥 빠뜨렸습니다.

이제 생성이 **측정하고, 없으면 채웁니다.** 보수(repair) 패스가 "안 맞는 슬라이드"를 다시
쓰게 하는 것과 같은 방식으로, 말할 것이 없는 슬라이드에 대해 **노트만** 다시 받아옵니다.

- 슬라이드의 **내용은 건드리지 않습니다.** 이미 템플릿에 맞춰 측정·수정이 끝난 글이라,
  돌아온 초안이 본문까지 바꿔 왔으면 **노트만 떼어서** 씁니다
- 한 덱에 최대 4장까지, 남은 시간 안에서만
- 받아온 뒤 다시 재서 **더 나빠졌으면 버립니다**

같은 프롬프트, 같은 모델로 다시:

```
물류 자동화 도입 제안 — 10장,  advisories 6  {repeat: 5, source: 1}   ← notes 0
신규 서비스 출시 계획 —  8장,  advisories 3  {source: 2, repeat: 1}   ← notes 0
```

오프라인(모델 없는) 생성은 원래 8/8 장에 노트를 쓰고 있었고, 그대로입니다.

## 문 하나가 늘어도 규칙은 한 번만 적습니다

이번 주에 "같은 글이 문마다 다르게 그려지는" 결함을 네 번 고쳤습니다. 매번 새로 만든 문만
런 분할기를 안 거친 것이었습니다. 이제 **미리보기 · pptx · PDF · 유인물** 네 곳을 한 테스트가
한꺼번에 봅니다 — 덱이 말하는 말은 전부 그려지고, 그걸 쓰려고 타이핑한 것은 어디에도
그려지지 않아야 합니다. 유인물을 예전 방식으로 되돌리면 깨집니다.

## 설치

```bash
gzip -dc ptium-1.11.6.tar.gz | docker load
```
