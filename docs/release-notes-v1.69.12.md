# Ptium 1.69.12

## 유인물의 슬라이드 점프가 아무 데도 가지 않았습니다

덱 안에서 다른 장으로 가는 링크(`[4장](#4)`)는 PDF 로 내보낼 때도 살아 있어야
합니다. 건너뛴 장이 있으면 4번 슬라이드가 3쪽에 인쇄되므로, 링크는 슬라이드 번호가
아니라 인쇄된 쪽을 가리켜야 합니다. 그 계산은 맞게 하고 있었습니다.

쓰는 형식이 틀렸습니다.

```
/Dest [2 /Fit]        ← 쪽 번호를 숫자로 적음
/Dest [12 0 R /Fit]   ← 쪽 객체를 가리킴
```

PDF 규격에서 숫자만 적는 형태는 **다른 파일**의 쪽을 가리킬 때 쓰는 것입니다. 같은
문서 안의 링크는 쪽 객체를 직접 가리켜야 합니다. 제3자 도구(pypdf)로 읽어 보니 이
점프는 아무 쪽으로도 풀리지 않았습니다.

고친 뒤 같은 도구로 다시 읽으니, 1쪽의 점프가 3쪽 — `넷째 장 도착 지점입니다` —
으로 정확히 갑니다. 건너뛴 장을 셈에서 빼는 계산도 그대로 맞습니다.

같이 따라온 것 하나: 쪽 트리 객체의 번호를 미리 계산할 때 **쓰이지 않을 링크까지**
세고 있었습니다. 링크가 하나라도 버려지면 그 번호가 어긋납니다. 이제 실제로 쓰는
링크만 셉니다.

## 지키는 장치

`internal/export/pdf_test.go` 와 `scripts/e2e/api.py` 의 검사가 둘 다 옛 형식
(`/Dest [1 /Fit]`)을 정답으로 붙들고 있었습니다. 두 검사 모두 이제 **읽는 사람이
따라가는 길로** 확인합니다. 쪽 트리(`/Kids`)에서 쪽 순서를 읽고, 점프가 가리키는
객체가 그중 몇 번째 쪽인지 봅니다. 되돌려 돌리니 둘 다 실패합니다.

## 확인만 하고 고치지 않은 것

열아홉 개 화면에 실제로 그려진 글자를 모두 훑어 영어 문장을 찾았습니다. 걸린 것은
템플릿·디자인 이름(고유명사)과 관리자용 오류 기록뿐이었습니다. 오류 기록은 운영자가
읽는 내부 메시지라 영어가 맞습니다.
