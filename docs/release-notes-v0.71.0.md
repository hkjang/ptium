# Ptium v0.71.0

지난 두 판의 수정이 실제 모델 출력에 어떻게 작용하는지 보려고 모델로 덱을 만들었습니다.
**첫 시도는 실패했고**, 그 실패가 다음 결함을 보여 줬습니다.

## 첫 단계가 잘못됐다고 덱을 버리고 있었습니다

생성은 두 단계입니다 — 구성 설계, 그 다음 슬라이드 작성. 이번에는 모델이 첫 단계에 JSON 대신
이렇게 답했습니다.

> 물론이죠! 이렇게 구성해 보겠습니다…

Ptium은 이것을 **설정 오류로 분류**해 생성을 실패시켰습니다. 하지만 이건 설정 문제가 아니라
로컬 모델이 가끔 하는 일이고, **두 번째 단계는 멀쩡히 할 수 있었습니다.** 372초를 기다린
사람은 빈손으로 돌아갔습니다.

이제 **첫 단계에서 무엇이 잘못되든 덱을 가라앉히지 않습니다.** 계획은 보조이지 필수가
아닙니다. 그리고 이렇게 해도 아무것도 감춰지지 않습니다 — 정말로 잘못 설정된 제공자는 곧바로
두 번째 단계에서 같은 이유로 실패하고, 그 실패는 보고됩니다.

같은 브리프로 다시 돌리니 **8장이 402초에** 나왔고, 덱이 이렇게 말합니다.

> 구성을 먼저 설계하는 단계를 건너뛰고 바로 썼습니다. …

## 그리고 비교 슬라이드가 두 줄의 회색 글씨였습니다

나온 덱을 그려 보니 비교 슬라이드가 이랬습니다. 모델은 이렇게 씁니다.

```
@comparison
- 현행 유지 | 400억 원 손실 위험 | 단일 장애점 존재
- 이중화 구축 | 2.4억 원 추가 비용 | 99.95% 가용성 확보
```

Ptium은 이 줄들을 표로 읽었고, **표의 첫 줄은 머리글**입니다. 그래서 `현행 유지` 쪽이 열 제목이
되고 본문에는 `이중화 구축` 한 줄만 남았습니다 — 비교가 있어야 할 자리에 작은 회색 글씨 두 줄.

저자가 **비교라고 말한 슬라이드에서 각 줄은 비교 대상**입니다. 서로 대등하고, 하나가 다른 하나의
머리글일 수 없습니다. 이제 비교 컴포넌트로 그립니다 — 두 선택지가 나란히, 각 항목이 자기 열에.
`::table` 로 직접 쓴 표는 첫 줄이 그대로 머리글입니다.
