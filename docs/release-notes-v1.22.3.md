이번 세션에서 안 돌려 본 훑기 두 개를 돌렸습니다.

- **경합 검사** — race detector로 빌드한 서버에 60초 동안 전부 동시에:
  **34,695건 · 실패 0 · 경합 보고 0건**
- **첫 시간 검사** — 방금 만든 `ptium:1.22.2` 이미지를 **빈 데이터베이스**에 붙여
  운영자의 첫날 그대로: 템플릿 50개 심어짐 → 덱 생성 완료 → **결함 0** →
  pptx · pdf · 유인물 전부 정상

## 응답에 문서에 없는 항목이 있었습니다

살아 있는 응답을 스키마에 맞춰 봤더니 관리자 개요가 걸렸습니다.

```
data.oldestQueuedSeconds   ← 문서에 없음
data.failedLastDay         ← 문서에 없음
data.lastCompletedAt       ← 문서에 없음
```

그리고 이 응답의 봉투는 **닫혀 있습니다**(`additionalProperties: false`) — 스키마대로
검증하는 클라이언트는 **멀쩡한 응답을 거절**합니다.

하필 빠진 셋이 **운영자가 실제로 보는 숫자**입니다. 대기 12건은 그 자체로 아무 말도 하지
않습니다 — 방금 12건이 몰린 아침인지, 세 시간째 안 움직이는 죽은 작업자인지는
**가장 오래 기다린 것의 나이**가 가릅니다.

셋 다 적었습니다. 그리고 **개요가 답하는 항목이 스키마에 없으면 실패하는 검사**를 넣었습니다 —
Go 구조체의 태그를 하나씩 스키마에서 찾습니다. REST 훑기도 살아 있는 응답으로 같은 것을
확인합니다(523개 점검).

## 함께 고친 것

경합 훑기는 서버가 없는 곳을 가리키면 `'int' object has no attribute 'get'` 로 죽었습니다.
거절된 연결이 오류 문자열로 돌아오고 그걸 순회하니 바이트가 정수로 나온 것입니다 —
**진짜 소식은 "아무도 듣고 있지 않다"** 인데요. 이제 어느 호출이 답을 못 받았는지,
서버가 뭐라 했는지, 어느 주소로 물었는지를 말합니다.
