# Ptium v0.10.0

검사가 발표 자료로서의 완성도까지 봅니다. 그리고 "잘못 그려진 것"과 "덜 다듬어진 것"을
구분합니다.

## 결함과 다듬을 곳

슬라이드는 사람이 옆에 서서 말하는 물건입니다. 그 관점의 실패 두 가지를 추가했습니다.

| 종류 | | 뜻 |
| --- | --- | --- |
| `overflow` | 결함 | 읽을 수 없을 정도로 축소해야 하거나 담기지 않는 텍스트 |
| `outside` | 결함 | 영역·슬라이드 밖으로 나감 |
| `collision` | 결함 | 영역이 겹침, 템플릿 사진·글자 위의 텍스트 |
| `contrast` | 결함 | 합성 영역 대비 4.5:1 미만 |
| `orphan` | 다듬기 | 제목 마지막 줄에 한 음절만 남음 |
| `density` | 다듬기 | 한 장에 일곱 개 이상의 요점, 또는 영역이 마지막 줄까지 꽉 찬 상태 |
| `notes` | 다듬기 | 주장을 담은 슬라이드에 발표 노트가 없음 |

- 둘을 섞으면 양쪽을 모두 무시하게 됩니다. `GET …/inspect`가 `defects`와 `advisories`를
  따로 세고, `clean`은 결함만을 가리킵니다. 편집기의 **검사** 버튼도 "검사 통과",
  "다듬을 곳 N건", "결함 N건"을 구분해 알려 줍니다.
- `orphan`을 다듬기로 재분류했습니다. 슬라이드는 정상적으로 그려지고 다만 읽는 맛이
  아쉬운 것이므로, 결함으로 두면 측정값을 맞추려고 제목을 훼손하게 됩니다.
- 표지·간지는 노트가 없어도 지적하지 않습니다. 그 슬라이드는 혼자 방을 버팁니다.

기본 제공 30종 회귀 테스트는 **결함만** 봅니다. 노트가 있는지는 작성자의 일이고 그
테스트는 디자인에 관한 것이기 때문입니다.
