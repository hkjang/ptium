# Ptium v1.5.0

저장된 덱 **1,019개** 를 전부 측정해 봤습니다. 측정이 사람에게 내놓은 문장은 모두 **5,798개**
였고, 그중 **4,998개(86%)** 가 **똑같은 한 문장** 이었습니다.

> 발표 노트가 없습니다. 이 슬라이드에서 무엇을 말할지 적혀 있지 않습니다

8장짜리 덱을 열면 이 문장이 4줄, 50장짜리 덱을 열면 **48줄**. 그 사이에 이 덱에만 해당하는
지적 — 출처 없는 숫자, 넘치는 글자 — 이 **파묻혀 있었습니다.**

## 같은 말은 한 줄로

측정 결과 패널이 **같은 문장을 두 번 말하지 않습니다.** 같은 종류에 같은 문장이면 한 줄이고,
그 줄이 해당하는 슬라이드를 **번호 칩** 으로 답니다. 칩을 누르면 그 장으로 갑니다.

```
전                                      후
─────────────────────────────────      ─────────────────────────────────
3번 슬라이드  발표 노트 없음  …  [수정]    4개 슬라이드  발표 노트 없음  …  [4개 한번에 수정]
4번 슬라이드  발표 노트 없음  …  [수정]    3번 4번 5번 6번
5번 슬라이드  발표 노트 없음  …  [수정]    5번 슬라이드  숫자의 출처 없음  …  [AI로 고치기]
6번 슬라이드  발표 노트 없음  …  [수정]
5번 슬라이드  숫자의 출처 없음 …  [고치기]
```

1,019개 덱 전체로 보면 패널의 줄 수가 **5,798 → 1,387** 로 줄었습니다. 50장짜리 덱은
**48줄이 1줄** 이 됩니다.

## 한 줄이면, 한 번에 고칩니다

전에는 노트 없는 4장을 채우려면 **패널 열기 → 수정 → 패널이 닫힘 → 다시 열기** 를 네 번
반복해야 했습니다. 같은 일을 네 번 시키는 목록이었습니다.

이제 그 줄의 버튼 하나가 **네 장 모두** 를 처리합니다.

- **발표 노트 초안** 은 한 번에 다 넣고 패널도 닫지 않습니다
- **AI로 고치기** 는 그 줄이 가리키는 장들만 순서대로 다시 씁니다 (각각 따로 되돌릴 수 있습니다)
- **슬라이드 나누기** 는 여전히 한 장씩입니다 — 나누면 덱이 바뀌므로 다시 재야 합니다

## 측정 자체는 그대로입니다

점수는 **한 장씩** 계산합니다. 20장 중 12장에 노트가 없는 것과 3장 중 1장에 없는 것은 다른
일이고, 묶어서 세면 그 차이가 사라집니다. **묶은 것은 읽는 방식이지 재는 방식이 아닙니다.**
