# Ptium v0.66.0

이번 판은 **관리자 화면**을 감사했습니다 — 개요 · 오류 센터 · 사용자 · 서비스 설정. 아직 이
방법을 대 본 적이 없는 화면들입니다.

## 화면 자체는 건강했습니다

네 화면 모두 4xx 없이, 자바스크립트 오류 없이 열렸고 **숫자도 맞았습니다.** 개요가 말하는
"프레젠테이션 687 · 생성 완료 533"을 DB에서 직접 세어 대조했습니다 — 정확히 일치합니다.

그런데 오류 센터가 비어 있었습니다(열린 오류 0). 비어 있는 화면은 감사할 수 없으므로,
**진짜 장애를 하나 만들었습니다** — AI 제공자를 없는 주소로 돌려놓고 덱을 생성했습니다.
(설정은 확인 후 원래대로 되돌렸습니다.)

## 그리고 이것이 사용자 화면에 떠 있었습니다

```
AI request failed: Post "http://10.0.4.19:11300/v1/chat/completions":
dial tcp 10.0.4.19:11300: connect: connection refused
```

덱을 요청한 사람에게 **아무 도움이 안 되는 문장**이고, 계정만 있으면 누구나 **내부 서비스의
주소와 포트**를 읽을 수 있습니다.

이제 읽는 사람이 둘이면 문장도 둘입니다.

- **운영자**는 오류 센터에서 원인을 **그대로** 봅니다. 발생 횟수와 마지막 감지 시각까지.
- **저자**는 무엇이 잘못됐고, 다시 시도할 값어치가 있는지, 누구에게 말해야 하는지를
  **덱을 요청한 언어로** 봅니다.

> AI 서비스에 연결하지 못했습니다. 관리자에게 서비스 설정의 모델 연결을 확인해 달라고 요청하세요.

여덟 가지로 나눠 씁니다 — 연결 불가 · 인증 거부 · 과부하 · 시간 초과 · 제공자 오류 ·
읽을 수 없는 응답 · 템플릿 문제 · 설정되지 않음. 분류가 안 되면 일반 문장으로 물러섭니다.
한국어 · 영어 · 일본어 · 중국어.

HTTP 500 응답은 이미 이 규칙을 지키고 있었습니다(`The server could not complete the request`
만 나가고 원인은 로그와 오류 센터로). 생성 실패 경로만 빠져 있었습니다.

## 확인

- 실제로 장애를 만들어 **저자 화면**과 **오류 센터**를 눈으로 확인했습니다.
