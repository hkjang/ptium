# Ptium v1.50.1

**같은 문이 하나 더 열려 있었습니다 — 덱 가져오기.**

## 마지막 남은 문

1.48.1은 템플릿 읽기를, 1.50.0은 문서 만들기를 막았습니다. 가져오기는 템플릿과
**같은 크기 한도(최대 64 MB)** 를 쓰면서 아무 제한도 없었습니다.

```
60 MB 덱 6개를 동시에 가져오기  →  0/6 · OOMKilled
```

## 그리고 예산이 두 개로 나뉘어 있었습니다

1.48.1의 템플릿 관문(한 번에 하나)과 1.50.0의 문서 예산(3단위)은 **서로 모르는 채**
따로 세고 있었습니다. 템플릿 읽기 441 MiB와 PDF 세 장 450 MiB가 동시에 일어나면
합이 한도에 닿습니다.

이제 **예산 하나**입니다. 단위는 약 150 MiB — PDF 한 장을 그리는 값입니다.

| 하는 일 | 실측 최대 | 비용 |
| --- | --- | --- |
| PDF 그리기 | 약 150 MiB | 1 |
| 덱 가져오기 (60 MB) | 255 MiB | 2 |
| .pptx 만들기 | 362 MiB | 3 |
| 템플릿 읽기 (60 MB) | 441 MiB | 3 |

예산은 3이고, 넘치면 60초(업로드는 30초)를 기다린 뒤 이유를 듣습니다.

```
가져오기 12개 동시  →  12개 모두 성공 · 6.5초 · 최대 270 MiB
PDF     16개 동시  →  16개 모두 성공 · 25.9초
.pptx    8개 동시  →  8개 모두 성공 · 45.5초
```

## 문마다 자기 말로 답합니다

예산 하나를 네 가지 일이 나눠 쓰지만, 거절은 두드린 문의 말로 합니다 —
`templates_busy`·`import_busy`·`printing_busy`. 템플릿을 올린 사람에게 "문서를
만드는 중"이라고 답하는 것은 남의 이야기입니다.
