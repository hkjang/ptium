# Ptium v1.46.1

**설정을 설명하는 답을 장애로 기록하고 있었습니다.**

## 오류 센터를 다시 열어 봤습니다

1.46.0을 확인하면서 개발 배포의 오류 센터를 보니 이런 그룹이 다섯 개 있었습니다.

```
HTTP 503 on POST /api/v1/presentations/21bfa589-…/slides/1/revise   n=1
HTTP 503 on POST /api/v1/presentations/9a497bde-…/slides/1/revise   n=2
HTTP 503 on POST /api/v1/presentations/35d0cfba-…/slides/1/revise   n=3
HTTP 503 on POST /api/v1/presentations/3b2fa20f-…/slides/1/revise   n=3
HTTP 503 on POST /api/v1/presentations/69fd6627-…/slides/1/revise   n=1
```

전부 같은 일입니다 — **모델이 없는 배포에 다시 쓰기를 요청한 것.** 제품은 정확히
답했고("이 배포에는 AI 제공자가 설정되어 있지 않습니다") 관리자 화면도 같은 말을
합니다. 그런데 그 올바른 답이 **운영자가 봐야 할 장애 목록에 다섯 줄**로 쌓였습니다.

## 두 가지를 고쳤습니다

**하나. 의도한 거절은 기록하지 않습니다.** 배포가 자기 설정을 설명하는 답은 고장이
아닙니다. 진짜 5xx는 예전처럼 그대로 기록됩니다.

**둘. 같은 결함은 한 그룹입니다.** 지문을 만들 때 바뀌는 값을 지우는데, 그 규칙이
`21bfa589` 같은 8자리와 `1147` 같은 4자리 숫자만 지우고 UUID 가운데의 `43cc`·`97a2`
는 남겼습니다. 그래서 덱마다 다른 지문이 됐습니다. 이제 UUID를 통째로 지웁니다 —
서로 다른 결함은 여전히 서로 다른 그룹으로 남습니다.

## 확인

모델이 없는 배포에서 서로 다른 덱 세 개에 다시 쓰기를 요청했습니다.

```
revise → 503 · 503 · 503
오류 그룹: 16개 → 16개 (그대로)
```

세 번 모두 요청자는 무엇이 부족한지 들었고, 오류 센터는 조용했습니다.
