# Ptium v1.56.2

**"1장에는 글자가 없습니다"라고 했는데, 글자가 없는 건 4번 장이었습니다.**

## 가져오기에 어려운 것들을 넣어 봤습니다

파워포인트로 이런 파일을 만들어 넣었습니다 — 분산형 차트(제품에 그릴 형태가 없는
것), 한 칸에 문단이 둘인 표, 요점 40개짜리 장, 글자가 하나도 없이 사진만 있는 장.

**문자열 50개가 모두 남았습니다.** 그리고 제품은 자기가 한 일을 말했습니다.

```
· 그림 1개를 이미지 라이브러리에 저장했습니다
· 표 1개를 이 덱의 디자인으로 다시 그렸습니다
· 차트 1개는 가져오지 않았습니다. 숫자를 ::bars 나 ::line 으로 적으면 다시 그려집니다
· 1장에는 읽을 수 있는 글자가 없어 제목을 임시로 붙였습니다
```

마지막 줄이 틀렸습니다. **글자가 없는 장은 4번**이었습니다.

## 세는 말과 가리키는 말

`wordless`는 **개수**인데, `"%d장에는"`은 한국어에서 **몇 번째 장인지**를 가리키는
말입니다. 그래서

* 4번 장 하나가 비어 있으면 → "1장에는" (1번 장을 가리킴)
* 2·5·6번 장이 비어 있으면 → "3장에는" (3번 장을 가리킴)

읽는 사람은 1번 장을 열어 보고, 거기 글자가 멀쩡히 있는 것을 봅니다.

바로 옆 갈래는 제대로 적혀 있었습니다 — "슬라이드 **%d장 모두에** 글자가 없습니다"는
`슬라이드`와 `모두`가 붙어 있어 개수로만 읽힙니다. 한 갈래만 그 보호 없이 같은 틀을
쓰고 있었습니다.

## 개수 대신 자리를 말합니다

가져오기 반복문은 이미 몇 번째 장인지 알고 있었습니다. 세지 않고 그 자리를 모읍니다.

```
4번 장 하나가 글자 없음      → 4번 슬라이드에는 읽을 수 있는 글자가 없어…
2·5·6번 장이 글자 없음      → 2·5·6번 슬라이드에는 읽을 수 있는 글자가 없어…
아홉 장이 글자 없음         → 슬라이드 9장에는 읽을 수 있는 글자가 없어…
```

여섯 장까지는 자리를 하나씩 적고, 그보다 많으면 자리를 늘어놓는 것이 도움이 되지
않으므로 **자리로 읽힐 수 없는 형태**로 개수를 말합니다.

세는 것보다 낫습니다. 개수는 "몇 장이 그렇다"만 말하지만, 자리는 **가서 볼 곳**을
말합니다.

## 검사가 결함을 지키고 있었습니다

기존 검사에 이 줄이 있었습니다.

```go
if !strings.Contains(said, "1장") {
    t.Errorf("one wordless slide among three was reported as %q", said)
}
```

그 시험의 글자 없는 장은 **두 번째**입니다. 검사가 "1장"을 요구하고 있었으니, 잘못된
동작을 잠가 두고 있었던 셈입니다. 고쳤습니다.
