# Ptium v0.91.0

지난 판에서 KPI 숫자가 옆 카드를 덮는 것을 고쳤습니다. **그걸 잰 것은 아무것도 없었습니다.**
컴포넌트는 자기 영역 안에 들어가 있고, 그 안은 우리가 직접 그리는 그림입니다.

컴포넌트 **안쪽 높이** 는 오래전부터 재고 있었습니다 — 머리말이 자기 첫 줄을 덮는 것, 두 줄이
서로 포개지는 것. **가로 폭은 한 번도 재지 않았습니다.**

## 처음 쓴 검사는 절대 발동하지 않았습니다

`inkBounds` 에게 "글이 상자 밖으로 얼마나 나갔나" 를 물었는데, `inkBounds` 는 **상자를 잉크에
맞춰 좁히기만** 합니다. 그 질문에는 언제나 **0** 이라고 답합니다.

가장 긴 줄을 직접 재도록 고치자, **좁은 영역에서 자기 상자 밖으로 그리는 컴포넌트가 네 개 더**
나왔습니다.

| 컴포넌트 | 넘친 폭 |
|---|---|
| hero | **5.90cm** |
| shareBar | 4.47cm |
| timeline | 4.09cm |
| meter | 2.92cm |

## 숫자는 물러나고, 저자의 글은 알립니다

- **숫자** (hero, kpi): 자기 자리에 맞춰 크기를 줄입니다 — 이제 **같은 헬퍼 하나** 를 씁니다.
  바닥은 "이보다 작아지면 슬라이드가 말하려는 그 숫자가 아니게 되는" 크기입니다.
- **라벨** (meter, share, timeline): **저자의 글** 입니다. 그래서 줄이지 않고 **지적합니다** —
  수리 패스가 더 짧은 문장을 요청하고, 그게 저자만이 고칠 수 있는 글에 대한 옳은 답입니다.

**가운데 정렬 글은 예외입니다.** 눈금에 가운데를 맞춘 라벨은 원래 그 간격보다 넓게 그려지는
것이 맞고, 그게 무엇을 덮는지는 **겹침 검사** 의 몫입니다.

## 확인

저장된 덱 49개에서 새 측정은 **한 건도 울리지 않습니다.** 그리고 일부러 좁게 만든 경우에는
정확히 울립니다.

오프라인 설치 방법은 [docs/offline-deployment.md](offline-deployment.md) 를 보세요. 이미지에
