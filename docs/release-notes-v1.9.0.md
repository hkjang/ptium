# Ptium v1.9.0

## OIDC Client Secret을 관리자 화면에서 등록합니다

지금까지 Client Secret은 **환경변수로만** 넣을 수 있었습니다. 서버는 이미 저장된 값을 읽을 준비가
되어 있었는데(`auth.oidc.client_secret`), **입력할 화면이 없었습니다.**

이제 **서비스 설정 → OIDC · SSO** 에 Client Secret 칸이 있습니다.

- **AES-GCM으로 암호화** 되어 저장되고, 저장된 값은 **다시 노출되지 않습니다** — 설정 응답
  어디에도 원문이 나오지 않는 것을 검사로 확인합니다
- 비워 두면 **바뀌지 않습니다.** 지우려면 **공백 한 칸** 을 저장하세요 — 공백만 있는 값은
  빈 값으로 정리되어 "저장됨" 표시도 사라집니다
- **Client ID 없이 Secret만** 저장하려 하면 저장 시점에 막습니다. 예전 같으면 다음 재시작에서
  서버가 기동을 거부하며 알려 줬을 일입니다
- 같은 항목의 **환경변수가 있으면 환경변수가 계속 우선** 합니다. 배포 매니페스트로 고정해 둔
  곳은 그대로 동작합니다. 이 규칙은 이제 테스트로 고정되어 있습니다

공개 SPA 클라이언트는 Secret이 필요 없습니다. Keycloak에서 **Confidential** 로 둔 경우에만
채우면 되고, 그때는 인가 코드 교환을 브라우저 대신 서버가 수행합니다. OIDC 설정은 예전처럼
**서비스 재시작 후** 적용됩니다.

## 첫 로그인이 500을 내던 문제

동시 요청을 흘려보내며 찾았습니다. **처음 로그인하는 사람의 요청 몇 개가 500을 받고 있었습니다.**

워크스페이스를 열면 브라우저가 계정·덱·템플릿을 **동시에** 요청하고, 그 각각이 계정을 만듭니다.
계정을 만드는 문장은 충돌 판정을 `subject` 하나로만 하고 있어서, 경쟁에서 진 삽입이 **이메일
유일 색인** 에 부딪혔습니다. 그 색인은 판정 대상이 아니라서 Postgres가 그대로 오류를 냅니다.

재현했습니다 — 같은 사람의 첫 요청 16개를 동시에 보내면 **12번 중 6번** 실패했습니다.

진 쪽은 다시 보기만 하면 됩니다. 그때는 이긴 쪽의 행이 있으니 같은 문장이 갱신 경로를 탑니다.
정말 다른 신원이 같은 이메일을 쓰는 경우라면 500 대신 **409와 설명** 을 돌려줍니다.

**57,044건**을 동시에 흘려보내 확인했습니다 — 500 **0건**, 경합 **0건**.

## 동시 부하 검사를 도구로 남겼습니다

`scripts/e2e/race.py` — 읽는 사람, 쓰는 사람, 관리자, 이미지 열람, 생성을 **동시에** 돌리고
경합 검출기가 뭐라 했는지까지 읽습니다.

```bash
cd server && go build -race -o /tmp/ptium-race ./cmd/ptium
DATABASE_URL=... /tmp/ptium-race > /tmp/ptium-race.log 2>&1 &
python3 scripts/e2e/race.py --log /tmp/ptium-race.log --seconds 90
```

이 검사가 **자기가 만든 덱은 전부 지웁니다.** 처음 만들었을 때는 안 지워서 큐에 6,000개를
쌓았고, 그 다음 검사가 엉뚱하게 실패했습니다 — 도구가 뒷정리를 안 하면 다음 사람이 그 값을
치릅니다.
