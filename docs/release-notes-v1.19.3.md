# Ptium v1.19.3

지난 세 판이 브리프 읽는 자리를 계속 건드렸으므로, **평범한 브리프 25개**를 v1.18.7(이 작업을
시작하기 전)과 **한 줄씩 비교**했습니다.

바뀐 것은 **두 줄**이었습니다. 하나는 지난 판에서 고친 것이고, 나머지 하나는 **비교하다가
발견한 것**입니다.

## `비용` · `채용` · `내용` 이 들어가면 제목이 첫 단어에서 잘렸습니다

| 브리프의 주제 | 슬라이드 제목 |
| --- | --- |
| 신규 **채용** 계획 | **신규** |
| 클라우드 **비용** 최적화 방안 | **클라우드** |
| 고객 **사용** 패턴 분석 | **고객** |
| 데이터 **활용** 전략 | **데이터** |
| 약관 **내용** 변경 안내 | **약관** |
| AI **적용** 범위 확대 | **AI** |

`용` 은 "무엇을 위한 것인가"를 나타냅니다 — `보고용`, `고객용`. 그래서 제목에서 빼는 것이
맞습니다. 그런데 `용` 은 **아주 흔한 명사들의 마지막 글자**이기도 합니다 — 비용, 내용, 채용,
사용, 활용, 운용, 적용, 수용.

읽는 규칙이 그 둘을 구분하지 않아서, **그런 단어가 나오는 순간 제목이 거기서 끊겼습니다.**
표지 제목도, 각 장의 제목도, 전부. 한국어 업무 브리프에서 이 단어들은 드물지 않습니다.

이제 **`용` 앞의 말이 실제로 목적을 뜻할 때만** 그렇게 읽습니다(보고·발표·공유·제출·설명·
안내·소개·교육·홍보·내부·외부·고객·임원·경영진…). `임원 보고용 자료` → `임원` 은 그대로입니다.

## 어떻게 찾았는지

새 기능을 넣을 때마다 **평범한 입력이 그대로인지**를 봅니다. 25개 중 24개가 글자 하나까지
같았고, 그 비교가 아니었으면 이 결함은 계속 남았을 겁니다 — 실패하는 검사도, 오류 로그도
없었으니까요. **아무도 보지 않으면 아무 일도 일어나지 않습니다.**

## 검사

`용` 으로 끝나는 평범한 단어 6가지와, **규칙이 원래 노리던 2가지**를 함께 고정했습니다.
되돌리면 여섯 곳에서 실패합니다.
